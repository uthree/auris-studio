# 実験的な制作フェーズ

[English](composition-workflows.md)

Auris の起動前に `AURIS_COMPOSITION_WORKFLOWS=1` を設定すると、作曲・編曲・MIX の三つのフェーズに分けた制作を試せます。ツールカタログ全体は変わらないため、プロンプト実験でツールの異なる条件を暗黙に比較することはありません。既定では、聴取の証拠が変更を支持するまで既存のプロンプトを使います。候補ツールを案内するには `AURIS_COMPOSITION_CANDIDATES=1` も個別に設定し、両条件で同じ値にしてください。評価ランナーは両条件でこのフラグを有効にします。既定のアプリケーションカタログを試すときは `--no-candidate-tools` を使います。ローカルモデルのコンテキストは既定で64kで、`--context-tokens` で明示的に記録できます。実験で予算を増やしても、アプリケーションの既定値は変わりません。

両プロファイルは、ボーカル曲全体の形式に関する案内を共有します。新しい曲で指定がなければ第2ヴァースと後半のコーラス／エンディングを含め、短い形式を明示した場合や局所編集ではその範囲を保ちます。したがって既定プロファイルでもこの動作になります。セクションの網羅とスコアの読み戻しについては、[ライブボーカル制作](agent-workflows.ja.md#live-vocal-production)を参照してください。

`production_record` は `enter_phase` を受け取ります。引数は `phase`（`score`、`arrangement`、`mix`）と `reason` で、作曲フェーズでは `writing_order`（`harmony_first`、`melody_first`、`rhythm_first`）も指定できます。作曲フェーズでは形式、テンポ、コード、歌詞、主旋律とその歌声を決め、簡単なガイド伴奏つきのデモで終えます。編曲フェーズでは、固定された楽譜のまわりに音色、伴奏、ドラム、演奏表現、転換を作ります。MIX フェーズでは、バランスを取り、エフェクトをかけ、納品します。`set_roles` で主旋律のトラックとガイドのトラック（または理由つきの `no_foreground`）を登録します。編曲に入るには、この登録が必要です。部分的な修正は、直す対象を担当するフェーズに入って行います。

フェーズは会話メタデータであり、他の記録更新と同じ書き込み権限の対象です。コンテキスト圧縮や会話の再起動後も保持されます。モジュールモードでは、応答と後続のプロジェクト検査に、現在のフェーズの指示だけが含まれます。前のフェーズに戻っても後ろのフェーズの成果は残り、`phase.revisit` にやり直すフェーズが並びます。`phase.checks` は、現在とそれ以前のフェーズについて満たされていない構造上の条件を、`inspect_project` の `phase_facts` から読んで報告します。作曲では曲全体を覆うセクション、全セクションのコード、役割の登録、歌詞注記、最新の歌声テイク、編曲ではドラムの割り当てとガイドの置き換え、MIX では全体ミックスの測定です。これらは警告で、拒否ではありません。

共通契約は、正確なID、ティック単位、リビジョン検査、ソース保持、探索上限、測定値・批評家レポート・人間の聴取の区別を維持します。ワークフロー指示はモデル向けの案内であり、正規のセッションコマンドが検証と権限を個別に強制します。保留中の候補判断は、その有効期間内ならターンをまたいでラウンドとIDを保持します。ターンの終了だけを理由にラウンドをキャンセルしないでください。

制御された比較では、同じ固定実行ファイル、モデル、タスク群、ツールカタログを使い、`composition_quality.py run --prompt-profile legacy` と `--prompt-profile modular` を実行します。バックエンドのトークンカウンターとともに失敗と経過時間を記録してください。最後に報告された入力コンテキストは累積課金入力ではないため、利用量が欠落している場合にゼロコストとして扱ってはいけません。モジュールプロファイルを既定に採用する前に、盲検した人間の好みとリクエスト遵守を確認してください。
