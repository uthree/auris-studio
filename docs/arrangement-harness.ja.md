# エージェント向けの調整提案

[English](arrangement-harness.md)

アレンジメントハーネスは、楽器の機能、フレーズ条件、セクションオーケストレーション、パラメータの移動、SFXを共有セッション編集パスに接続します。`breath`編集で明示的にプレビューされた正確なリリース、ピックアップの省略、または保持された到着を除き、作成済みのノート、歌詞、和声、テンポ、拍子を保持します。提案は一時的な準備済みの文書であり、新しいプロジェクト形式ではありません。

<a id="enable-and-inspect"></a>
## 有効化して検査する

`AURIS_ARRANGEMENT_HARNESS=1`でデスクトップまたは保存済みプロジェクトのMCPを起動します。無効にすると、`arrangement`ツールとその標準モデルの指示がありません。保存済みMCPはそれを`manual`グループに配置します。Live Claude、Codex、rigは同じスキーマ、ワーカープロトコル、権限パスを使用します。保存済み呼び出しは`project`を追加します。

```json
{"operation":{"kind":"inspect","start_bar":17,"bars":16}}
```

安定したトラックおよびクリップIDを取得するには、まず`inspect_project`を読み込んでください。アレンジメント検査では、コンテンツの改訂、セクションの範囲、検証済みのコントローラーのサポート、ファミリーベースの推奨事項、正確なネイティブパラメータキー、制限付きフレーズの観察結果が返されます。サポートは`supported`、`unsupported`、または`unknown`です。General MIDIファミリーは慣習であり、サードパーティ製のパッチのアーティキュレーションの証拠ではありません。CC1は弓圧、ビブラート、またはパッチ固有のマッピングを意味する場合があります。BendとCCはチャンネル全体に適用され、重なるボイスに影響を与える可能性があります。

検査では、最大16トラックと、各トラックで交差する最大16クリップを扱います。トラックについては`next_offset`に従ってください。個別のクリップまたは追加のパラメータページについては`inspect_project`、`read_notes`、`inspect_performance`、`inspect_instrument`を使用してください。フレーズ測定は最大2,048音符と32段階のサンプルを使用します。生成された曲線検査は最大64四分音符までのクリップを対象とします。不完全な測定はマークされますが、これは成功した検証とはみなされません。大規模な応答には変更不可能な`read_report`ページを使用します。

<a id="prepare-a-proposal"></a>
## 提案を準備する

各変更には具体的な音楽的目的が含まれています。検証では1〜16の変更と現在のコンテンツの改訂を受け付けますが、文書やその元に戻す履歴を変更することはありません。

```json
{
  "operation": {
    "kind": "validate",
    "expected_revision": "COPY_FROM_INSPECTION",
    "changes": [
      {
        "purpose": "Open the second chorus with guitar strokes",
        "edit": {
          "kind": "revoice",
          "clips": [12],
          "sound_id": "COPY_FROM_SEARCH_INSTRUMENTS",
          "name": "Chorus guitar",
          "settings": {"reset": ["pitch"], "strum": {"spread_ms": 25}}
        }
      },
      {
        "purpose": "Lift the pad inside the chorus",
        "edit": {
          "kind": "automation",
          "target": {"kind": "track_gain", "track": 4},
          "start_tick": 92160,
          "end_tick": 122880,
          "points": [
            {"at_tick": 93120, "value": -24},
            {"at_tick": 121920, "value": -12}
          ]
        }
      }
    ]
  }
}
```

サポートされている編集：

| 編集 | 契約 |
| --- | --- |
| `breath` | 明示的なフレーズの休止、短縮されたリリース、指定されたピックアップの省略、および正確なアプローチインデックスに代わるオプションの保持到着。保護された/ボーカルノートおよび可能なタイは拒否されます；適用前に演奏されたスペースは確認されます。 |
| `performance` | 既存のクリップの`set_performance`設定の一部が変更されます。ドラムライターの範囲はオプションで正確に指定できます。ソースノートと作成済みの曲線はそのまま残ります。 |
| `automation` | 既存のネイティブパラメータ1つ、つまり区間の内側に厳密に位置する1〜128のユニークなポイントが残ります。既存の境界値、補間、および外部曲線は変更されません。 |
| `revoice` | 1つの楽器/ドラムトラックから新しいサウンドに1〜16の完全なクリップを転送します。`layer:true`は元のクリップを保持し、コピーされたクリップIDを再発行します。 |
| `transition` | `riser`、`crash`、または`impact`、明示的な境界、期間、名前、およびゲイン付き。 |
| `audio_sfx` | 開始位置、絶対サンプルピーク、またはソースの末尾に沿って揃えられた凍結されたローカルソースコピーで、明示的なゲインとソースタイムフェードが含まれています。 |
| `clip_mute` | スコアを削除せずに休憩を追加または削除します。 |

Revoiceは新しい`search_instruments` IDを使用します。ミキサーストリップ、エフェクト、出力、送信、およびそれらの再発行されたIDを既存のトラック複製操作を通じてコピーします。選択されていないソースクリップは変更されません。ソース楽器パラメータレーンは元のトラックに残ります。古いパラメータアドレスは新しい楽器にコピーされません。オプションの`settings`は新しいクリップのパフォーマンスのみを変更します。セクション固有の提案を作成する前に、適切なフレーズ境界で`edit_clip`を使用してスプリットクリップを処理し、その後、結果のIDとリビジョンを再度確認します。スプリットまたはサウンドハンドオーバー時に持続音、コントローラーリセット、テールを確認してください。

自動化は両方の区間境界で元の値を保持します。ポイントはネイティブ単位を使用し、厳密にその境界の間に位置する必要があります。連続/離散補間は既存のレーンまたは記述子から継承されます。これにより、元の線形ランプと保持された値は要求された指定区間外に保たれます。静的パラメータ値は変更されません。

ネイティブライザーは、境界点で終了する編集可能な弓奏のクレッシェンドです。クラッシュとインパクトは、そこから始まるネイティブドラムアタックです。ゲインは-60..0 dB、ネイティブの長さは1..15,360ティックです。これらのサウンドには外部アセットは必要ありません。望ましい効果が特定の録音された音である場合は、実際のオーディオソースを使用してください。

オーディオSFXは、32 MiBまで、30秒以内の空でないローカルモノ/ステレオファイルである必要があります。ワーカーはデコード前にファイルをコピーし、チャンネル間でサンプルピークを見つけて波形/再サンプリングを準備します。ソースはプロジェクトのテンポには追従しません。アライメントは全テンポマップを通過して変換し、ティック丸め誤差を報告します。フェードはソースのミリ秒単位で、録音に適合する必要があります。曲前のアライメントや既存の曲の長さを延長する編集は拒否されます。準備引数は128 KiBまで制限され、候補ドキュメントと保持ソースは各プランごとに64 MiBの予算を共有します。

例えば、これらの2つの変更オブジェクトは、同じ境界にローカル録音と弓で奏でられるクレスンドロを配置します。現在のバージョンで`operation.changes`にそれらを含めてください：

```json
[
  {
    "purpose": "Place the effect's attack at the chorus",
    "edit": {
      "kind": "audio_sfx",
      "path": "/absolute/local/path/effect.wav",
      "at_tick": 92160,
      "alignment": "peak",
      "name": "Chorus effect",
      "gain_db": -12,
      "fade_in_ms": 2,
      "fade_out_ms": 5
    }
  },
  {
    "purpose": "Build toward the chorus boundary",
    "edit": {
      "kind": "transition",
      "transition": "riser",
      "at_tick": 92160,
      "duration_ticks": 1920,
      "name": "Chorus swell",
      "gain_db": -18
    }
  }
]
```

<a id="apply-and-verify"></a>
## 申請して確認する

準備済みの変更、効果測定、警告をすべて確認し、返送された`plan_id`と元の改訂版を使用します。

```json
{"operation":{"kind":"apply","plan_id":"COPY_FROM_VALIDATION","expected_revision":"SAME_ORIGINAL_REVISION"}}
```

所有者はドキュメントの識別、コンテンツの改訂、有効なジェスチャー、期限を確認します。ソースコピーは適用されるまで非公開です。サウンドの準備とオーディオ作業はUIスレッド外で実行され、失敗、キャンセル、または期限切れの準備はプライベートファイルを削除します。アプリケーションは1回の「元に戻す」編集をコミットします。正確な再試行は、トラック、ノート、オーディオを再度作成することなく、元のレシートを返します。その後の編集や「元に戻す」の後に、通常の履歴/「やり直す」を使用するか、新しい提案を作成してください。変更されていない提案は「元に戻す」履歴を追加しません。

プランは15分後に期限切れになり、プロセス再起動またはバウンディングキャッシュのエバキュートが行われます。キャッシュは最大8つのプランと256 MiBを保持します。保存されたプロジェクトの呼び出しは、そのプロセス内の異なるセッションの開く際にプランを再利用できます。プロセス再起動には再検証が必要です。ライブ操作は保存されず、変更された保存操作は既存のチェックポイント保存アダプターを使用します。読み取り専用/プランモードはアプリケーションを拒否し、複合アプリケーションは通常のライブ権限決定が必要です。ソースファイル/プラグインの準備は確認のために別々に分類されます。既存の拒否ルールはこのツールに対して引き続き適用されます。

独立した呼び出しで、影響を受けたノート、パフォーマンス、オートメーションを読み返します。`inspect_audio`/`preview`で前後の同じ小節をレンダリングします。モデルが音声を聴ける場合は、`listen`とその比較IDを使用します。ボイシング変更後にレベルバランスとハンドオーバーテールを再確認します。保存された設定、ゼロ以外のイベントカウント、または変更されたPCMが、アレンジメントがより良い音が出ることを証明するものではありません。ローカルの修理試行は2回に制限し、解決されていない音楽的またはリソース上の状況を報告します。

休符、コールアンドレスポンス、選択的レイヤーリング、センドオートメーションは、すべての音を置き換えることなくコントラストを提供できます。意図的な繰り返しとフレーズのアイデンティティを保ちます。[Melody breathing](melody-breathing-plan.ja.md)は、クリップのジョイン、サステイン、テールを含む、継続的に再生される前景メロディに対する実装された診断と明示的な修理を文書化しています。

<a id="validation"></a>
## 検証

セッションテストは、正確なスコア/曲線保持、範囲限定の自動化、ソースルーティング、レイヤーのアイデンティティ、不可変のSFXコピー、アライメント、キャンセル、古い所有者/バージョン、準備失敗、リトライレシート、そしてUndo/Redoをカバーします。カタログおよびポリシーテストは、オプトインスキーマと読み取り専用/プラン拒否をカバーします。

オプトインGPUIテスト`installed_agent_arranges_sections_with_performance_automation_and_sfx`は、隔離された保存されていない32バーフィクスチャーに対して、実際のClaude/Codex/rigワーカーを実行します。`AURIS_ARRANGEMENT_HARNESS=1`と`AURIS_TOOL_SURFACE_EVAL`を[開発](development.ja.md#real-agent-window-tests)に記載されている構成に設定します。セクションのボイシング変更、ストラム、範囲限定パッドゲイン、コピーされたオーディオSFX、ネイティブライザー、独立した読み返し、数値オーディオ検査、1リクエストでのUndo/Redoをチェックします。エビデンスは実際のバックエンド結果を記録します。テストの存在自体がモデルの信頼性やリスニング品質を証明するものではありません。

[2026-10-23 validation record](../tools/eval/references/agent-arrangement-2026-10-23.json)には実際の結果が含まれています。Codexは、独立した読み返し、ペアリングされたオーディオ測定、そして1回のUndo/Redoを含む、数値のみのフィクスチャーを57.45秒で完了し、ツールエラーはありませんでした。ClaudeはOAuthセッションが期限切れになったため、推論前に停止しました。ローカルのQwen 27Bトライアルは、提案を適用せずに診断中にタイムアウトしました。以前のCodexトライアルは、別々の音声批評モデルでストールしました；受け入れられたフィクスチャーは明示的に数値検査に限定されています。これらの測定のいずれも、改善された音楽的品質を確立していません。
