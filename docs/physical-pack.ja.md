# 物理ドラムキットのコピー合成

[English](physical-pack.md)

工場出荷時の励振・損失設定と因果的な放射の色付けを、7種類のドラムキットファミリーの実録音に対してフィットする。ベースラインは `cfcd5a9` で、比較には24 kHzと48 kHzで実際に生成したRust PCMを使う。すべての係数は学習用音声だけで選ぶ。検証は変更が有用かどうかを決めるために使い、最適化への入力にはしない。

<a id="references-and-split"></a>
## 参照データと分割

録音にはAlexander Holmの元の[Salamander Drumkit](https://github.com/endolith/Salamander-Drumkit)を使う。[元アーカイブ](https://archive.org/details/SalamanderDrumkit)にもミラーされている。これは実際のキットを上方から録音したもので、音源シンセサイザーのレンダーではない。アーカイブの元ライセンスはCC BY-SA 3.0だったが、作者は[2022年にサンプリング音源をパブリックドメインに提供した](https://rytmenpinne.wordpress.com/2022/03/04/good-news-everyone/)。キャプチャーマニフェストにはクレジットと元アーカイブの識別情報を、ノートマニフェストには各ヒットの元メンバー名とハッシュを保持する。

コホートはフィット前に固定し、元録音のドラムヒット151件を、結果に応じて除外することなく使う。各元ファミリー／レイヤーの番号付きヒットの先頭8件を選び、奇数を学習、偶数を検証に回す。別のスネア、ゴースト、スティック、半開きハットなどの奏法はこの固定コホートの対象外である。同じヒットを両方の分割に入れることはない。名前付きダイナミクスは速度の代用値であり、測定したMIDI速度ではない。

| ファミリー | 学習 | 検証 |
| --- | ---: | ---: |
| キック | 12 | 12 |
| スネア | 12 | 12 |
| クローズドハット | 8 | 8 |
| オープンハット | 10 | 8 |
| クラッシュ | 6 | 5 |
| ライド | 6 | 6 |
| タム、低音／高音 | 23 | 23 |
| 合計 | 77 | 74 |

ソースハッシュ、オンセットオフセット、利用可能な長さ、抽出したfloat32 WAVのハッシュは `tools/eval/references/physical-pack-{captures,notes}.json` に固定する。オンセットは、1 ms分解能で最初に局所2% RMSを超えた時点とする。冒頭に1秒を超える無音があるキャプチャーも含む。抜粋は3秒で、利用可能な長さが短い場合はゼロパディングする。合成ノートは3秒間保持するため、人為的なノートオフでフィットを改善することはできない。

<a id="measurements"></a>
## 測定

両方の信号に、因果的な2次30 Hzハイパスをかけてから、抜粋全体のRMSを0.1に正規化する。これにより、サブバンドのマイクランブルが正規化に入らない。フレームごとの正規化、時間ワープ、合成オンセットの探索は行わない。512サンプルと2048サンプルのHann窓、ホップ240、30 Hz–10 kHzの64本の面積正規化HTKメル帯域から `log(1 + 10000 * mel_power)` を生成する。平均絶対距離には、0–50 msを0.3、50–250 msを0.3、250–3000 msを0.4の重みで与え、2つの解像度について平均する。

副次測定は、抜粋全体で正規化した20 ms RMSエンベロープのdB誤差と、帯域制限した抜粋エネルギーの90%が含まれる時間の絶対誤差である。これらは打撃の別の側面を測定し、スペクトル距離が改善した場合も確認できる。48 kHzの本番レンダーは、同じ24 kHz解析のためにポリフェーズ・ダウンサンプリングする。

対応する95%区間には、シード20261003の2,000回ブートストラップ再標本化を使い、元キャプチャーごとにグループ化する。多重比較補正は行わず、このコホートを記述する。ホールドアウトしたヒットは、学習データと同じキット、演奏者、録音経路を共有する。したがって、これは録音ドメイン内の改善を示すものであり、あらゆるドラムキットへの一般化を示すものではない。

<a id="fitting-and-runtime-behavior"></a>
## フィットと実行時の動作

範囲を制限した座標探索は、変更していないモデルから開始する。接触の硬さ、打撃位置、減衰、ダンピングには、宣言した範囲の0.18/0.06のステップを使い、その後0.03で精密化する。90 Hz–10 kHzを幾何学的に配置した12個のピーキングセクションはQ=0.9で、ゲインを±9 dBに制限し、0.25/0.10のステップと0.0001のゲイン二乗平均ペナルティーを使う。これらの広い事前分布には励振とマイクの色付けが含まれ、測定した胴体アドミタンスではない。Rustワーカーは接触／損失候補をすべてレンダーする。因果フィルターの代理モデルで放射探索を高速化し、最終的な実PCMは絶対サンプル誤差 `2e-4` 以内で一致しなければならない。

キットはファミリーごとに独立してフィットするが、共有制御は既存のデフォルトを保つ。硬さ／位置／ダンピングには工場出荷時からの相対オフセットを与え、減衰にはフィットした比率を乗じる。ファミリーごとの放射は、現在鳴っているヒットと終了しつつあるヒットの合計に従う。学習ノートのRMS中央値は、公開Level制御を変更せず、固定出力正規化によって保つ。

スネアとタムの候補は、ラベルを使わない既存の音響役割契約も維持しなければならない。スネアは適合度0.65以上を維持し、25–200 msでワイヤー／ヘッドの帯域振幅比を2.05より大きくする必要がある。すべてのタムキーは、タム適合度とキック適合度の差を少なくとも0.05に保つ必要がある。これらのガードには合成プローブと学習録音を使い、検証ラベルは使わない。元／フィット済み制御値と放射強度0/0.125/…/1の組み合わせを選び、固定ステップ0.125/0.05/0.02で実現可能なゲインを精密化する。このガード付き選択では、学習エンベロープ誤差が最大5%まで増えることを許す。制約なしでスネアのメル損失を大きく減らした候補はワイヤー／役割契約に失敗したため、下記の小さい補正を採用して契約を維持する。この精密化は数値回帰チェックの後に行ったもので、区間はモデル開発後の記述統計であり、未使用の最終テストではない。

係数と7個の固定パッドバッファーはコールバックの外で準備する。チョーク、スティール、ミックス、リセットではアロケーションを行わない。All-sound-offでは2 msかけてフェードし、放射メモリをクリアする。自然な放射の残響は、打撃モードが非アクティブになった後もしばらく続くことがある。ノートのタイミングと書き込まれるプロジェクトデータの表現は既存のままである。

<a id="targeted-snare-and-ride-voicing"></a>
## スネアとライドの狙いを定めたボイシング

2026-10-19のボイシング調整は、鋭いドラム音を対象にした孤立ヒット調査に基づく。スネアではワイヤー信号だけに3.8 kHz、Q=1.3の-4 dBピーキングセクションを適用し、低いラトルを残すためワイヤーゲインを1.145に固定する。膜とその減衰は変更しない。ライドではプレートモード0と8を、それぞれ従来振幅の0.6と0.8で励振する。これらのモードは2.65 kHzと12.36 kHzにある。減少量は打撃エネルギーの正規化に従うため、取り除いたエネルギーを他のモードに配分せず、モードの周波数と損失は変わらない。

48 kHz、速度1では、スネアの最初の50 msにおける2–5 kHzパワーが1.52 dB低下する。700–1500 Hzのワイヤー本体と7–10 kHzのシズルは、それぞれ+0.94 dBと+0.55 dB変化する。既存の25–200 msワイヤー／ヘッド振幅比は2.05を上回る。ライドの50–250 msのラインパワーは、2.65 kHzで4.45 dB、12.36 kHzで1.90 dB低下する。ノート全体のRMSはスネアで0.39 dB、ライドで1.14 dB低下し、90%エネルギー時間の変化はどちらも1 ms未満である。これらの測定は音色の指定された部分を維持するものであり、知覚品質や実録音との距離が改善したことを示すものではない。

`tools/eval/drum_harshness.py` は、9つのパッド／音域、3つの速度、44.1/48/96 kHzについて、凍結した変更前／変更後ワーカーを比較する。無関係なパッドはサンプル単位で一致しなければならない。絶対パワー、エネルギー持続時間、レンダラーのハッシュ、共通ゲインの試聴ペア、追加のRMS一致候補を保存する。概要測定は `tools/eval/references/drum-harshness.json` にある。再ビルド前に元ワーカーを保持する。

```sh
uv run tools/eval/drum_harshness.py <before-worker> <after-worker> target/drum-harshness/fix
uv run --with pytest --with numpy --with scipy --with soundfile pytest tools/eval/test_drum_harshness.py
uv run --with ruff ruff check tools/eval/drum_harshness.py tools/eval/test_drum_harshness.py
```

シンボリックな定規は変更しない。`music.py` を通した別の8秒、4ヒットのスネア診断では、1つの窓と固定したロック向けプロンプトを使い、TuneJury報酬が-0.0575、MuQ-MuLanの正コサインが+0.00089変化する。条件と抜粋位置は一致している。これらの孤立ヒットの混在したスコアから、曲の好みや知覚される音色が改善したとは言えない。

<a id="held-out-production-results"></a>
## ホールドアウトした本番結果

以下は実際の48 kHz Rustレンダーによる最終結果で、距離は小さいほどよい。

| ファミリー | 変更前メルL1 | 変更後 | 減少率 |
| --- | ---: | ---: | ---: |
| キック | 0.113811 | 0.083642 | 26.51% |
| スネア | 0.565809 | 0.553065 | 2.25% |
| クローズドハット | 0.368537 | 0.323287 | 12.28% |
| オープンハット | 0.398668 | 0.356545 | 10.57% |
| クラッシュ | 0.484578 | 0.380532 | 21.47% |
| ライド | 0.367159 | 0.269354 | 26.64% |
| タム | 0.229406 | 0.145699 | 36.49% |

対応する7個の平均差区間はすべて0未満である。スネアのエンベロープ誤差は11.39→11.40 dBとほぼ不変である。オープンハットとライドには依然として42.35 dBと35.70 dBの大きなエンベロープ誤差があり、録音された後半の残響は忠実に再現されていない。ノートごとの位相、区間、その他の測定値は `tools/eval/references/physical-pack-validation.json` に保持する。

開発マシンでは、重なり合う24個のクラッシュが5.333 msのコールバック予算に対して約0.22 msの中央値、0.23 msのp99を使い、モーション監視も同じ予算内に収まる。アロケーション、タイミング、リセット、サンプルレート／極端な制御値、音高、ワイヤー、チョーク、キット全体の音響役割テストで実行時の動作を検証する。作曲家の測定行は変更しない。9つのプリセットのAudiobox測定値とWAVハッシュは同一である。このプリセット検査は変更した工場出荷時サウンドを使わず、それらの品質改善を示さない。スコアと追加の共通ゲインによるキットグルーブ比較は、参照ファイル横の `physical-pack-regressions.json` を参照する。その16秒グルーブではAudioboxのProduction Qualityが7.54から7.67に上昇する。これは単一の学習済み回帰診断であり、客観的な知覚品質の保証ではない。

<a id="reproducing-the-experiment"></a>
## 実験の再現

オーディオは `target/` 以下で引き続き無視し、マニフェスト、フィットした係数、レポートはバージョン管理する。係数を適用する前に変更前ワーカーを保持する。アーカイブした実行ファイルが演奏者のベースラインになる。

```sh
cargo build --release -p auris-synth --example physical_fit_render
uv run tools/eval/fetch_physical_pack.py target/physical-pack/reference --lock tools/eval/references/physical-pack-captures.json
uv run tools/eval/prepare_physical_pack.py target/physical-pack/reference --lock tools/eval/references/physical-pack-notes.json
uv run tools/eval/fit_physical_pack.py target/physical-pack/reference <before-worker> target/physical-pack/fit.json
uv run tools/eval/fit_physical_pack.py target/physical-pack/reference <before-worker> target/physical-pack/validation.json --fit tools/eval/references/physical-pack-fit.json --candidate <after-worker> --audition target/physical-pack/audition
```

Windowsでは `.exe` のパスを使う。ベースライン／候補の実行ファイルハッシュ、依存関係のバージョン、正規の参照／フィットハッシュを記録する。参照アーカイブ全体は387,611,727バイト以下に制限する。抽出前にハッシュを確認し、アーカイブからフラットなローカルパスへ読み込むのは明示的に選択したドラムファイルだけにする。
