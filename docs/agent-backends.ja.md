# エージェントバックエンド

[English](agent-backends.md)

エージェントパネルは、サインイン済みのCodex、Claude Code、OpenCode、Antigravity CLI、ローカルのOllama、および設定 > エージェントで設定されたAPI接続を検出します。`OPENAI_API_KEY`を使用すると、OpenAIのデフォルトエンドポイントでの検出も有効になります。プロバイダーは並行して照会され、利用できないプロバイダーは他のプロバイダーから返されるモデルを非表示にしません。

`OPENAI_API_KEY`はOpenAI本体 (`https://api.openai.com`) にのみ送信されます。カスタムのOpenAI互換URLは、接続名にAPIキー変数の名前が含まれていない限り、キーは付与されません。したがって、AurisをLANサーバーや他のサービスに指向しても、OpenAIの認証情報が渡されることはありません。

メッセージコンポーザー下部のコマンド行でモデルを選択します。各オプションには接続名が表示され、例として `GPT-6.1 Sol (Codex)` があります。カスタムAPI接続にはホスト名も表示されます。オプションを選択するとバックエンドが自動的に切り替わり、設定済みのAPI接続は次回以降の検出にも使われます。モデルメニューの「更新」を選ぶと検出をやり直します（セレクターにフォーカスがあるときは `Ctrl+R` / `Command+R`）。推論レベルはモデルの横に表示され、Codexが公開している推論レベルが選択を決めます。権限ルールは左側の承認モードメニューから開けます。ターンの実行中は円形の送信コントロールが「停止」に変わります。

**Fast**トグルは、推論の努力の横にあるもので、Codex、Claude Code、およびOpenAI独自のAPI接続でファストモードを要求します。これは推論の努力とは独立して保存され、ターンが実行中の間は無効です。モデルおよびアカウントの資格は引き続き適用され、プロバイダーは追加の使用料を請求する場合があります。Codexは`service_tier`設定を使用し、Claude Codeはセッション固有の`fastMode`設定を受け取り、OpenAI APIはリクエスト時に`service_tier`を受け取ります。詳細は[Codex speed](https://learn.chatgpt.com/docs/agent-configuration/speed)、[Claude Code fast mode](https://code.claude.com/docs/en/fast-mode)、[OpenAI API fast mode](https://developers.openai.com/api/docs/guides/fast-mode)をご覧ください。

設定 > エージェントには **Repeated tool failure limit** があり、1〜20（既定値は5）で設定できます。Auris API と Antigravity のループでは、1回のユーザーターン中にツール名と正規化した引数ごとに失敗回数を数えます。呼び出しが成功すると、その組み合わせの回数はリセットされます。引数を修正した呼び出しには別の上限が適用されます。設定した回数に達すると、同じ呼び出しをもう一度実行する前にターンを停止します。完了した編集はドキュメントに残り、新しいユーザー指示で上限がリセットされます。

Claude Code は内部のツールループを管理します。Auris のツールエラーの直後に成功した CLI ターンを終了した場合、Auris は既存のトランスクリプトで修正を求めます。この処理は設定した失敗回数の範囲内で、継続要求を最大でも1回少なくした回数に制限されます。エージェントには現在のドキュメントを確認し、完了した編集を保持するよう求めます。書き込みをそのまま繰り返すことはありません。新しいツールエラーを伴わない新しい返信は自動的に繰り返しません。権限拒否、キャンセル、ネイティブのシェル／ファイルエラー、通信エラーではこの復旧を行いません。明示的な CLI ターンエラーは表示されますが、次のユーザー要求に使えるストリームは維持されます。Codex と OpenCode はそれぞれのツールループを管理し、すべてのネイティブバックエンドには設定した復旧案内が渡されます。権限の判断はこの上限とは独立しています。

連続したツール呼び出しは、その回数と実行中または失敗した呼び出しを示す折りたたまれた要約を共有します。グループを開くと、各呼び出しの引数と結果を確認できます。ユーザーメッセージとアシスタントの返信は、別々のグループに保持されます。

<a id="reference-attachments"></a>
## 参照添付ファイル

次のメッセージに添付するには、ファイルをエージェントパネルにドラッグします。そこにオーディオをドラッグすると参照ファイルが添付され、アレンジメントにオーディオをドラッグすると、オーディオが曲にインポートされます。添付されたファイル名は表示され続け、送信前に各ファイルを削除できます。メッセージには最大8つのファイルが受け付けられます。オーディオソースは各最大512 MiB、合計1 GiBまでで、メモリ容量の制限とキャンセルにより、プライベートなローカルスナップショットにコピーされます。画像は各最大25 MiBに制限されます。

Rig、Codex、Claude Code、OpenCodeは参照添付ファイルをサポートします。PNG、JPEG、GIF、WebPは画像部分として送信されます。UTF-8テキスト、Markdown、歌詞、CSV、JSON、ソースファイルは、テキストファイルあたり最大256KiBの区切り付き参照データとして送信されます。添付ファイル内の指示は参照コンテンツとして残ります。選択したモデルは、提供されたメディアをサポートしている必要があります。CLIバックエンドでは、オーディオファイルをローカルで分析し、長さ、一定テンポの代替案、推定ビート、メジャー／マイナーコード候補をテキスト形式の測定値として送信します。長いレポートでは、録音全体から最大256個のビートと256個のコードウィンドウをサンプリングし、ソースのタイムスタンプとサンプリング間隔を付けます。分析は曲を編集したり曲にインポートしたりせず、バックグラウンドで実行されます。これらの経路では生のオーディオはローカルに保持されます。

オーディオ参照は会話に限定された不可変のスナップショットであり、合計でディスク上の8ファイル/1 GiB内に保持されます。ファイルを追加すると、古い参照が期限切れになる可能性があります。エージェントが参照が期限切れになったと報告された場合は、ファイルを再度添付してください。

ネイティブオーディオ入力を使用する場合は、`input_audio`を実装したOpenAI互換モデルを使用してください。選択したrigプロバイダーがオーディオを送信できない場合も、パネルは下書きを保持します。

ネイティブAPIリクエストには、Base64エンコード前の実際に準備したペイロード用として、別途128 MiBの予算があります。25 MiBを超えるオーディオソースは、モノ／ステレオのチャンネルとタイミングを維持したまま、フルレングスの16 kHz・16ビットPCM WAVへ自動変換されます。通常のデコーダの512 MiBデコード済みサンプル予算内で、最大30分のモノ／ステレオオーディオを受け付けます。抜粋を暗黙に選択することはありません。元のスナップショットはローカル解析用に変更せず保持し、モデルにはアップロード時の変換を説明するメタデータを渡します。小さいソースは元の形式で送信します。準備はキャンセル可能なワーカーで行い、デコーダー／リサンプラーの呼び出しはキャンセルを検知する前に完了します。選択したエンドポイント／モデルが、追加の形式、長さ、またはリクエスト制限を課す場合があります。128 MiBはAurisのリソース予算であり、プロバイダーの機能を保証するものではありません。ネイティブリクエストが収まらない場合は、添付ファイルを減らすか、CLIのlocal-reference経路を使用してください。CLIの画像／テキストペイロードには、ローカルオーディオを除き、別途合計25 MiBの予算があります。

<a id="codex-setup"></a>
## Codex のセットアップ

[Codex CLI](https://learn.chatgpt.com/docs/cli) をインストールし、ChatGPTアカウントで `codex login` を実行します。Auris は `codex app-server --listen stdio://` を起動し、Codex は認証と推論を管理します。Auris は資格情報ファイルを読み込むことも、rig を通じてサブスクリプショントークンを使用することはありません。このバックエンドでは API キー認証は拒否されます。API エンドポイントには rig を使用してください。

実行可能なファイルのパスを空欄にすると、PATHを検索できます。Windowsでは、Aurisはnpmインストール内のネイティブ実行可能ファイルも認識します。カスタムパス名は`codex.exe`と名付ける必要がありますが、PowerShellやバッチランチャーではありません。この統合はCodex CLI 0.163.0でテストされています。アプリサーバープロトコルは実験的であるため、互換性のないCLIバージョンでは起動エラーが発生する可能性があります。

新しい保存されていない曲でエージェントパネルを開き、楽器トラックを追加するように依頼します。トラックはすぐに表示され、曲は保存されず、元に戻す操作で通常のドキュメント履歴を通じてトラックが削除されます。同じ許可モードと拒否ルールがすべてのバックエンドに適用されます。保存は依然としてユーザーによる明示的な操作が必要です。

<a id="claude-code-setup"></a>
## Claudeコードの設定

[Claude Code](https://code.claude.com/docs/en/setup)をインストールし、サインインするには`claude`を実行してください。設定 > エージェントでその実行可能ファイルを設定し、エージェントパネルでClaude Codeモデルを選択します。認証と推論はインストールされたCLI内で実行され、リグエンドポイントやAPIキーのプレファレンスは使用されません。サポートされている環境変数を通じてCLIでの認証は引き続き利用可能です。

実行可能なパスを空欄にすると、PATHとネイティブの`.local/bin`インストールを検索できます。Windowsでは、`.cmd`や`.ps1`のランチャーではなく、ネイティブの`claude.exe`を使用してください。この統合はバイナリ方向ストリーム-json制御プロトコルを使用しており、Claude Code 2.1.304でテストされています。モデルはCLIの初期化レスポンスから取得されます。デフォルトの努力度はCLIのデフォルトを維持します。NoneとMinimalはLowにマップされます。

Claude CodeはCodexと同じ認証済みのライブMCPエンドポイントに接続するため、通常の権限とUndoの経路を通じて保存されていない曲を編集できます。各ワーカーには、継承設定、フック、プラグイン、スラッシュコマンド、Chromeを無効にした専用のMCP構成が割り当てられます。明示的なネイティブシェルおよびファイルツールは、デスクトップの承認ポリシーを通過します。保存済みの会話はプロジェクトフォルダを作業ディレクトリとして使用し、未保存の会話は使い捨てのスクラッチスペースを使用します。ベアラートークンは一時構成ファイルに保存され、ワーカー終了時に削除されます。CLIセッションの永続性は無効にしており、Aurisが会話を保存し、ワーカーが置き換わったときにテキストを復元します。Stopはツールを取り消し、ターンを中断して、子プロセスを終了します。オーディオは`inspect_audio`で検査できます。

オプションの輸送用煙テストでは、推論なしでインストールされたCLIを使用します。

```sh
cargo test -p auris-agent installed_claude_connects_to_the_live_mcp_catalog -- --ignored
```

推論を確認するには、`cargo test -p auris-agent installed_claude_edits_an_unsaved_song -- --ignored` を実行すると、Haiku にメモリ内の曲に1つのトラックを追加するように要求され、Undoが検証されます。これはCLIで設定されたアカウントを使用し、保存された曲を開いたり変更したりすることはありません。

<a id="opencode-setup"></a>
## OpenCodeの設定

[OpenCode](https://opencode.ai/docs/)をインストールし、プロバイダーを設定するには `opencode auth login` を実行します。設定 > エージェントで実行可能なファイルのパスを空にしておくと、PATH、`.opencode/bin`、`.local/bin`（macOSの標準Homebrew場所を含む）を検索できます。または、ネイティブの実行可能なファイルを明示的に指定することもできます。Windowsでは `opencode.exe` を選択してください。`.cmd` と `.ps1` のランチャーはサポートされていません。エージェントパネルのモデルメニューを更新し、「OpenCode」とラベル付けされたモデルを選択します。モデルIDはプロバイダーと宣伝されているバリエーションを保持するため、異なるプロバイダーの同様に名付けられたモデルは別々に扱われます。推論を制御するにはモデルバリエーションを選択します。このバックエンドでは、別々のエフォート制御はデフォルトに保持されます。

Aurisは`opencode acp`をリリースし、[ACP v1 over stdio](https://opencode.ai/docs/acp/)について発表しました。このトランスポートは、グループ化された選択を含む、元の`models.availableModels`カタログとモデルの`configOptions`の両方をサポートします。認証と推論はOpenCode内部で行われ、Aurisは認証ストアを読み取っていません。統合機能は起動前にCLIバージョンを確認し、OpenCode 1.xまたは2.xに対応する構成を生成します。V2は`agents`、`system`、順序付けられた`permissions`ルール、およびネイティブの`shell`ツールを使用し、V1は元の構成フィールドを使用します。未知の主要バージョンは拒否されます。[現在のACPリファレンス](https://opencode.ai/v2/docs/cli/acp/)および[V2権限](https://opencode.ai/v2/docs/permissions/)を参照してください。

各ワーカーは専用の構成ホームを使用し、プロジェクト構成、外部スキル、自動共有、スナップショット、LSP、フォーマッターを無効にします。ユーザープラグイン、カスタムツール、カスタムプロバイダー構成、その他の構成済みMCPサーバーは継承されません。OpenCodeの通常の認証データディレクトリは、デフォルトの認証プラグインおよびプロバイダー環境変数とともに保持されます。OpenCodeの認証フローまたは環境構成でサポートされているプロバイダーを使用してください。rig API設定はこの経路を構成しません。ユーザー構成ファイルは編集されません。ネイティブシェルおよびファイルツールは同じAuris権限ゲートを要求します。未知のリクエストや、クライアントからの予定外のファイル／ターミナルリクエストは拒否されます。V2は`codemode: false`の専用構成を通じてライブサーバーを受け取り、そのトークンはそのファイルに保存せず、子プロセス専用の環境変数から展開します。これにより各MCP操作は直接ツールリストに残り、既存のAurisゲートの対象になります。V1はACP stdinを通じて認証済みサーバーを受け取ります。

認証済みのライブMCPサーバーは、既存の権限および「元に戻す」パスを通じて、保存されていない変更を含むオープンな曲を編集します。画像とテキストはACPコンテンツブロックを使用し、オーディオは他のCLIバックエンドと同じローカル分析および音声認識ツールを使用します。ストップはライブ呼び出しをキャンセルし、`session/cancel`を送信し、子プロセスを終了します。Aurisは継続して動作し、独自のテキストトランスクリプトを復元します。OpenCodeも通常データディレクトリにセッションを保持する場合があります。Aurisからの手動コンパクションはまだサポートされていません。承認審査では、すべてのツールが拒否された別のセッションを使用します。

スタートアップは推論を許可する前に、実際の認証済みMCPツールカタログリクエストを待機します。

デフォルトのテストでは、スクリプト化されたACPピアと実際のHTTP MCPエンドポイントを使用して、モデルの認証情報なしでライブ編集、元に戻す操作、ストリーミング、権限決定、キャンセルを検証します。OpenCodeがインストールおよび構成されている場合、このチェックは推論なしで起動状態とモデルカタログを確認します：

```sh
cargo test -p auris-agent installed_opencode_lists_models_and_opens_a_live_mcp_session -- --ignored
```

<a id="antigravity-cli-setup"></a>
## Antigravity CLI の設定

[Antigravity CLI](https://antigravity.google/docs/cli/install/)をインストールし、サインインするには`agy`を実行してください。設定 > エージェントでは、オプションとしてネイティブの`agy`/`agy.exe`実行可能なパスを受け付けます。空欄にすると、PATHと`.local/bin`を検索します。エージェントモデルメニューを更新し、「Antigravity CLI」と表示されるオプションを選択します。モデルのスラグは`agy models`から取得され、リグAPIのURL/キー設定は保持されます。デフォルトの推論ではCLIのデフォルトが維持され、Low、Medium、Highの選択肢が利用可能です。

この統合はCLI 1.4.6でテストされています。文書化された[stream-json入力および出力](https://antigravity.google/docs/cli/headless/)と構造化された出力を使用します。CodexやClaude Codeとは異なり、このプロトコルには外部ツール承認チャネルはなく、テキストブロックのみを受け付けます。一時的な[カスタムエージェント](https://antigravity.google/docs/subagents/)は、実行せずに構造化されたツールボックスリクエストを返信する`finish`のみを公開します。Aurisは送信前にすべてのリクエストされたツール名とオブジェクト形状を確認し、共通のToolHostを通じて各呼び出しを検証して実行し、結果を同じCLI会話に送信します。したがって、すべてのドキュメント編集は通常のライブ権限と「元に戻す」機能を使用します。テキストカタログはパラメータの単位、例、フィールド説明を保持します。継続メッセージはホストの指示と信頼できないツール結果を区別し、完了時に空のコールリストを明示的に要求します。同じツールが繰り返し失敗したり、連続して3回の同じリクエスト/結果バッチが発生すると、以前の編集を元に戻すことなくターンを停止します。ネイティブのCLIシェル/ファイル/ブラウザ/サブエージェントツールは利用できません。権限バイパスフラグは使用されません。

テキスト参照とローカルオーディオ測定がサポートされています。画像添付は送信前に拒否され、下書きは別のバックエンドでも利用できる状態で保持されます。構造化レスポンスは、生のJSON断片を表示せず、検証されるまでバッファリングされます。手動コンパクションは利用できません。完了したターンはAurisの会話ストレージを使用し、置き換えられたワーカーは履歴テキストを受け取りますが、ネイティブCLIの会話IDを再開することはありません。CLIは通常のプロファイル内に独自のネイティブトランスクリプトを保持する場合があります。Stopはstdinを閉じ、Aurisが保留中のツールをキャンセルして遅れて届いた編集を拒否する間に、子プロセスを終了します。

呼び出しはエージェント、スキーマ、ログ用の専用一時フォルダを使用し、シャットダウン時に削除します。認証はインストール済みCLIの内部に残ります。CLIは呼び出しごとにグローバルフック、MCPサーバー、プラグインを分離できないため、バックエンドはそれらの拡張機能を含むプロファイルを継承せず拒否します。グローバルCLI構成を編集したり、曲フォルダをCLIワークスペースとして再利用したりすることはありません。空のグローバル構成ファイルは受け入れます。

`cargo test -p auris-agent antigravity`は、アカウントなしでスクリプト実行、承認、拒否、Undoジョブのテストを実行します。オプションのサインイン済み推論チェックは次のとおりです：

```sh
cargo test -p auris-agent installed_antigravity_returns_structured_tool_requests_without_native_tools -- --ignored
```

曲を実行したり開いたりすることなく、1つの構造化された`add_track`コールを要求します。

より広範なオプトインスイートは、サインインされたCLIと実際の推論を使用します：

```sh
cargo test -p auris-agent installed_antigravity_ -- --ignored --nocapture --test-threads=1
```

使い捨ての4バーメロディ/ベース/ドラムアレンジメントを構成し、ノートとハーモニーを読み返し、ピッチ/パフォーマンス/ミキサーコントロールを編集し、リクエストレベルのUndo/Redoを確認します。サウンド選択、トラック名変更、クリップコピーおよび再生ループをテストし、次に8秒分のWAVをレンダリングして測定し、MIDIをエクスポートし、テキスト/オーディオ参照を送信し、代替ワーカーで会話履歴を復元し、拒否およびキャンセルされた編集をテストし、モデル発見および独立した承認/拒否レビューを確認します。出力および会話ファイルは一時ディレクトリにリアルタイムで保存され、保存された曲は開くことはありません。これらのチェックには`gemini-3.8-flash-low`モデルが必要で、推論クレジットが消費されます。

<a id="runtime-boundary"></a>
## ランタイムの境界

`auris-agent::Worker`はバックグラウンドランタイムとキャンセルを管理します。各バックエンドは会話ループを管理します。rigはそれをローカルで実行し、Codexはアプリサーバーの子プロセスを駆動し、Claude Codeはstream-jsonを使用し、OpenCodeはACPを使用し、AntigravityはAurisが実行する構造化リクエストを返します。プロバイダープロトコルの型はバックエンド内部に留まります。`ToolHost`はフラットなツールボックス呼び出しを正規化し、認証と実行を直列化して、ウィンドウへライブコマンドを送信します。ウィンドウはセッションを管理し、編集直前に権限を再確認します。

Codexは、会話ごとにランダムなベアラートークンを使用して、一時的なループバックポート上の組み込みストリーミング可能HTTP MCPサーバーに接続します。このエンドポイントは、保存済みファイルの`auris-mcp`カタログではなく、ライブのツールカタログを公開します。未保存のドキュメントもサポートし、曲の2つ目のコピーを開くことはありません。Codexのツール承認は共通の`ToolHost`に委ねられますが、アプリケーションのライブ権限チェックは引き続きすべての呼び出しを承認します。ワーカー終了時にリスナーと子プロセスを取り消します。Stopリクエストはプロセス終了前にCodexのターンを中断し、ウィンドウは直ちに古い編集を受け取らなくなります。

CLI構成は専用ディレクトリを使用する一方、ネイティブツールは保存済みの会話ではプロジェクトフォルダ、未保存の会話では使い捨てのスクラッチスペースで動作します。Aurisはこの呼び出しに対して継承されたMCPサーバー、プラグイン、アプリ、フック、サブエージェントを無効にし、CodexとClaude Codeではプロンプト送信前に有効なMCPカタログを確認します。ネイティブシェルとファイル操作は同じ承認ポリシーを使用しますが、それらの外部への影響はAurisのUndo対象外です。ユーザー構成ファイルは編集しません。予期しないサーバー側リクエストは拒否します。プロセス引数にライブMCPベアラートークンを含めることはありません。

完了したターンは既存のAurisトランスクリプトストレージを使用します。Codexスレッドは一時的です。代替ワーカーは保存済みテキストを過去の文脈として一度受け取り、その後はCodexがアクティブな会話を所有します。トランスクリプトのプレビューとリセット生成チェックは引き続きrigと共有されます。

パネルの[会話リスト](agent-conversations.ja.md)は、各プロジェクトに対して複数の独立した履歴、ドラフト、読みやすいツール結果を保持します。

<a id="validation"></a>
## 検証

`cargo test -p auris-agent`には、実際のHTTP MCPエンドポイントを呼び出し、一般的な権限ゲートを通過させ、実際の保存されていないヘッドレスセッションを編集し、Undoを検証するスクリプト化されたアプリサーバーピアが含まれています。既存のデスクトップハーネスは、ウィンドウ内のライブ編集と権限を確認します。デフォルトのテストにはモデルアカウントは必要ありません。

ChatGPT認証付きのCodexインストールを使用すると、このオプションのトランスポートチェックは、推論を実行せずにアプリサーバーを開始し、そのライブMCPカタログを確認します。

```sh
cargo test -p auris-agent installed_codex_connects_to_the_live_mcp_catalog -- --ignored
```

実際のモデルのターンを確認するには、`cargo test -p auris-agent installed_codex_edits_an_unsaved_song -- --ignored`を実行します。サインイン済みのChatGPTサブスクリプションを使用して、メモリ内のセッションに1曲を追加し、Undoを検証します。保存済みの曲を開くことも変更することもありません。
