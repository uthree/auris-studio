# メロディーの呼吸

[English](melody-breathing-plan.md)

アレンジハーネスはフレーズ間の空間を測定し、前景ノートの明示的な修復を準備します。`AURIS_ARRANGEMENT_HARNESS=1` で有効にします。共通の作曲案内も、新しい音楽を書くときに手動ノートツールまたは生成作曲を通じて、呼び出し、継続、回答、呼吸点を計画するようエージェントに求めます。

元の報告は連続して演奏するエージェント作曲リードを扱ったもので、プロジェクトは再現されていません。生成ライターはすでにフレーズを閉じており、変更していません。テストは、直接作成した連続ノート、フレーズ休止のない分離ノート、既存の生成フレーズ終端、サステイン付きの記譜上の空白を区別します。

<a id="diagnose-before-editing"></a>
## 編集前に診断する

安定したID、元ノートインデックス、リビジョンのために `inspect_project` と `read_notes` を読みます。トラック名から推測せず、前景の役割を確認してください。

```json
{
  "operation": {
    "kind": "inspect_breathing",
    "track": 2,
    "role": "lead",
    "start_tick": 0,
    "end_tick": 30720,
    "min_rest_ticks": 480,
    "phrase_ends": [15360, 30720]
  }
}
```

結果は重なる区間を統合してから、作成ノートと演奏ノートの占有、連続ラン、`longest_without_phrase_rest` を測定します。後者は `min_rest_ticks` より短いアーティキュレーション空白をまたぎます。均一に分離したノートだけではフレーズ呼吸を作りません。長さはティック、4分音符単位、全テンポマップを通じた秒で示します。フレーズ終端には直前の空間を報告します。範囲境界の空白を含め、すべての位置は絶対ティックです。

`role:"texture"` はリード固有の提案を除き同じ測定を行います。拍子、テンポ、スタイル、セクション、歌詞に合わせてしきい値とフレーズ終端を選びます。普遍的な無音量や4小節ごとの必須休止はありません。明示したリード終端の空間不足は提案であり、芸術的失敗ではありません。

クリップ結合と範囲内のシード付きループは演奏パフォーマーを使います。ミュートされたクリップとトラックはノート占有に寄与しません。1リクエスト128拍、交差クリップ32、クリップあたり作成ノート2,048、演奏インスタンス4,096、ループ128回、演奏段階32、表現あたり区間8,192が上限です。未対応または過大な処理は `complete:false` となり、呼吸提案を抑制します。部分的な数値は検証済み結果ではありません。空白詳細は最大64件で、全件数と切り詰めフラグも返します。大きなレポートには `read_report` ページを使います。

`audibility` はサステイン情報とエフェクト／センド経路を別に示します。これらは原因候補であり、可聴テールの証明ではありません。楽器のリリース、ペダル状態、他トラック、ソロ／ルーティング、バスエフェクトはノート占有の外です。前景ステムと全ミックスを比較してください。記譜上の休止は可聴無音の証明ではありません。

<a id="prepare-an-explicit-rest"></a>
## 明示的な休止を準備する

現在のリビジョンで `arrangement` 検証を使います。各編集には短い目的を1つだけ含め、UTF-8で最大256バイトにします（日本語の目的は短い節にしてください）。

```json
{
  "operation": {
    "kind": "validate",
    "expected_revision": "COPY_FROM_CURRENT_INSPECTION",
    "changes": [{
      "purpose": "Let the lead release before the next phrase",
      "edit": {
        "kind": "breath",
        "clips": [12],
        "rests": [{"start_tick": 14880, "end_tick": 15360}],
        "min_note_ticks": 120,
        "protected_notes": [{"clip": 12, "index": 0}],
        "omit_notes": []
      }
    }]
  }
}
```

休止の開始をまたぐノートはそこで短くし、少なくとも `min_note_ticks` を残します。休止内のアタックは、正確な元の `{clip,index}` が `omit_notes` にある場合を除き拒否します。省略は明示したノートだけを削除し、残りのピッチ、アタック、ベロシティ、順序は変えません。検証は変更した全元インデックスの前後の長さ、または省略ノート全体をプレビューします。省略は要求休止内に収まる必要があります。保護インデックス、歌唱データ／装飾、同音高の連続（クリップをまたぐ可能性のあるタイ）も拒否されます。ノートを分割したり一律にゲートしたりはしません。

<a id="held-arrivals-and-instrument-tails"></a>
### 保持音の到達と楽器の余韻

`inspect_breathing.ending_guidance` は、持続する管／弦、打撃／撥弦楽器、パッチ依存のシンセを区別します。登録済みネイティブ楽器では `envelope_controls` が実装から攻撃・減衰・サステイン・リリースと保存上書きを読み、オートメーションの有無も示します。リリース値は音響無音の測定値ではありません。オートメーションを検査し、次のエントリーを通じてステムとミックスをレンダーします。ホストおよびサンプルのエンベロープはパッチ依存で、ネイティブ既定値を推測しません。

新しくアタックした終端音を短くしてクリップする場合、`breath` 編集で既存の到達音を指定できます。

```json
"landings": [{
  "note": {"clip": 2, "index": 15},
  "start_tick": 13440,
  "replace_notes": [14]
}]
```

全インデックスは元の `read_notes` 応答を参照します。到達音はピッチとベロシティを保ち、絶対 `start_tick` に移動して要求休止まで保持します。接近ノートは新しいアタックから元のアタックまでを空白や重複なく正確に覆い、別の作成声を含めてはいけません。保護・歌唱・タイノートは、置換される接近ノートも含めて拒否されます。到達は最大16個で、独立クリップを必要とします。ループパスには独立コピーを使います。`landings` がなければ従来のリリースのみの契約は変わりません。曲線、演奏、レシピは保持され、提案全体がUndo 1回になります。

到達音が落ち着く時間と楽器のテールを次のエントリーまで確保します。ピッチは局所ハーモニーとモチーフに合わせ、最後の記譜ノートが必ず解決音になるとは限りません。ピアノ／ギターの共鳴は汎用フェードで強制せず自然に減衰させます。持続する管・弦・シンセでは、明示的に範囲を限定した表現またはネイティブパラメーターのオートメーションで終端を整えられます。外側の曲線を保持し、ゲイン復元時にテールが再出現しないか確認します。ゲインを下げるだけでは保持中の声を解放しません。フレーズ設計の代わりにグローバルな楽器既定値を変更しないでください。

前景楽器トラック上でミュートされていないクリップを1〜16個、順序付きで重ならない休止窓を1〜16個選びます。選択範囲は128拍に制限されます。歌唱／ドラムトラックは保護されます。繰り返しクリップでは、聴こえるすべてのパスで同じ相対休止を覆う明示的な窓が必要です。要求していないパスに影響する提案は拒否されます。反復ごとに異なるフレーズには独立クリップを使います。既存のレシピ、曲線、変換、クリップ長、ハーモニー、タイムラインは保持されます。

候補は対象トラック全体の実際の演奏ノートと照合します。別クリップや演奏段階が休止を埋めていれば拒否されます。休止中の既知または未知のサステインも拒否されます。さらにノートを変更する前にCC64を明示的に読み戻し／リセットしてください。CC64を無視する楽器はレーンがあってもペダル対応になりません。リバーブとリリースは音声レビュー条件です。

準備した `note_changes` を確認し、元のリビジョンで `plan_id` を適用します。既存の契約が古いリビジョン、キャンセル、正確な再試行、Undo/Redoを扱います。検証失敗ではスコアや履歴を変更しません。空の休止に他の編集がなければUndoを増やしません。ノートを独立に読み戻し、同じフレーズを診断して同じ小節をレンダー比較します。局所修復は2回までに制限します。

<a id="verification"></a>
## 検証

セッションテストは占有の統合、アーティキュレーションとフレーズ空間、テンポ変更、クリップ／ループ結合、ミュート、明示的役割、処理上限、保護・歌唱ノート、タイ、ペダル、重複クリップ、正確な保持、Undo再試行を確認します。実PCMテストは修復休止の前景エネルギー低下を測り、持続テクスチャが全ミックスを保つことも確認します。既存の生成フレーズ終端は再生成せず検査します。

無視されるウィンドウテスト `installed_agent_repairs_lead_breathing_and_preserves_generated_phrases` は、[agent tool validation](agent-tool-validation.ja.md) の `AURIS_TOOL_SURFACE_EVAL` 設定を使います。実エージェントが手動・生成リードと意図的テクスチャを診断し、1提案で2つのリード終端だけを修復し、結果を独立に読み戻して前後の前景ステムとミックスを数値検査します。正確な状態、レシピ保持、Undo/Redoを確認します。数値検証だけでは自然なフレーズや音楽的改善を証明しません。音声批評モデルが利用できる場合は別の聴取比較を行います。

2026-10-23の[検証記録](../tools/eval/references/agent-breathing-2026-10-23.json)には実エージェントと音声モデルの結果があります。エージェントは2つの終端を正確に修復し、生成参照とテクスチャを保持しました。批評モデルはステムとミックスを比較しましたが、新しい終端を唐突でスタッカートと判断し、意図には不確実でした。ノートとPCMの空間は増えましたが自然なフレーズは確立されませんでした。これは音楽的合格ではありません。保持した到達や範囲を限定したダイナミックテーパーを検討し、空間低下を品質スコアとせず再比較してください。

<a id="follow-up-ending-comparison"></a>
### フォローアップの終端比較

[保持到達の比較記録](../tools/eval/references/phrase-ending-2026-10-23.json)には、フォローアップの試行、実際のネイティブエンベロープ設定、WAVハッシュ、PCM測定、すべての批評応答を保持します。6秒の抜粋には次のエントリーが含まれ、以前の短縮のみの修復と新しい明示的な終端を比較します。連続した元の音は別の対照として保持します。これらは合成テストフレーズであり、曲全体についての主張ではありません。

最終比較では同じ到達音をより長く保持し、楽器ごとのリリース空間を確保します。持続する chiptune と clarinet には範囲を限定したトラックゲインのテーパーを適用し、ネイティブリリース後の次のエントリーで元のゲインに戻します。ピアノはゲインフェードなしで自然に減衰させます。バイオリンは1.5秒のリリース設定を保ちます。このフィクスチャでは、ノートオフから約0.7秒後にテールが -100 dBFS を下回るため、最終区間は均一な4分の1秒ではなく0.75秒です。控えめな1.75秒の中間区間も記録に残しますが、静かな空間が過剰でした。楽器や作曲家のデフォルトは変更しません。同じ持続する背景を使う前景ステムとミックスを、共通ゲイン、正規化なし、リミッターなしでレンダーします。

数値アサーションは、シンセ／管のリリース前のイージング、次のエントリー直前のバイオリンテール低下、4つすべてで次のアタックが保たれることを確認します。これらは音響動作を示すもので、知覚される自然さではありません。批評モデルには最終ペア8組を送信しましたが、繰り返し音声を要求するか音楽を識別できませんでした。短い焦点の抜粋とモノラル／16-bit対照でも信頼できる音楽的判断は確立されませんでした。以前の孤立した回答の1つは短縮のみのステムを好みましたが、そのミックス比較は失敗しました。モデル品質について好意的な判定は主張しません。比較 WAV は人が試聴できます。

これらの記録を作ったテストは別の批評モデルに音声を送るもので、その批評モデルはすでに廃止しました。記録は、当時の測定結果の証拠として残しています。
