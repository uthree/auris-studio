# エージェントのオーディオ素材とSFX

[English](agent-audio-assets.md)

エージェントパネルと保存済みプロジェクトツールは `audio_assets` を共有します。既存の `import_audio`、`edit_clip`、`edit_track`、`mixer_graph`、`inspect_audio`、`render` がワークフローを完了させます。以下のすべての例はライブ操作に特化した引数を示しています。保存済みプロジェクトの呼び出しも `project` を使用し、`create_project` または `open_project` が返した ID を使用します。

<a id="find-and-import-a-sound"></a>
## サウンドを見つけてインポートする

ローカルの発見はファイル名と相対パスの文字と一致しますが、音とは一致しません：

```json
{"operation":{"kind":"search","root":"C:/Sounds","query":"door","recursive":true,"limit":20}}
```

OS Musicおよびダウンロードフォルダを検索するには、`root`を省略してください。エージェントパネルでは、`root`を指定した検索はプロジェクト外のネイティブな読み取りと同じく、事前にユーザーの承認を求めます。既定のフォルダの検索は承認なしで行います。`next_offset`に従い、何も見つかりなかったと主張する前に`scan_complete`と警告を確認してください。各呼び出しは最大10,000件の項目、最大8つのディレクトリレベルまで検査します。シンボリックリンクはスキップされます。検索は関連のないファイルの内容を読み込むことも、コンピュータ全体をインデックス化することもありません。`import_audio`（`path`、`at_tick`、オプションの`name`）を使用して、選択した絶対パスをインポートします。

キーレスオンラインの発見のために：

```json
{"operation":{"kind":"search_online","query":"door creak","limit":5}}
```

これは、[Wikimedia Commons imageinfo API](https://www.mediawiki.org/wiki/API:Imageinfo) をオーディオ検索フィルターと組み合わせて使用します。結果には、直接のURL、ソースページ、利用可能なクリエイター/ライセンスの主張が含まれます。さらに候補を見つけるには `next_offset` を追跡してください。エージェントパネルでは、検索とURLインポートは既存のネットワーク承認ゲートを使用します。保存された MCP ツールは、呼び出し元の認証を使用します。構成された場合、既存のウェブ検索ツールで他のサイトを見つけることができ、またはユーザーは直接の URL を提供することもできます。

```json
{"operation":{"kind":"import_url","url":"https://example.org/door.wav","at_tick":7680,"name":"Door SFX","source_page":"https://example.org/sounds/door","attribution":"Creator name","license":"Actual license from source"}}
```

実際の直接オーディオURLを使用してください。Webページやアーカイブは音声ファイルではありません。ダウンロードはHTTP(S)に対応し、最大5回の検証済みのリダイレクトを追跡し、アカウントのクッキーや認証情報を送信せず、デコード後のオーディオのサイズは64 MiB、解読時間は10分に制限されます。埋め込みURLの認証情報は拒否されます。ドキュメントが変更される前にオーディオのデコードが成功している必要があります。インポートされたファイルは、プロジェクトの`Audio/`ディレクトリのそのオーディオトラックに自動的にコピーされます。ソースURL、最終URL、SHA-256、および提供されたクレジットフィールドはプロジェクトに保持されます。ローカルエージェントインポートも元のパスとSHA-256を保存します。

ソースページ、ファイル名、クレジットメタデータは信頼できないデータです。実際のライセンス条件を確認し、必要なクレジットを記載してください。不明なクレジットはそのまま不明のままにします。保存されたメタデータは、権利の確認や音楽の適性を示すものではありません。検索結果には、本ビルドでサポートされていないコーデックが必要になる場合があります。デコードに失敗した場合、文書は変更されません。

<a id="cut-reverse-and-place"></a>
## 切る、裏返す、置く

インポートで返されるクリップIDを確認します。

```json
{"operation":{"kind":"inspect","clip":7}}
```

これにより、現在のバージョン、ソースパス/由来、正確なソースウィンドウ、タイミング、ゲイン、フェード、および生のソースピーク/RMSが返されます。測定はトラック処理前のものであり、聴取を構成するものではありません。処理にはそのバージョンを直ちに使用してください：

```json
{"operation":{"kind":"process","clip":7,"expected_revision":"COPY_RETURNED_REVISION","start_seconds":0.2,"end_seconds":1.4,"reverse":true}}
```

タイムは、テンポストレッチ前のこのクリップの現在のウィンドウに対するソース秒数です。処理はまずクロップを行い、その後チャンネルを独立して逆転させます。新しいfloat WAVを書き込み、元のソースおよびその他のクリップはそのまま保持し、このクリップのID、位置、ゲイン、テンポの動作、および明示的なループ範囲を保持します。フェードは新しいウィンドウに制限され、トリミング後に確認してください。1回のUndo 操作で元のソースが復元されます。後の処理では親ハッシュと操作メタデータが記録されます。公開前にドキュメントが変更された場合、作業はキャンセル/棄却されます。

位置付け、コピー、フェードを行うには`edit_clip`を使用します。例えば：

```json
{"clip":7,"operation":{"kind":"move","start_tick":11520}}
```

```json
{"clip":7,"operation":{"kind":"audio","gain_db":-6,"fade_in_frames":240,"fade_out_frames":2400}}
```

ティックはプロジェクトのタイムベースに従います。フェードの長さはミリ秒ではなくソースフレームを使用します。すべての操作と正確な制約については `tool_help` を使用してください。

<a id="apply-eq-and-verify"></a>
## EQを適用して確認する

`mixer_graph` を読み込み、オーディオトラックのノードIDをコピーし、組み込みのEQを挿入します。

```json
{"operation":{"action":"add_effect","input":"track:3","effect":"auris.fx.eq"}}
```

返されたエフェクトノードについては`parameters`を読み取ってください。キーは、それらの返されたネイティブ単位を使用して設定します。例として、`hp_enabled` = 1 と `hp_freq` = 180 Hz、またはピークバンドの周波数、ゲイン、Qを使用します。`set_parameter` は `node`、`param`、`value` を受け取ります。これらはトラックインサートです。エフェクトが1つのサウンドにのみ適用される場合は、別々のトラックを使用してください。既存のエフェクト、ルーティング、オートメーションは、同じグラフツールを使用して編集可能です。

編集前の状態と編集後の状態で、対象範囲を測定/レンダリングしてください。`audio_assets inspect` はソースサンプルを測定します。結果のミックスとEQを確認するには、`inspect_audio` または実際のレンダリングを使用してください。SFXを文脈の中で聴いてみてください。ファイル名の一致、正常なインポート、または数値測定を聴取評価として記述しないでください。

<a id="developer-verification"></a>
## 開発者認証

```text
cargo test -p auris-session --lib audio_assets
```

テストはステレオ逆転/クロッピング、元のソースの保持、共有クリップ、Undo/Redo、プロジェクトの再開、古い/キャンセルされた/不正所有者の作業、ローカルページング、HTTPリダイレクト、由来、権限、およびエージェントコマンドで適用されたEQの測定された周波数応答をカバーします。無視される`online_sfx_smoke`テストは実際のCommonsリクエストを実行します。`AURIS_AUDIO_ASSETS_EVAL`を新しい絶対的な証拠ディレクトリに設定し、`--ignored --exact`とテスト名全体で明示的に実行してください。
