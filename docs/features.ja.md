# 機能

[English](features.md)

アプリケーションの動作をパネルごとに説明します。概要は[README](../README.ja.md)に、曲が自動で作られる仕組みは[自動作曲](composition.ja.md)にあります。

<a id="tracks"></a>
## トラック

* **楽器トラック** — タイムライン上のノートをソフトウェア楽器で演奏します。
* **歌声トラック** — 歌声シンセサイザー用に歌詞を持つノートです。[歌声トラック](#singer-tracks)と[歌声バックエンド](singing-backends.ja.md)を参照してください。
* **オーディオトラック** — 読み込んだ音声を、トリム、ゲイン、フェード付きのクリップとして配置します。
* **バス** — 独自のクリップを持たないミキシングポイントです。[バスとセンド](#buses-and-sends)を参照してください。
* すべてのトラックには**色**があり、ヘッダーとクリップに色味を付けます。新しいトラックにはパレットの次の色が割り当てられます。トラックの右クリックメニューには残り7色のスウォッチが表示されます。作成順とドラムかどうかは関係しないためです。

**トラックヘッダーを上下にドラッグ**するとリスト内で移動できます。ポインターの移動に合わせて配置が並び替わり、離したときに線が現れてジャンプする方式ではありません。手に付いてくるもの自体が移動し、ドラッグ全体が1回のUndoになります。移動しないクリックは従来どおり選択になり、ヘッダーのフェーダー、パン、ミュートに着地したクリックはそれぞれの操作を維持します。

移動するのはリストだけです。ドキュメント内の自動化レーン、ルーティング出力、センドなどはすべてトラックをIDで参照するため、聞こえる内容を1つも変えずに、バスをそこへ送るトラックの上へ移動できます。

オーディオトラックのヘッダーまたはレーンの空き部分を右クリックし、**Audio Display → Spectrogram**を選ぶと、時間に沿った周波数成分を表示できます。低周波数は下、高周波数は上で、20 Hzから20 kHzとナイキスト周波数の低い方までを対数目盛りで示します。暗い紫からオレンジ、淡い黄色になるほど入力レベルが高く、範囲は−90～0 dBFSです。表示は各チャンネルの最も強い周波数レベルを組み合わせるため、ステレオの位相キャンセルで音声が隠れません。

入力が表示可能になるとバックグラウンドで解析が始まり、スクロール、トリミング、伸縮、クリップのループ中も画像を再利用します。画像が表すのは元の録音で、クリップゲイン、フェード、トラックエフェクトは再生時に適用されます。長い録音ではピークを保った粗い時間概要を使います。**Waveform**を選ぶと既定の表示に戻ります。表示の選択は現在のウィンドウに適用され、プロジェクトを開くとリセットされます。

<a id="track-grid"></a>
## トラックグリッド

コマンドパレットから**Track grid**を実行すると、すべてのトラックをレスポンシブなグリッドで表示できます。同じコマンドをもう一度実行するとタイムラインに戻ります。物理楽器は実際の機械的な動きを表示し、その他の楽器、オーディオトラック、歌声、バスはそれぞれのフェーダー後のステレオ波形を表示します。名前でトラックを選び、**Mute**と**Solo**ボタンを使うか、右クリックして通常のトラックメニューを開きます。**Freeze**は再生を止めずに表示を固定します。これらの表示設定は保存済みプロジェクトを変更しません。

<a id="dragging-files-in"></a>
## ファイルのドラッグ＆ドロップ

音声ファイルをウィンドウへドロップすると、**新しいオーディオトラック**に追加されます。`.sf2`をドロップするとライブラリの棚に追加され、音色を選べる状態でフォントが開きます。複数をドロップした場合は、ドラッグした順に1つずつ読み込みます。ステータス行には現在読み込んでいるファイルが表示されます。デコードには時間がかかるため、テイクのフォルダーを読み込む間も、何を処理しているか分かるようにしています。

**`.mid`**をドロップすると、テンポや拍子を含めて新しい曲として開きます。[MIDIファイル](#midi-files)を参照してください。

**`.auris`プロジェクト**をドロップすると、**File → Open**と同じように開きます。開いているドキュメントに未保存の変更があれば先に確認し、*Save*を選ぶと保存してからドロップしたプロジェクトを開きます。ただしプロジェクトは**単独で**ドロップしてください。プロジェクトは別のものに入れる素材ではなくドキュメントです。プロジェクトと3つのテイクを含むドロップには、画面上の作業を危険にさらさず解釈できる方法がないため、理由を示す行を表示してドロップ全体を拒否します。

ドロップは**どこに置いたかではなくファイルの種類**で解釈します。ポインターがレーン、ミキサー、ライブラリのどこにあってもウィンドウは受け取るため、狙うターゲットも先に覚える規則もありません。配置場所が決めるのは1点だけです。レーンにドロップした音声は、ドラッグしたクリップと同じようにグリッドへスナップして、その場所から始まります。それ以外の場所にドロップした音声はプレイヘッドから始まります。読み込めるものを持ったドラッグがウィンドウ上にある間は枠が点灯し、フォルダーやPDFなら理解できないことが事前に分かります。

<a id="panels-and-where-you-put-them"></a>
## パネルと配置場所

配置はウィンドウ中央です。それ以外のライブラリ、ピアノロール、ミキサー、インスペクターはパネルで、各パネルは3つのドックのいずれかに置かれます。左の縦列、右の縦列、下部の横帯です。初期配置はDAWの一般的な配置で、ライブラリが左、インスペクターが右、2つのエディターが下部を共有しますが、固定ではありません。

タイトルバーは選択したカラースキームに従い、プロジェクト名、未保存変更の印、再生コントロールを位置とテンポの表示の上に置きます。パネルアイコンは右側にドックごとにまとめて並びます。狭いウィンドウではステータスバーへ移動し、左ドックは左端、下ドック、右ドックの順に反対側へ並びます。アイコンをクリックするとそのパネルを表示し、表示中のアイコンをもう一度クリックするとドックを閉じます。右クリックすると**Dock Left**、**Dock Bottom**、**Dock Right**を選べます。そのため、ミキサーを右列に置きながらロールを下部に残したり、両方のエディターを下部のタブにしたりできます。1つのドックが同時に表示するパネルは1つだけで、240ピクセルの列が2つの半端なパネルになるのを防ぎます。表示していないパネルにもアイコンが残るため、しまったまま見失うことはありません。

各ドックの仕切りをドラッグしてサイズを変更できます。配置を存在できないほど押しつぶすことはありません。パネルを置いた場所は次回起動時にも使われ、全体の配置は`layout.json`に書き込まれます。

<a id="editing"></a>
## 編集

任意のコンポーネントを右クリックするとメニューが開きます。トラックとクリップでは複製、名前変更、削除、ミュートができ、クリップにはプレイヘッド位置での分割とクリップ上でのサイクルが加わります。ピアノロールでは選択ノートの複製、削除、移調、ダイナミクス（pp～ff）を操作でき、エフェクトスロットではバイパス、並べ替え、削除ができます。メニューはポインターだけでなくキーボードからも操作できます。名前変更はプラットフォームの入力ハンドラーを通るため、IMEは他の入力欄と同じようにフィールド内で変換します。

作成と削除はポインター操作で、どのジェスチャーがどちらを行うかは設定です。既定値はLogicと同じで、⌘クリック（WindowsではCtrlクリック）でノートまたはクリップを作成し、⌥クリック（WindowsではAltクリック）でポインターの下にあるものを削除します。どちらにもダブルクリックを使えますが、既定では破壊的な操作を割り当てません。クリップがあるすべてのエディターでダブルクリックはクリップを開き、利用者が慣れたジェスチャーで作業を壊さないためです。ピアノロールや配置の空白をドラッグすると選択矩形を描き、⇧ドラッグは選択済みのものに追加します。複数選択はまとめて移動、複製、削除できます。空の配置を押しても移動しなかった場合はスイープではなく*クリック*になり、その場所へプレイヘッドを移動します。1回のクリックを受け付ける場所はルーラーだけではありません。

**Createは通常のクリックにもできます**。修飾キーを押さずにノートを書きたい場合の設定です。これを選ぶとラバーバンドは⇧ドラッグへ移ります。設定画面にもそのことが表示されます。⇧は他のすべての操作で*選択範囲を拡張*する意味があるため、このジェスチャーはその場で発明されたものではありません。両方の編集面に適用され、空のレーンをクリックするとプレイヘッドを移動する代わりにクリップを作ります。これが通常のクリックに伴うもう一つの動作であり、修飾キーが既定のままになっている理由です。削除を通常のクリックにすることはできず、選択肢にもありません。通常のクリックで作成したものは見えて元に戻せますが、通常のクリックで削除すると拾おうとしたすべてのノートを消してしまうためです。

配置の上でホイールを回すとトラックを上下に移動します。⇧で曲に沿った横方向へ切り替わり、**Ctrlまたは⌥**でポインターを中心に時間軸をズームするため、見ている小節はその場所に留まります。

**ホイールを受け取るバーはありません。**フェーダー、プラグインパラメータ、クリップのダイヤルは、どれもポインターで操作し、スクロールには応答しません。これらはスクロールするパネルの中にあります。以前はトラック列をスクロールすると、ポインターが通過したフェーダーのレベルが黙って変わり、ドラッグを始めたことを示すものも、どのフェーダーが動いたかを示すものもありませんでした。ホイールはスクロール対象のために使います。

**スクロールするパネルにはそのことが表示されます。**ブラウザー、インスペクター、ログ、レーン列、ミキサーのストリップでは、収まらない量があると端にバーが現れ、すべて収まる間は場所を取りません。つまみの長さは表示範囲が全体に占める割合に応じます。つまみをドラッグするとパネルが移動し、トラック上のどこかを押すとそこへジャンプします。チャンネルストリップが40本ある場合、端までドラッグするより便利だからです。

ピアノロールには2つのツールがあり、ヘッダーの帯と、ロールが画面にない状態でキーを使ったときのステータス行に、現在のツールが表示されます。**T**で次のツールを選び、2つのツールではLogicと同じく、2回押すと元へ戻ります。他のキー割り当てと同じく、設定画面で変更できます。ポインターは選択、移動、サイズ変更、作成に使います。ノートの端はハンドルで、そこに来るとポインターが↔に変わります。配置上のクリップ端と同じです。ベロシティツールは1つの操作だけを行います。ノートを上下にドラッグすると強くまたは弱く演奏され、値が横に表示されます。選択範囲はまとめてドラッグされ、形を保ちます。弱い・強い・弱いと書いたフレーズを強く演奏しても、その関係は変わりません。両端を越えて戻ってきた場合も、押し付けられた上限にコード全体を平らにするのではなく、その形を復元します。1回のドラッグが1回のUndoになり、途中でEscapeを押すとノートを戻します。各ノートには同じ値を示すバーもあり、色のグラデーションだけでは96と100の差を示せないからです。

ノートを選択範囲として掃引した後、選択ノートの右端をドラッグすると、長さの差を保ったまま選択全体を同じ量だけサイズ変更できます。各ノートは1ティックで止まり、戻すドラッグで元の差を復元します。サイズ変更中に**Shift**を押すと選択ノートの終端を揃え、**Alt+Shift**（Macでは**Option+Shift**）を押すと同じ長さにします。ベロシティツールで**Alt+Shift**を押すと選択ノートのベロシティを揃えます。これらの修飾キーはドラッグ中にも変更できます。選択範囲のサイズ変更は1回のUndoになり、Escapeでキャンセルします。

新しいピアノロールノートは、クリック、作成、サイズ変更を最後に行ったノートの長さを再利用します。コンテキストメニューから追加したノートも同じです。ノートをまだ操作していなければ、現在のグリッド分割が長さを決めます。ポインターの小さな揺れでは長さを保ち、意図的なドラッグで新しい長さを設定します。Escapeでサイズ変更をキャンセルすると、次のノートにも前の長さが使われます。

ピアノロールヘッダーの**Length Snap**は、現在の編集グリッドへの長さのスナップを制御し、一般設定でも同じ値を使います。初期状態では有効です。作成修飾キーを押して描いてもスナップします。既存ノートのサイズ変更中にCtrl（MacではCommand）を押すと微調整できます。スナップしない描画には、グリッドをFreeにするかLength Snapを無効にします。

選択したノートは塗りの輝度が反転し、対照的な輪郭が付きます。ベロシティバーと歌詞は読み取れるままです。選択範囲を移動すると、トラックの楽器で音高をまとめて試聴し、音高の変更に合わせて更新します。横移動では同じ音高を繰り返し鳴らしません。ポインターを離すかEscapeを押すとプレビューが止まります。

ピアノロールのポインターツールで**Altドラッグ**（Macでは**Optionドラッグ**）すると、選択ノートを複製してコピーを移動します。選択していないノートをつかんだ場合は、そのノートだけをコピーします。コピーは歌詞、ベロシティ、演奏設定を保持し、新しい選択範囲になります。ドラッグのしきい値を越えるとコピーが始まり、その後Alt/Optionを離しても同じコピー操作が続きます。Undoでコピーを削除し、Escapeでキャンセルして前の選択を復元します。Alt/Optionクリックを削除に設定している場合、ドラッグせずに離すまで削除しません。右端でAlt+Shiftを押すと、ノートの長さを引き続き揃えます。

ノートの描画、移動、コピー、サイズ変更中は、横の表示に、つかんだノートの音高、選択数、曲位置、長さが示されます。値はスナップ後の記述ノートに従います。位置は`bar:beat:tick`で、小節と拍は1から始まります。長さは同じ単位を0から使い、ノート開始時の拍子を基準にします。表示はピアノロールの見える範囲内で端に近い場所へ移動し、ジェスチャーが終わるかキャンセルされると消えます。

Logicではツール上だけでなく⌃⌥ドラッグでもこのジェスチャーを使えますが、その半分は別のプラットフォームへ持ち越せません。macOSではウィンドウが受け取る前に⌃クリックが右クリックになり、途中で⌃が外されます。そのためドラッグではなくコンテキストメニューの要求として届くからです。

**Cut、copy、paste**は⌘X、⌘C、⌘V（WindowsではCtrl+X、Ctrl+C、Ctrl+V）で、ピアノロールではノート、配置ではクリップを対象にします。キーボードが置かれている場所に応じてスコープされ、⌘Aや⌘Dと同じ3つのキーを使います。Editメニューには両方が対になって表示され、どちらを実行したか確認できます。Pasteはプレイヘッド位置に配置されます。空のレーンを右クリックすると代わりに*Paste Here*が表示され、貼り付け位置を持たせられます。

クリップボードにあるのは場所ではなく*形*です。ノートは間隔を保って戻り、4トラックからコピーしたクリップのブロックは、指定した場所から4本の連続トラックに配置されます。元のトラックの名前変更、並べ替え、削除後も同じです。配置されたものが新しい選択になるため、探さずにそのままドラッグできます。貼り付け先がない場合（オーディオトラックへMIDIクリップを貼る場合や、ブロックの下段がトラックリストの下からはみ出す場合）は、可能な部分だけ配置してそのことを知らせます。これはAuris Studio独自のクリップボードで、システムのものではありません。ここから別のアプリケーションへ渡ることも、別のアプリケーションでコピーしたものがここへ入ることもありません。

配置するものはすべてグリッドボタンの分割にスナップします。分割は*free*（ドキュメントで扱える最小の1ティック）まで切り替えられます。⌘（WindowsではCtrl）を押している間はドラッグ中のスナップが一時停止し、拍から外して配置できます。フェーダーやノブをダブルクリックすると既定値に戻ります。音量は0 dB、パンは中央です。

**Quantise**は、演奏済みのノートを後から同じグリッドへ揃えます。ノートが持つ2つの数値は別々に誤るため、3種類あります。*Quantise Starts*（**Q**）はノートの開始位置を整え、*Quantise Lengths*は保持時間を整え、*Quantise Both*は両方を行います。拍より少し前に演奏したパートでは、長さだけを均して演奏感を残す場合があります。片方だけが必要なテイクに両方を適用すると、演奏者が演奏したように聞こえなくなります。3つともロールの右クリックメニューとEditメニューにあり、選択ノートに適用され、グリッドボタンに表示されている分割へスナップします。見えない分割へ量子化すると説明のないジャンプになるためです。長さがゼロに丸められることはありません。16分音符グリッドでは、切り詰められた装飾音符も消えず16分音符になります。ステータス行には実際に移動したノート数が表示され、残りがどれだけ揃っていたか分かります。

クリップの両端はハンドルで、押す前にポインターが↔へ変わるため操作可能だと分かります。ドラッグするとクリップの長さが変わり、その意味はクリップの種類によって異なります。**audio**クリップはトリミングされ、素材がある範囲で止まります。先端はテイクをタイムライン上で滑らせるのではなく、ソース内のクリップの窓を移動するため、戻すドラッグで残りを繰り返すのではなく隠れていた部分が現れます。誰かが**演奏した**クリップはノートを正確な位置に保ちます。**自動作曲された**クリップはノートではなくレシピを持つため、現在の長さに合わせて再作成されます。伸ばすと増えた小節を埋め、縮めるとその位置で止まります。レシピがクリップの内容を示し続けるため失われるものはなく、再び伸ばせば素材が書き戻されます。

**クリップはループできます。**クリップの*名前バー*右端には2つ目のハンドルがあり、使うまではサイズ変更ハンドルの上に重なっています。外側へドラッグすると、細い線で区切られた薄い反復として、引いた長さだけクリップが繰り返されます。クリップ自身の終端まで戻すと停止します。クリップ本体は変わらず、何回聞いても1ブロック、1つの名前、1つの選択です。名前バー下の端はサイズ変更に使えるため、フレーズの長さと再生回数は別々に変更できます。右クリックメニュー、Editメニュー、**L**の*Loop Clip*でも同じ操作ができ、オンにするとレーン上の次のクリップまで伸び、前に何もなければ長さを2倍にします。

どちらの種類のクリップもループします。最後の反復は全通過に丸めずループ終端で切れるため、小節の途中で止まることがあります。オーディオクリップではフェードがクリップ自身の両端に残り、反復間のつなぎは平坦です。各通過の末尾でフェードアウトすると1小節ごとに音量が揺れるためです。ループしたクリップを分割すると両方とも反復を止めます。存在しなくなったブロックの反復だからです。複製するとコピーは反復の上ではなく、その後ろに置かれます。書き出したファイル、WAV、MIDIには反復が含まれ、再生だけでループが止まることはありません。

オーディオクリップはハンドルでフェードイン／アウトします。2つのハンドルは名前バーのすぐ下の帯にあり、両端に1つずつあります。ドラッグすると波形上に暗いくさびとして傾斜が描かれます。フェードは意図的にグリッドを無視します。波形を聞きながら形を決めるもので、息が終わる位置とグリッド位置は関係しないためです。クリップ自身のゲインは右クリックメニューからデシベルで設定し、トラックのエフェクトより前に適用されます。0 dB以外では名前の横に数値が表示され、同じメニューの*Remove Fades*で両方のフェードを外します。

**2つのテイクをクロスフェードするには**、同じトラック上で一方をもう一方へドラッグして重ねます。離した時点でつなぎが作られ、先のクリップは重なり全体でフェードアウトし、後のクリップは同じ範囲でフェードインします。クリップがそこへ移動したことで存在するフェードなので、移動と同じUndoに含まれます。空間を空けるために他のものは動きません。つなぎの長さはドラッグした重なりの長さであり、クロスフェードを長くするには重なりを長くします。

**描いたフェードが上書きされることはありません。**ドロップでつなぎが作られるのは、向かい合う2つの端のどちらにも既存のフェードがない場合だけです。どちらかにフェードがある場合は、いずれかのクリップの右クリックメニューにある*Crossfade*を選んで明示的に実行します。

つなぎには端のフェードと異なる形を使います。**無音へのフェード／無音からのフェード**は振幅の直線で、見た目どおりの形です。**クロスフェード**は正弦の4分の1と余弦の4分の1を組み合わせます。異なる演奏の2クリップで直線ランプを交差させると、中央の合計が両端より約3 dB低くなり、つなぎに穴ができるからです。形は聞こえ方どおりに描かれ、クロスフェードのランプは曲がり、端のフェードは直線です。

どちらの形も手動で選べます。クリップメニューの*Fade-In Shape*と*Fade-Out Shape*は、その端にフェードがある場合に表示されます。別の方法で作ったつなぎ、つまりハンドルで隣のクリップへ伸ばしたフェードや、クリップをトリミングして隣に合わせた場合に使います。

トランスポートバー中央には位置、テンポ、拍子の3つの表示があります。最初の2つは入力可能で、どちらもダブルクリックして直接数値を入力できます。ホイールは感覚的にテンポを探すため、ドラッグは微調整のために使えますが、120から174へ、または1小節から97小節へ移動する方法にはなりません。位置には`bar.beat.hundredth`を必要なだけ入力でき、`97`は97小節の先頭、`97.3`はその3拍目です。3つともコマンドパレットにあるため、マウスは必要ありません。

テンポはタイムラインに沿って変更できます。表示にはプレイヘッドがいる区間のテンポが示され、編集もできます。別の場所の変更はルーラーの右クリックメニュー（*Tempo from Here…*）から書き込み、拍に配置され、ルーラー下端に数値が表示されます。同じメニューで、ポインター下にある変更を削除できます。タイムライン開始時の曲のテンポは常に存在し、キーと同じく削除できません。

<a id="singer-tracks"></a>
## 歌声トラック

歌声トラックは通常のノートクリップを保持し、ピアノロールの機能をそのまま使える。ただし各ノートには、歌詞と、IPAで記した歌唱音素を持たせられる。声を選ぶまでは、内蔵の **Vocal** プレビュー楽器（開いた母音を1つ歌うフォルマントフィルター）で再生するため、歌詞を書きながらメロディーを確認できる。

声は楽器と同じ**ライブラリー棚**にある。ブラウザーのVoicesには、バイナリの横、設定ディレクトリ内、または *声フォルダを追加…* で登録したフォルダの `Voices` フォルダにある声を表示する（検索先は `AURIS_VOICES` で上書きできる）。登録フォルダはプラグインフォルダと同じく記憶し、コピーしない。**1回のクリックで選択した歌声トラックに声を設定できる。** 検索欄は名前を検索し、**トラック → 声を選択…** は特殊な場所の単一ファイルを選ぶダイアログとして残る。DiffSinger、LeapSinger、VOICEVOXには棚にバックエンドのバッジが付く。LeapSingerは、エクスポートした音響モデル、NHVSingボコーダー、音素辞書を指定する `.leapsinger.json` から登録する。[設定とエクスポート手順](singing-backends.ja.md#leapsinger-voices)に対応する変種と話者の選択を記載している。設定のVoice Setupボタンは、DiffSingerの `dsconfig.yaml` を作成し、LeapSingerのモデルパスとフレームグリッドを設定・検査し、VOICEVOX Engineを起動・確認してURLと歌唱スタイルIDを保存する。LeapSingerの登録では投影された話者埋め込みを保持し、ワーカースレッドでモデル契約を検証し、設定ファイルを手で編集せずに声ライブラリーを更新する。

複数コーパスで学習した声は、ソースごとに1人の**話者**を持つ。**トラック → 次の話者**で一覧を巡回し、ステータス行に現在の話者と一覧内の位置を表示する。単一話者の声はその旨を表示して変わらない。選択はトラックに属し、ドキュメントとともに保存する。テイクはシードと同じく話者によって固定される。いずれの場合もトラックは声エントリを参照し、声はその場所に置いたまま、以後は実際に歌う。レンダーは **テイク**であり、`Audio/` 内の通常のオーディオファイルとして再生、エクスポート、再オープンできる。DiffSingerとLeapSingerは内部でノイズを生成するため、同じシードでも波形が異なることがある。保存された音声はどのマシンでも演奏を保持する。**ウィンドウはスコアに合わせてテイクを自動更新する。** 編集が落ち着いてから短時間でバックグラウンド再レンダーを行い、処理中はヘッダーのバッジが *… ♪ voice* になる。レンダー中に編集が入ると古い作業を破棄し、次に静かになった時点でやり直す。**トラック → 歌う**は明示的な要求として残り、エクスポートオーバーレイの進捗と停止ボタンを表示し、別のシードによる別テイクを作る。テキストを黙って別のものへ書き換えることはない。編集から再レンダーまでの間は元のテイクを再生し、ノートの背後に *! ♪ voice* バッジを表示する。

試聴も歌声で行う。声を選んだ後、ノートをクリックまたはドラッグすると、そのノート固有の音節をつかんだ音高で歌い、バックグラウンドでレンダーして準備でき次第再生する。レンダーはキャッシュするため、すでに通過した音高をドラッグする場合は即時に聞こえる。声のないトラックは以前と同じフォルマント楽器でプレビューする。

歌声クリップを開くと、ピアノロールはノート上に**歌唱音高カーブ**を描く。モデルへ渡す輪郭（音高、ベンドによる半音未満の変化、母音の音高に乗る子音、隣接ノート間を移動する音高、休符による線の空白）を表示し、描いたポルタメントやビブラートがそのまま確認できる。**音素分割**も同じフレームから描く。ノート内の各切れ目に薄い区切り線を置き、フレーム開始位置のIPA記号をノート上に表示するため、子音にかかるミリ秒が画面上でも同じになる。遠くまでズームアウトすると記号は退き、区切り線は残る。

計算場所は **設定 → 一般 → 歌声合成**で選ぶ。デフォルトの *Auto* は、ランタイムが提供する場合にプラットフォームのGPUプロバイダー（WindowsではDirectML、macOSではCore ML）を使い、それ以外や途中でGPUがモデルの形状を拒否した場合はCPUで完了する。*GPU* はGPUを強制し、拒否をエラーにする。*CPU* はGPUを使わない。設定は次のレンダーから有効になる。

区切りは自分で動かせる。**区切り線をドラッグ**すると左側の音素を指定した長さに固定し、その情報を音素とともにノートへ保存して歌詞と移動する。固定していない音素は固定点の周囲に配置し、最後の音節音素がノートの残りを吸収する。固定点の合計がノートを超える場合は比例して詰め、すべての音素を鳴らす。歌詞を打ち直すと存在しなくなった音素に属する固定点も引き継ぐ。固定点がある間はノートの右クリックメニューに **音素タイミングをリセット** が現れ、1回のドラッグが1回のUndoになる。編集後は他の変更と同様にテイクを再レンダーする。

歌声ノートには**ピッチ装飾**も付けられる。下から入る **しゃくり**、末尾で下がる **フォール**、定着後に揺れる **ビブラート**である。右クリックメニューの初期値は、しゃくりが約半音を0.1秒、ビブラートが約6 Hzで半音の3分の1、少し遅れてフェードインする設定である。同じ項目で削除できる。描いたピッチカーブ上には小さな四角い**ハンドル**が現れ、しゃくりとフォールはジェスチャーの角で水平ドラッグが長さ、垂直ドラッグが深さになる。ビブラートは最初の揺れの頂点に乗り、開始と深さを同じ方法で動かす。しゃくりとフォールはノートの半分を超えないため互いに衝突しない。装飾は歌詞と隣接してノートに保存され、音素ではなく音高なので歌詞を打ち直しても残る。1回のドラッグが1回のUndoで、画面のカーブはモデルへ渡す輪郭そのものであり、編集後にテイクを再レンダーする。装飾で表せないノート間のスライドやテンプレート外の動きはベンドカーブで描き、両者を合算する。

**ノートをダブルクリック**して単語を入力する。**Returnで確定して次のノートへ進む**ため、マウスに触れず歌詞を順に入力できる。空欄で単語を削除する。右クリックメニューには **歌詞を編集…**、**音素を編集…**（空白区切りのIPA、歌詞の綴りを変えず読みを手修正）、**歌詞を書く…**（選択ノートへ1モーラ1ノートでフレーズを配置）がある。たとえば、こんにちはは5ノートでこ・ん・に・ち・はと読む。漢字の語は最初のノートに置き、残りには `+` を付ける。

**かなは追加インストール不要**で、内蔵表が直接読む。**漢字**は日本語辞書を使う。リリースには `naist-jdic`（jpreprocessのビルド、BSD-3-Clause）が同梱され、バイナリ横の `Dictionary` ディレクトリ（macOSではバンドル内）からSoundFontと同じように見つかる。`tools/fetch-dictionary.sh` 後のチェックアウトからも検出する。設定（*設定 → 一般 → 日本語辞書*）は自分のフォルダへ差し替える**上書き**である。*クリア*で同梱辞書へ戻り、`AURIS_DICTIONARY` は `AURIS_SOUNDFONTS` と同じように検索を上書きする。コマンドラインの `auris dictionary` は現在使っている辞書を表示する。

**ファイル → 歌声フレームをエクスポート…**は、声モデルが消費する1フレームあたりの音素ID、Hzの音高、エネルギーをJSONへ書き出す。サンプル間隔はトラックのフレームホップ（変更しなければ10 ms）。音高はノート、ベンド、装飾の合計で、エネルギーはベロシティをエンベロープとエクスプレッションペダル（コントローラー11）で形作った値である。プレビュー楽器も同じ値に従い、聞こえる音とモデルへの入力を一致させる。

<a id="lyrics-in-a-composed-song"></a>
### 作曲した曲の歌詞

作曲した歌声にも**規則で装飾**を付ける。各フレーズの最初のノートはしゃくりで入り、0.5秒を超えて保持するノートには冒頭を待ってフェードインするビブラートを付け、最後のノートはフォールで終える。これらはピアノロールで手動設定するものと同じで、ピッチカーブ上に見え、個別に調整・削除できる。規則は出発点であり、最終判断ではない。

アクセントは歌詞と同じ日本語辞書から得る。リリースに同梱されるため通常はそのまま使える。辞書を取得していないチェックアウトでは、かな歌詞もアクセントなしのメロディーで作曲できる。辞書が「歌詞を添えた曲」を「歌詞が形作った曲」に変える。同じ歌詞とシードなら同じ曲を作り、生成物はノート、コード、レシピを含む通常の編集可能な素材として1回のUndoで戻せる。

<a id="midi-files"></a>
## MIDIファイル

**ファイル → MIDIファイルをインポート…**、またはウィンドウへ `.mid` をドロップすると、**新しい曲**として読み込む。テンポマップ、拍子、各パートのトラック、そしてファイルが指定した位置のノートを読み込む。開いている曲にトラックを追加せず新しいドキュメントにするのは、MIDIファイルが固有のクロックを持つためである。別の速さで動く曲へノートを入れると、ノート自体は正しくても長さが合わず、画面には理由を示すものがない。未保存の作業は **開く** とまったく同じように先に確認する。

**チャンネル10**で演奏されたパートにはノイズドラム楽器を割り当てる。素のMIDIファイルがトラックの用途について伝える情報はこれだけであり、General MIDIのドラムパートをリードシンセで鳴らす状態は想定しない。

**ファイル → MIDIファイルをエクスポート…** は逆方向に、アプリケーション固有の解像度（四分音符あたり960ティックで、SMFヘッダーにも保持される）で書き出す。曲を往復させてもすべてのノートが同じ位置になる。正確に残らないのはテンポだけである。MIDIファイルは四分音符あたりの整数マイクロ秒を保存するため、144 bpmは416 667として出力され、143.999 88として戻る。差は1分あたり千分の1拍で、96と120は割り切れるため正確に戻る。

**ピッチベンドとモジュレーションは双方向に移動する。** どちらのカーブもクリップ自体が保持する。フレーズに属するためオートメーションレーンではなくクリップに保存し、4小節後へ移動しても一緒に移動する。**表示 → ピッチベンド**（`⌘⌥B`、WindowsではCtrl+Alt+B）と **表示 → モジュレーション**（`⌘⌥W`、WindowsではCtrl+Alt+W）でピアノロール下に各ストリップを表示する。空のストリップを押すと、これからドラッグする点を書き込み、カーブの配置と形作りを1つのジェスチャーで行える。⌥クリックで点を削除し、右クリックでクリップ全体を直線に戻す。ノートと同じタイムラインに広がるため、カーブが形作るノートを直上で確認できる。

両方で同じジェスチャーと描画器を使い、違いは2点だけである。ベンドは中央を通る線を基準に上下へ動き、ホイールは移動範囲の床から上へ動く。ホイールの下には移動範囲がないためである。

どちらもファイル上では完全に正確ではないが、理由は逆である。ベンドは受信機が想定する範囲を14ビットで表すため、半音は約50分の1セントに量子化される。ホイールはコントローラー1の7ビットで、線が持つ解像度はそれだけである。このファイルを読む受信機は、他のファイルを読む場合とまったく同じ音を聞く。

ゼロで終わらないカーブは、**クリップ終了前に解放する**。どちらも楽器が別の指示まで保持するチャンネル状態である。2半音高い状態でクリップを終えると後続のすべてが音痴になり、ホイールを上げたまま終えると揺れが残る。

`.mid` がどちらの方向にも保存できないものは、オーディオトラック、ミュートとソロを含むすべてのミキサー設定、各トラックが演奏する楽器、オートメーションである。MIDIファイルはノートとクロックである。

ビートではなく **SMPTEフレーム**で数えるファイルは、推測せず拒否する。ビートがないため小節もなく、音楽的なタイムラインへ置くにはファイルに代わってテンポを選び、ファイルが指定したように記録することになる。

<a id="automation"></a>
## オートメーション

トラックヘッダーを右クリックして **音量を自動化** または **パンを自動化** を選ぶと、クリップと同じタイムライン上にパラメーターのカーブを示すレーンが開く。もう一方を選ぶと描画内容が入れ替わり、同じものをもう一度選ぶと閉じる。

空のレーンを押すと点を書き込み、そのままドラッグを開始するため、値の配置と形作りは1つのジェスチャーになる。点をドラッグするとタイムライン方向とパラメーター範囲の上下を同時に動き、クリップと同じくグリッドへ吸着する。プラットフォームのコマンド修飾キーを押している間は吸着しない。削除ジェスチャーで点を取り除き、ドラッグは1回のUndoになる。

**レーンのないパラメーターはまったく自動化されない。** フェーダーやノブの値を保持し、点が存在して初めてレーンが制御する。これによりミックスを1つの操作部ずつ自動化できる。最後の点を削除するか **オートメーションをクリア** を選ぶと、パラメーターは保存された値へ戻る。

レーンは書き込まれた範囲の外では最も近い値を平らに保持する。これはその範囲についてだけ値を主張し、曲の他の部分については主張しないという意味である。したがって40小節に1点置けば曲全体のレベルを設定し、40〜44小節に書いたフェードでは40小節より前がフェード開始時の値になる。

再生とエクスポートは同じ経路を通るので、聞こえるものが書き出される。レーンはサンプルごとではなく処理ブロックごとに読む。フェーダーのゲインはミキサーが与えられたブロック全体で補間する目標であり、これは近似ではない。プラグインパラメーターにもそれより細かい置き場所はない。シークやループではプレイヘッド下の値へ到着し、そこへ滑っていかない。ジャンプしたプレイヘッドは動いたフェーダーではない。

現在レーンが提供するのは音量とパンである。ドキュメント、エンジン、下位のコマンドはプラグインのすべてのパラメーターをすでに扱っている（[`ParamTarget`](https://docs.rs/auris-core)）。したがってメニューを広げるのはメニューの変更だけである。

<a id="buses-and-sends"></a>
## バスとセンド

アレンジメントのヘッダーにある **バス**、またはトラックメニューの **新しいバス** はミキシングポイントを追加する。クリップを持たず、そこへルーティングされた素材を受け取るトラックである。トラックなのでフェーダー、パン、ミュート、エフェクトチェーン、オートメーションレーンを持つ。

ミキサーの各ストリップには送り先が表示される。名前をクリックするとマスターとすべてのバスが候補になり、横の **+** で **センド**を追加する。センドはトラック自身の出力先へ送るのと*同時に*、固有のレベルでバスへ送るコピーである。6トラックを1つのリバーブへ送れば6センドであり、ドラムキット全体にかかる1つのフェーダーは6出力である。センド行のスライダーは通常のミキサー操作と同じで、ドラッグ、ダブルクリックでリセット、オートメーションができる。右クリックするとフェーダー前にタップを移動する（リバーブはフェーダーに追従させたいが、ヘッドホンミックスはそうでない）か、センドを削除する。

ソロはルーティングの両方向へ伝わる。ドラムトラックをソロにすると、その音が他へ行かないためドラムバスも開く。ドラム**バス**をソロにすると、バス自身の音がないためドラムトラックも開く。ソロにしたものを通る経路上にあるトラックだけが正確に聞こえる。

トラックからエフェクトへキー信号を送るのもルートであり、ここでは1つとして数える。ベースのコンプレッサーがキックを聞く場合、キックを先にミックスする必要がある。用途は **内蔵エフェクト** を参照する。

信号を自分自身へ戻すルートは、ミキサーでも選択欄でも拒否する。宛先一覧には合法なものだけが入る。何らかの方法でループを含むプロジェクトファイル（この画面からは作れない）は拒否せず、ログに1行を書いて開くときに修復する。

プラグイン遅延補償はトラック一覧ではなくルーティングに従う。バスのリミッターは通過しないトラックを遅らせ、ミックスを同期させる。トラックがマスターへドライで送りながら同じバスへ送る場合も、各コピーを個別に遅らせるため、ドライとウェットが同時に到着し、互いにコムフィルターを作らない。

ミキサーのグラフ表示では、ワイヤーまたはラベルにカーソルを置くと、接続の送信元、宛先、現在のピークレベルをdBFSで表示する。並列ワイヤーには個別のツールチップがあり、センドにはIDが含まれる。無音は **−∞ dBFS** と表示する。カードは開いている間更新され、Escapeまたはワイヤーからカーソルを外すと閉じる。

グラフ上で **Ctrl+ホイール**を使うと、カーソルを中心に通常50%〜200%でズームする。ノード、操作部、ポート、ラベルは一緒に拡大縮小する。**−** と **+** ボタンはキャンバス中央を中心にズームし、パーセント表示をクリックすると100%に戻る。修飾キーなしのホイールはグラフをパンする。これらの表示変更はプロジェクトのUndo履歴に入らない。

**グラフに合わせる** は、余白を含めて表示キャンバスにすべてのノード、ワイヤー、ラベルを収める。大きなグラフでは50%未満にズームすることがあり、その縮尺も通常のズーム操作で使える。ノード位置と音声ルーティングは元のままである。

<a id="setting-the-levels-by-listening"></a>
## 聴いてレベルを設定する

**Compose → Balance the Mix** は各トラックを個別にレンダリングして測定し、そのパートが収まるべき位置に来るまでフェーダーを動かします。次にミックス全体をレンダリングし、ストリーミングサービスがラウドネスを正規化する基準である −14 LUFS まで持ち上げます。曲の作曲はこの処理で終わるため、このコマンドは、まだ存在しなかった時点に書かれた曲や、作曲後に楽器が変更された曲に使います。

測定には ITU-R BS.1770 のプログラムラウドネスを使います。これはすべての放送局とストリーミングサービスが使うものです。ピークや RMS ではありません。ピークは一つのサンプルにすぎず、残りの音については何も分かりません。RMS は 40 Hz と、耳が 20 デシベル敏感な 3 kHz を同じ重みで扱います。どちらでバランスを取っても、毎回同じ方向に結果を誤ります。ピーキーなキックは小さすぎ、そうでないパッドは大きすぎます。

この機能が必要なのは、フェーダーの位置がレベルそのものではないからです。トラックの価値は、応答した楽器によって変わります。作曲者がパートを選び、セッションが、それを演奏する SoundFont がインストールされているかどうかを調べます。同じフェーダーの同じ数値でも、内蔵シンセではリードが −18.6 LUFS、同梱フォントでは −25.8 になります。以前は、どのプリセットを選ぶかで曲の音量が決まっていました。8つのプリセットの幅は10デシベルで、−17.0〜−27.0 LUFS でした。現在は −14.0〜−17.9 の間に収まります。

移動するのは、自分が何であるかを把握しているトラックだけです。作曲者は各パートの目標値を書き込みますが、手作業で作ったトラックにはその数値がありません。そのため、自分でミックスしたプロジェクトに対して実行しても、ラウドネスは正規化されますが、バランスはそのままです。2回実行しても、2回目には何も起こりません。

各トラックにつき1回、曲全体について2回のレンダリングが必要です。8パートの曲なら、作曲にかかる時間に加えて約2.5秒かかります。実行中、ウィンドウは応答しません。

隠さずに知らせる制限が2つあります。フェーダーは +12 dB で止まるため、それ以上の音量が必要なほど静かな楽器を演奏するパートは、目標に届かないことがあります。その場合はステータス行に表示されます。また、マスターフェーダーはマスターのエフェクトの**後**にあります。したがって、測定後に強く駆動された曲はリミッターの上限を超えることがあります。この上限が保証するのはエフェクトチェーンから出る音であり、ミキサーから出る音ではありません。

<a id="the-time-signature"></a>
## 拍子

拍子も変更できます。拍子表示には、再生ヘッドが現在いる場所の拍子が表示されます。クリックすると、4/4、3/4、6/8、7/8 など一般的な拍子と、それ以外の拍子に使う *Other…* が表示されます。記譜で扱える範囲なら、全音符、2分音符、4分音符、8分音符、16分音符のいずれかを単位として、最大32拍まで指定できます。選択すると、再生ヘッドがいる区間がその拍子になります。

後ろの位置で変更する場合は、ルーラーの右クリックメニューから *Time Signature from Here…* を選びます。変更は必ず**小節線上に置かれます**。4/4 の小節の途中から 3/4 を始めると、その小節の長さがなくなり、それ以降の小節番号を数えられなくなるためです。変更が始まる小節は、ズーム倍率にかかわらずルーラーに番号で表示され、その番号の横に新しい拍子が印刷されます。それ以降は小節線とグリッドが新しい拍子に従います。7/8 の小節は8分音符7つ分の幅になり、次の小節番号は次の小節番号になります。

すでにある変更より前に新しい変更を書き込むと、後続の変更は新しい小節グリッド上に移動します。この不変条件を曲全体で保つ必要があるためです。それ以外は何も移動しません。ノート、クリップ、コード、セクションはティック単位で保存されるため、拍子を変更すると小節線だけがそれらの上を移動し、聴こえる音のサンプルは一つも動きません。Undo で1ステップに戻せます。

<a id="the-metronome"></a>
## メトロノーム

トランスポートのサイクルボタンの横にあるボタン、**Transport → Metronome**、または **K**（Logic でのキー）から操作します。トランスポートの再生中はすべての拍でクリックし、小節線では1オクターブ高く鳴るため、数えなくても強拍を見つけられます。

クリックする拍は、拍子表記の単位ではなく、実際に**感じる**拍です。6/8 の小節は付点4分音符2つで数えるため、6回ではなく2回クリックします。拍子の変更とテンポの変更の両方に追従するので、曲が9小節目で 4/4 から 7/8 に移ると、アクセントも一緒に移ります。

クリック音はミックスに混ぜ込まず、その上に重ねます。マスターフェーダーの後、マスターミュートの後、メーターの後にあるため、誤って音量を下げることがなく、プロジェクト内の全ストリップをミュートしても聞こえ、オンにしてもレベルメーターの数値は一つも変わりません。クリック音は**エクスポートには決して現れません**。オフラインレンダーはそれ以外の点では再生と同じコードパスを通りますが、ここだけが異なります。これによって、バウンスにクリック音が含まれないことが保証されます。

サイクル領域と同じく、オンかどうかはプロジェクトと一緒に保存されます。曲がカウントインを必要とするかどうかは、その曲に関する事実だからです。これは Undo のステップにはなりません。練習中のパスではオンとオフを何度も切り替えるため、それらを履歴に積むと、そのパスで確認していた編集が履歴の末尾から押し出されてしまいます。

<a id="languages"></a>
## 言語

インターフェースは英語と日本語に対応しており、Settings → General で選ぶか、システムのロケールに従います。

これはウィンドウについての設定です。`auris` は設定にかかわらず英語を出力します。ターミナルは別の表示を保証できる画面ではないからです。UTF-8 以外のコードページを使う Windows コンソールでは日本語が文字化けし、ASCII を前提とするツールへのパイプではさらに悪化します。ドキュメントから出てくる名前（プロジェクト名やトラック名）は、入力したとおりのままです。それらはプログラムの言葉ではなく、あなたの言葉だからです。

プラグイン名とパラメータは、用語が分かっている場合は翻訳します。分からない場合はプラグイン作者の表記をそのまま使います。これにより、サードパーティ製プラグインは未翻訳文字列の印ではなく、英語に戻ります。

<a id="the-harmony-lane"></a>
## ハーモニーレーン

小節ルーラーの下にある帯にはキーとコードが表示されます。ハーモニーとは、その時点でアレンジ全体が従う一つのものであり、どのトラックにも属さないため、すべてのトラックにまたがります。テンポマップと同じように、曲の進行に合わせて変化します。

ハーモニーレーン、上にあるストラクチャーストリップ、ルーラー上のテンポマークは、それぞれ **View** メニューから表示・非表示を切り替えられます。次回起動時にも、その状態が使われます。コードを書いていない曲では、空の帯2列のために1列あたり50ピクセルを使います。コーラスを中心にアレンジしている曲では、3列すべてが必要です。レーンを隠しても描画が隠れるだけで、対象そのものは隠れません。画面に表示しているかどうかにかかわらず、ドキュメントにはコードが保持されます。

レーンを右クリックすると、コード（`IV`、`vi`、`bVII7`）やキー（`Eb`、`F# minor`）を入力できます。また、名前付き進行（`axis`、`marusa`、`royal-road`、`canon` など、さらに十数個）も入力できます。これは `auris progressions` が一覧表示するカタログと同じで、作曲者は `@marusa` として読み取ります。サイクル領域がある場合、進行はそこ全体に書き込まれます。ない場合は、進行自身の長さにわたって書き込まれます。

入力欄には必要なものが示されます。フィールドの下には構文の説明が表示され、受け付ける度数やキーの行は入力に合わせて絞り込まれます。候補をクリックすると入力欄が確定します。**Tab** でキーボードから手を離さずに候補を移動でき、現在位置が示され、末尾では先頭に戻ります。この移動は最後に押したキーが入力したものではなく、**入力された文字**に従います。そのため `b` では `bIII` に補完されて止まらず、4つすべての借用候補に到達します。後から説明するのではなく、先に明記しておくべき規則は数字の大文字・小文字です。`IV` はメジャー、`iv` はマイナーです。画面上の他の要素ではこの違いを示していません。

コードは `Fmaj7` のような絶対コードではなく、ローマ数字として保存されます。そのためキーを変更すると進行全体が移調され、セクションの途中で転調しても個々のコードを書き直さずに残りを再和声化できます。レーンに表示されるのは両方です。`IVmaj7 · Fmaj7`。

レーンには、演奏したメロディから内容を**補う**こともできます。メロディを含むクリップを右クリックして *Accompany This Melody* を選ぶと、キーと小節ごとのコード1つがここに書き込まれ、ベース、コンピング、キットがその横にトラックとして追加されます。メロディ自体は変更されず、推測されたものはすべてここで修正できます。生成されたクリップで **Write It Again** を選ぶと、修正内容に従って作り直されます。何を読み取り、何を知り得ないかについては [composition.md](composition.ja.md) を参照してください。

<a id="the-structure-lane"></a>
## ストラクチャーレーン

ハーモニーの上には曲そのものの形があります。イントロ、Aメロ、サビ、または Intro、Verse、Chorus といったセクション名の帯で、各セクションは次のセクションまで有効です。「サビはこの小節から始まる」という意味を表すため、小節線にスナップします。ポインターの下にあるセクション名をダブルクリックすると名前を付けられます。フィールドには通常の語彙が表示され、**Tab** で補完できます。ラベルは自由入力なので、Cメロや落ちサビも一覧の語と同じように入力できます。境界の先頭をドラッグすると移動でき、右クリックすると名前変更、削除、アウトロの終わりで構造を終了する操作ができます。同じラベルが繰り返される場合、描画上ではサビ 1、サビ 2 のように番号が付きます。番号は曲の開始から数えたもので、保存されないため、タイムラインと食い違うことはありません。

ラベルは単なる地図ではありません。名前付きセクション内で生成されたクリップは、**ラベル**から音形を引き出します。サビという名前の区間に書き込まれた2つのクリップは、認識できるほど同じアイデアになります。一方、Bメロという名前の区間には別のものが書かれます。これは、作曲者がタイムラインから読み取る、繰り返しセクションを曲の中で認識可能にする仕組みと同じです。これが曲全体のジェネレーターの土台になります。現在でも、たまたま共存しているだけのクリップと、同じ曲に属するクリップを分ける違いになっています。

<a id="built-in-instruments"></a>
## 内蔵楽器

エンジンの動作を聞くための、意図的に単純なチップチューン音源を用意する。

| Id | 名前 | 内容 |
| --- | --- | --- |
| `auris.synth.chiptune` | Chiptune | パルス幅、ADSR、グライド、ビブラート、ユニゾン、ビットクラッシュ付きのサイン／矩形／ノコギリ／三角波／LFSRノイズ |
| `auris.synth.fm2` | FM 2-Op | 2オペレーターFM音源。別方式の合成を変更なしで組み込めることを示す音源 |
| `auris.synth.noisedrum` | Noise Drum | バンドパスを通すピッチスイープノイズによる打楽器 |
| `auris.synth.drumkit` | Drum Kit | キック、スネア、ハット、シンバル、タムを持つポリフォニックキット。ハットチョークを共有 |

矩形波とノコギリ波はPolyBLEPで帯域制限するため、高音でもエイリアシングせずきれいに保つ。

両方の音程音源には**ビブラート**があり、**Vibrato Rate**（Hz）、**Vibrato**（この音がどれだけ揺れるか）、**Mod Depth**（モジュレーションホイールでどれだけ追加できるか）の3つを操作する。`Vibrato` の初期値は0で、触っていないパッチは以前と同じ音になる。`Mod Depth` は半音の半分から始め、パラメーターを探すまで何もしないホイールにならないようにする。

LFOはボイスごとにあり、各ノートオンで再開するため同時に鳴らしたコードは一緒に揺れる。楽器全体で1つだけ使うと各ノートの周期位置がずれ、ホイールの位置に応じてコードが音痴になって到着する。深さが0でも動き続けるので、途中でホイールを上げても周期を飛ばさず本来の位置から始まる。

アタック、ディケイ、サステイン、リリースをすべて持つプラグインでは、スライダーの上に**実際の形**を折れ線で描き、各角をLogicと同じようにドラッグできる。アタックとリリースの角は時間軸に沿い、中央の角は縦横に動く。横は減衰にかかる長さ、縦はどこまで落ちるかを表す。時間軸は比例ではなく立方根で、5 msの初期アタックが2秒範囲の0.25%に埋もれないようにする。スライダーも残す。グラフは形を探す手段、数値はそれを表す手段であり、互いを代替しない。4つすべてか、どれもない。ドラムシンセはディケイだけなので、存在しない2つの角を描かない。

<a id="the-log"></a>
## ログ

**表示 → ログ**（`⌘⌥L` / `Ctrl+Alt+L`）で、アプリケーションが書いた直近500件を表示するパネルを開く。初期状態はオフで、ほかのレイアウトとともに `layout.json` に保存する。

DAWは静かに失敗することがある。移動したSoundFontはセッションではなく1トラックの音を失わせ、未知のプラグインは置き換えられ、負荷中に落ちたエンジンコマンドは落ちたままになる。これらはすべてログに記録する。以前はログが端末にしか出ず、リリースビルドは端末を開かず、アイコンから起動した人は誰も見なかった。その結果、トラックが無音になっても理由が分からなかった。

最新の行を先頭に表示する。開いた理由は直前に起きたことだからである。未確認の警告またはエラーがある間はログのパネルアイコンが琥珀色になり、パネルを開いたことがない人に見える唯一の印になる。

**リリースビルドにはコンソールがない。** `windows_subsystem = "windows"` により、`auris-studio.exe` をダブルクリックしてもウィンドウだけが開く。デバッグビルドは端末を残す。`cargo run` と `RUST_LOG=debug` で作業し、記録は両方へ出力する。

ライブラリーパネルはツリーで、楽器、SoundFont、歌声、エフェクトを平らな一覧ではなくグループとして開く。プラグインはカテゴリ別、フォントは宣言されたバンク別である。各枝は開閉状態を保持し、楽器をクリックすると選択トラックに設定し、エフェクトをクリックするとそのトラックのチェーンへ追加する。

**すべての行には色印がある。** 色印はパネル左側の列にそろえる。プラグインとカテゴリ見出しにはカテゴリ色を付け、文字を読まなくてもグループ境界が分かるようにする。フォントのサウンドは8個ずつ帯に分ける。これはGeneral MIDIの16ファミリー（Piano、Organ、Guitar、Bassなど）に対応し、灰色の小さな行128個から目で探せる構造を作る。パーカッションバンクは16帯ではなく1帯で、パッチがプログラムではなくキットだからである。

パネルの機能は色に依存しない。色付きの各行には色印の横に名前と番号があり、色印自体を文字の代わりにはしない。4つのカラースキームすべてで、色相は色数に応じてホイール上でできるだけ離し、描画面に対して3:1を超えるコントラストになるまで調整する。目視だけでなく検査で確認する。

<a id="physical-instruments"></a>
## 物理楽器

ライブラリーには **Physical Piano、Guitar、Electric Guitar、Bass、Bell、Mallet、Violin、Clarinet、Hammered Dulcimer、Tin Whistle** があり、サンプルファイルのインストールは不要である。新しいメロディートラックはPhysical Pianoで始まる。編集可能な接触硬度、励振位置、ダンピング、ボディーレゾナンスを持つ表現豊かな縮約物理モデルである。[physical instruments](physical-instruments.ja.md) を参照する。

<a id="importing-a-soundfont-of-your-own"></a>
## 自分のSoundFontをインポートする

**ファイル → SoundFontをインポート…**、またはファイルをウィンドウへドロップすると `.sf2` を読み込み、サウンドを棚に置く。ライブラリーパネルにはすべてのインポート済みフォントが並び、フォントを開くとバンク、バンクを開くとサウンドを表示する。サウンドをクリックすると選択トラックをサンプラーへ切り替え、1回の編集とUndoで済む。

**読み込みはウィンドウの外で行う。** 200 MBのフォントや、プロジェクトのレートへデコード／リサンプルが必要な音声はワーカースレッドで読み込む。ステータス行にファイルを表示し、再生を含む他の処理は継続する。同時にドロップしたファイルは1つずつ読むため、テイクのフォルダが一度にメモリへ到着することはない。

プロジェクトはフォントの*パス*を保存し、サウンドをリスト位置ではなくバンクとパッチで識別する。ファイルを編集すると位置はすぐ変わるため、この方法なら先週保存した曲を同じ楽器で開ける。サンプルはドキュメントに入れないので、200 MBのオーケストラセットを参照してもJSONは数KBである。フォントが移動した場合は1トラックの音だけを失い、セッション全体は失わない。

フォントはインポート音声と違いプロジェクトフォルダへコピーしない。[プロジェクトフォルダ](#the-project-folder) を参照する。1つのフォントを使うすべてのプロジェクトで共有し、パスを短くするためにプロジェクトごと200 MBを支払うことはしない。移動後に再認識できるよう、ドキュメントには名前とサイズを残す。

再生には `rustysynth` を使い、形式の解析とレンダーを行う。シンセサイザーの構築はオーディオスレッド外で行い、オーディオスレッド上ではアロケーションしない。

<a id="shaping-a-font"></a>
### フォントを整形する

サンプラーは内蔵楽器と同じアタック、ディケイ、サステイン、リリースとドラッグ可能なエンベロープを持つ。フォント固有の形を置き換えず、その上に適用する。ピアノのハンマーはそのままに、立ち上がりを遅くしたり、固有の減衰中に保持したり、キーを離した後まで長く鳴らしたりできる。

**オンにするまで無効である。** ウィンドウの `Envelope` トグルが全体を切り替え、オフの間は4つのスライダーが何もしない。サンプラーは各ノートに1を掛けているのではなく、機構を動かしていない。オンにすると次のコストがある。

* **ポリフォニーは15音に下がる。** シンセサイザーが公開するノートごとのゲインはチャンネル表現だけで、MIDIチャンネル全体に適用される。そのため個別にフェードする音には専用チャンネルが必要であり、16チャンネルのうち1つを予約する。
* **ドラムキットのチョークグループは動かなくなる。** オープンハイハットをクローズドハイハットで切れなくなる。チョークは同じチャンネルを共有するノート間だけで確認するが、各ノートが別チャンネルになるためである。

オンの間はグラフ下の帯に状態を表示する。オフへ戻すと、必要ならノート途中でも直ちに元へ戻る。

オンにするとエンベロープがノートを制御する。リリース0はキーを離したときに停止し、グラフにもテールのない垂直降下として表示する。デフォルトは0.2秒で、General MIDIパッチの動作に近い。

<a id="built-in-effects"></a>
## 内蔵エフェクト

| Id | 名前 | 内容 |
| --- | --- | --- |
| `auris.fx.gain` | Gain & Pan | 定電力パン、ステレオ幅、位相反転 |
| `auris.fx.eq` | Equalizer | 6バンド（HP、ローシェルフ、ピーク2つ、ハイシェルフ、LP）とライブ応答曲線 |
| `auris.fx.compressor` | Compressor | ソフトニー、ゲインリダクションメーター、他トラックからキー入力可能 |
| `auris.fx.delay` | Delay | ピンポン、ダンピング付きフィードバック |
| `auris.fx.reverb` | Reverb | Freeverb型のコム／オールパスネットワーク |
| `auris.fx.distortion` | Distortion | ソフトクリップ、ハードクリップ、ウェーブフォルダー、ビットクラッシャー |
| `auris.fx.guitar_amp` | Guitar Amp | 8倍オーバーサンプリング飽和、トーンスタック、開閉スピーカーの色付け |
| `auris.fx.limiter` | Limiter | 4倍FIRピーク検出と0.1 dBガードバンドによる先読み |

エフェクトは任意のトラックとマスターバスでチェーンできる。先読みするリミッターは音声を遅れて返すため、他トラックも同じだけ遅らせて同期させる。エクスポートでは結果の先頭部分をレンダーして捨て、ファイルをタイムラインに合わせる。

エフェクトをクリックするとフローティングウィンドウに操作部が開く。各操作部はプラグインが宣言したパラメーターから作るため、見たことのないプラグインにもエディターがあり、そのうち2つは図も描く。

**エフェクトをドラッグするとチェーンの順序が変わる。** 名前を同じストリップ、インスペクター、ミキサーの別スロットへ移動する。ポインターの移動に合わせてチェーンが並べ替わるため、見えているのが順序そのものである。空の末尾へ落とせば最後になり、行横の矢印も1段ずつ同じ操作を行う。各スロットのメニューではバイパス、並べ替え、削除を選べる。

**エフェクトは別トラックを聞ける。** コンプレッサーと、サイドチェイン入力を持つCLAP／VST3プラグインが対応する。スロットのメニューに **Sidechain** 行があり、ウィンドウのタイトル下にも選択欄がある。トラックを選ぶと、その信号をキーにする。キックを指定したベースコンプレッサーはキック時だけベースを下げ、それ以外ではそのままにするため、両方を含む低域を聞き分けやすくできる。

エフェクトが聞くのは、ソースがミックスへ送る信号（自身のチェーン、フェーダー、パン、ミュートを含む）である。キックを下げればダッキングが減り、ミュートすれば完全に止まる。自身へ戻るためストリップを待たせるトラックや、エフェクトが載るトラックは候補に出ない。トラック削除時はそこから読んでいたキーを消す。

**イコライザーは曲線を描く。** 入力スペクトルを背後に表示し、作成中の応答を重ね、オンの各バンドにノードを置く。

* **ノードをドラッグする。** 横は周波数、上下はゲイン。
* **ノード上のホイール。** 帯域を狭める。前へ回すと狭く、後ろへ回すと広い。
* ハイパス／ローパスのノードは**横だけ**に動き、中心線上にある。これらはレベルではなくコーナーを持つため、スライダーが提供するゲイン値を音声は読まない。
* **オフ**のバンドにはノードも曲線上の位置もない。下の一覧にある **On** ボタンで曲線へ入れる。

グラフ下のスライダーはノードと同じ操作をすべて行い、さらに広い範囲を持つ。表示が始まる30 Hz未満へバンドを設定でき、Qはジェスチャーだけでなく数値でも指定できる。グラフは形を探す方法で、数値は形を表す方法である。

**振幅エンベロープを持つ楽器も同じ形を描く。** アタック、ディケイ、サステイン、リリースを、想像上の4つの数値ではなく、ドラッグできる3つの角を持つ1つの形として表示する。

<a id="recording"></a>
## 録音

オーディオトラックをクリックし、トランスポートの **Record**（または `R`）を押して演奏します。もう一度押すと停止し、最初のサンプルを取り込んだときに聴いていた位置へクリップとしてタイムラインに置きます。開始時にトランスポートも走るため、曲に合わせたテイクは曲とそろいます。

**往復遅延を差し引きます。** スピーカーから聞こえる音は、出力バッファ、デバイス、ミックスの遅延補償の分だけプレイヘッドより後れます。演奏音が Auris に届くまでにも入力固有の遅延があります。Auris は2つのデバイスが報告するタイムスタンプから両方を測り、その合計分だけテイクを戻します。これによりオーバーダブは数十ミリ秒後ろではなく、演奏した位置に着地します。デバイスのクロックから信頼できる値が得られないときは、従来どおりプレイヘッド位置に置きます。

**選択したオーディオトラックにテイクが入ります。** 押す前からそのトラックの **R** ボタンが枠で示されます。別のオーディオトラックを選ぶとテイクも移り、楽器トラックやバスなど録音できないトラックを選ぶと録音先はなくなり、近いオーディオトラックへ勝手に移りません。

**R ボタンを有効にすると、表示中のトラックとは別の録音先を指定できます。** ドラムを読みながらボーカルを録音する、といった用途です。クリックして解除するまで保持され、解除すると選択に戻ります。このボタンはオーディオトラックにだけ表示されます。

**複数トラックをアームするとすべて録音します。** 各トラックは固有の入力チャンネルを使い、バンドを一度に録音できます（トラックごとに1ファイル、1クリップ）。デバイスが2チャンネル以下ならデバイス全体を、そうでなければ他で使われていない最小番号の1チャンネルを割り当てます。4入力インターフェースで4トラックをアームすると入力1〜4を自動で使い、ステレオインターフェースで1トラックを録音すると従来どおり両チャンネルを録音します。ボタンは1つのランプなので、ステータス行が毎回入力を示します。

**入力を自分で選ぶには**、アレンジメントまたはミキサーでトラックを右クリックし、**Record Input** を開きます。各チャンネル単独と各ペアを選べます。選択するとトラックもアームされるため、現在の割り当てとは別の入力でアームする方法にもなります。入力番号はインターフェースの表示どおり1からです。

1つのデバイスを使うことから、次の動作になります。

* **存在しない入力チャンネルは無音を録音します。** アーム情報は元のデバイスがなくなっても残るため、入力5〜8にアームしたプロジェクトをノートPCで開くと、内蔵マイクの複製ではなく該当トラックが無音になります。
* **各トラックは同時にモニターできます（最大8）。** それぞれの入力、フェーダー、エフェクトを通ります。8を超えると少ない数へ黙って減らさず通知します。入力コールバックは実行中に新規作成できないため、リングはデバイスを開く時に作ります。
* **アーム中の各トラックには専用メーターがあります。** 左側の細いバーがそのトラックの入力チャンネルを読みます。4本のマイクはインターフェース全体の1値ではなく4つの値になります。トランスポートバーの入力メーターは従来どおりインターフェース全体です。トラックがアームされ、デバイスが開いている間だけ表示します。

**録音には保存済みプロジェクトが必要です。** 未保存の状態で Record を押すと拒否せず保存ダイアログを開きます。テイクは録音中にプロジェクトフォルダーの `Audio/` へ直接書き込むため、フォルダーのないプロジェクトには置き場所がありません。ファイル名はトラック名と空いている番号（`Vocals 1.wav`、`Vocals 2.wav`）です。

最初に保存した後は既存のプロジェクトフォルダーを使います。後続の変更は明示的に保存してください。[Autosave](#autosave) は別の非公開スナップショットを保持します。

テイクは **32ビット浮動小数点**で、ビット深度の選択はありません。整数形式では演奏の一部を聞く前に捨てますが、浮動小数点はクリップせず、最後のコーラスで声量が上がっても復元できます。

入力デバイスは **Settings → Audio** で出力とは別に選びます。再生を中断せず、テイク実行中だけ開きます。

* **入力と出力は別クロックです。** テイクは最初のサンプルでタイムラインに固定し、その後の長さは入力デバイスのレートで数えます。異なる機器ではレートが少し違うため、1時間のテイクが数フレーム長くなることがあります。意図的に補正しないので、目に見える数フレームのずれは移動できますが、黙って再サンプリングされることはありません。
* **ディスクが停止するとフレームを失い、その数を通知します。** その前に1秒以上の余裕があります。発生後もテイクは使えますが、ギャップ以降はその長さだけ前へ移動します。

<a id="counting-in"></a>
## カウントイン

メトロノームを右クリックして **No Count-In** または1〜4小節を選びます。停止状態で Record を押すと、クリックが指定小節を数えてから動きます。曲は再生せず、プレイヘッドはテイク開始位置に留まり、トランスポートバーには残りビートが表示されます。

* **小節は現在の拍子で数えます。** 7/8の2小節は14拍、6/8の2小節は6/8を2拍として感じるため4拍です。テンポはテイク開始時の値で、カウント途中では変わりません。
* **1小節目でも数えます。** プレイヘッド前の一時停止なので、曲の先頭でも通常と同じです。
* **クリックのオン／オフに関係なく鳴ります。** カウントだけクリックを有効にしてテイクでは切る使い方ができます。
* **再生中はカウントしません。** 再生中に Record を押すとすぐ録音します。
* **録音は直ちに始まり、カウントは切り取られます。** `Audio/` のファイルにはカウントも含まれるため、早く演奏した導入を後から戻せます。

<a id="punching-in"></a>
## パンチイン

良いテイクの一小節だけを録り直すには、ルーラーを右クリックして **Punch In Here** と **Punch Out Here** を設定します。ループ中なら **Punch Over Cycle Region** を使えます。タイトルバーのパンチボタン（サイクル枠と録音点、または `⌘P`／`Ctrl+P`）で有効化し、領域は赤く表示されます。

通常どおり録音し、1〜2小節前から再生して通します。**領域内だけが保持されます。** パンチアウトでトランスポートは自動停止します。

**パンチ録音は新しいクリップが覆う範囲だけ、同じトラックの既存内容を置き換えます。** 領域をまたぐクリップは2つに分割され、外側を保ち、全体が1回の Undo です。

* **Record は手で押します。** パンチはテイクが保持する範囲を決めるだけです。
* **ファイルにはパンチ以外も含む全テイクが保存されます。** プロジェクトの `Audio/` にトラック名で置かれるため、範囲を間違えても演奏内容は残ります。領域内に何もなければステータスが知らせ、ファイルは保持します。

<a id="hearing-yourself"></a>
## 自分の音を聞く

オーディオトラックヘッダーの **I** ボタン（または `U`）で、ライブ入力をそのトラックへ通します。トラックの素材と同じ経路、つまりエフェクト、フェーダー、パン、ルーティングを通るため、録音後に入るリバーブを同じレベルで聞けます。ミュート中のトラックは無音です。

トランスポート停止中でも動作し、テイク実行は不要です。録音とモニターは同じデバイス上の独立したスイッチです。

**トラックごとにスイッチがあります。** 任意の数で **I** を押すと各ストリップを通って再生します。アームしたトラックはその入力を、5なら5、7-8ならそのペアをモニターし、アームしていないトラックは最初のペアを使います。

**同時に8経路まで**です。入力デバイス起動前に各経路のバッファを作るため、9番目は少ない数へ黙って減らさず通知します。

**ソフトウェアモニターには遅延があり、インターフェースの直接モニターにはありません。** 入力デバイス→Auris→出力デバイスを通り、非同期クロックが枯渇しないよう中央に3ブロックのバッファを置きます。512フレームならハードウェア分に約32 ms加わります。直接モニター付きインターフェースではそちらを使い、二重に聞かないでください。このため、モニターはトラックをアームするたびに自動で有効になるのではなくスイッチになっており、有効にするたびにステータス行がそのコストを示します。

モニターが途切れるとステータス行が回数を示します。クロックのずれで再生済み部分を繰り返せなくなるとライブ端へ戻ります。長時間に少数なら通常ですが、連続する場合はブロックサイズを **Settings → Audio** で調整してください。

<a id="autosave"></a>
## 自動保存

Auris は未保存の変更がある間、約30秒ごとにセッション専用の作業フォルダーへ復旧スナップショットを保存します。初回保存前も機能し、ドラッグの完了を待ちます。成功時は何も表示せず、失敗時はステータス行に知らせます。

プロジェクトファイルとタイトルバーの未保存表示は変わりません。**Save** または **Save As** で変更を恒久的なプロジェクトへ書き込み、古いスナップショットを削除します。保存せずに閉じると、最後に手動保存した版が残ります。

中断終了後の次回起動では、新しい順に放棄されたスナップショットを提示します。**Recover** はスナップショットを未保存ドキュメントとして開くため、保存は常に明示的な選択であり、元のプロジェクトを自動で上書きしません。**Discard** は完全に削除し、**Not Now** は次回起動のために残します。別の実行中 Auris が所有するワークスペースはロックされ、一覧には表示しません。

自動保存は既定で有効です。**Settings → General → Autosave** で無効にできます。

<a id="the-project-folder"></a>
## プロジェクトフォルダー

プロジェクトは単独ファイルではなくフォルダーです。**Save As** で作成され、`MySong.auris` を選ぶと次のようになります。

```
MySong/
  MySong.auris        the document, pretty-printed JSON
  Audio/
    kick.wav          every audio file the song uses
```

音声はインポート時にコピーされ、ドキュメントはフォルダーからの相対パスで参照します。フォルダーごと移動、改名、別のマシンへのコピー、zip化、バージョン管理ができ、移動先でも不足なく開けます。1つのフォルダーに1つのプロジェクトがある場合だけ成立します。2つのドキュメントが同じ `Audio/` を共有すると、片方を別名で保存したときも両方が同じファイルを指し続けるため、Save As はフォルダーを作成します。相対パスはプラットフォームにかかわらず `/` 区切りで保存されるので、Windowsで保存したプロジェクトをMacで開けます。

入力した名前より1階層深い場所にドキュメントを作るため、システムの保存ダイアログは置き換えを警告できません。書き込まれないパスを尋ねているからです。Auris は代わりに、失われるプロジェクト名を示して確認します。New Project、Open Project、ウィンドウを閉じる、終了で未保存変更を捨てる場合も確認します。これらはドキュメントとともにUndo履歴を消すためです。

SoundFont は上記の理由で元の場所に残ります。**File → Collect Assets into Project**（または `auris collect`）でアーカイブや共有用にコピーできます。数百MBの容量を使うため、明示的な操作です。

ファイルが移動していた場合、プロジェクトを開くとプロジェクトフォルダーと、他のプロジェクトファイルが存在することが分かったディレクトリを探します。フォントは記録済みサイズで確認するため、同名の別ファイルを黙って採用しません。見つかったパスはドキュメントへ書き戻し、毎回検索することを避けます。完全に失われたファイルは報告し、そのトラックを無音にしてプロジェクトを開きます。

CLAP と VST3 プラグインもパスで名前を付けますが、ドキュメント内のパスだけでは実行できません。プラグインは **plugin folder** からのみ読み込みます。これはプラットフォーム標準の CLAP／VST3 フォルダーと、プラグインブラウザーで追加したフォルダー／ファイルです。別の場所（プロジェクトの隣や配布されたディスクイメージなど）を指すプロジェクトは、そのスロットを無音で開き、ステータス行にファイル名を示します。読み込むにはフォルダーを追加してください。プロジェクトを開くのはドキュメントを開くことなので、他人のドキュメントが隣に置いたコードを実行できてはいけません。

<a id="key-bindings"></a>
## キーバインド

すべてのコマンドは再割り当てでき、設定ウィンドウで行います。行にキーを押すと割り当て、＋で2つ目を追加、—でキーなしにします。既定へ戻すのとは異なる「キーなし」を表します。変更した項目だけが `keymap.json` に書かれるため、後で既定値が変わっても反映されます。

**キーのない行もあります。** トラックのミュート、ソロ、複製、クリップのミュートなど、右クリックから操作でき、指で使いたい一方で他の用途のキーを奪うほど頻繁ではないコマンドです。行で1回押せば割り当てられます。—で生じる「キーなし」と同じなので、割り当てを取り消したコマンドは第3の状態にならず開始時へ戻ります。

バインドはこのキーボードが報告した形で取得し、両方のキーボードが使う表記で保存します。dotfilesリポジトリに `keymap.json` を置けば、同じ行からMacでは⌘、WindowsではCtrlに結び付きます。

バインドはキーボードがある場所に適用されます。多くはウィンドウ全体で動きますが、パネル専用のものは行に示されます。**T** はピアノロールの次のツールを選び、ミキサーでは何もしません。**Tab** と **⇧Tab** はパネル間を移動し、キーボードを持つパネルを枠で示します。異なるパネルの同じキーは競合ではなく、到達可能な衝突だけを表示して許可します。

マウスは不要です。**F10** でWindows／Linuxのメニューバーを開き、←→でメニュー、↑↓で行を移動し、Returnで実行、Escapeで閉じます。右クリックメニューも同じキーに応答します。メニューを開いている間は他のバインドを無効にし、文字キーで別コマンドが同時に動かないようにします。

<a id="the-command-palette"></a>
## コマンドパレット

**⌘⇧P**（Windowsでは Ctrl+Shift+P）で、数文字を入力してコマンドを探すボックスを開きます。`nit` で New Instrument Track に到達します。単語の先頭の一致を途中の一致より優先し、`save` では Save が Add Audio Track より上になります。再割り当て可能な全コマンドとキーを表示するため、キーの有無も確認できます。

各行は画面上の名称だけでなく英語名にも応答します。日本語UIでも `save` で Save を検索できます。ドキュメント、キーチャート、他の音声プログラムが使う名称であり、入力時にアルファベットを切り替える必要がないためです。設定ウィンドウのキー検索も同じです。

値も設定できます。編集グリッドには `1/16`、プレイヘッド位置の拍子には `6/8`、ウィンドウを塗り替えるにはカラースキーム名、言語を切り替えるには `日本語` を入力します。言語一覧は各言語自身で表示されるため、現在の表示を読めない人でも選べます。

<a id="settings-where-dotfiles-can-reach-them"></a>
## 設定とドットファイル

設定の上部にある検索欄は、General、Audio、Agent、キーバインドをまとめて検索します。インターフェースの言語に関係なく、日本語と英語のラベル・説明に一致し、空白で区切った語で結果を絞れます。一致したセクションはコントロールを保持するため、結果から直接変更できます。欄を消す、欄で Escape を押す、タブを選ぶと全ページへ戻ります。

**General → Panel positions** では、ライブラリ、ピアノロール、ミキサー、インスペクター、ログ、エージェントを左・下・右のドックへ割り当てます。移動したパネルは新しい位置で開き、そのドックに表示されていたパネルを置き換えます。レイアウトは次回起動のために保存され、パネル固有メニューで行った変更も設定に反映されます。

設定では、言語、ポインタージェスチャー、オーディオデバイス、書き出し形式など相互排他的な選択にドロップダウンを使います。Enter または Space で選択肢を開き、矢印キーで移動し、Enter で適用、Escape でキャンセルします。インターフェースを接続した後は Audio ページでデバイスを更新してください。

General ページにはインターフェースフォントの選択とカラーテーマエディターもあります。インストール済みフォントを選ぶかシステム既定へ戻します。変更はすべてのウィンドウに適用され、日本語などのスクリプト用フォールバックフォントは保持されます。既存パレットからテーマを作り、名前を付け、アクセント色を `#RRGGBB` で入力します。**Save and apply** を押すまでプレビューは適用済みテーマを変更しません。保存したカスタムテーマはここで選択・編集できます。

各プリセットには、トラック、クリップ、ライブラリ用に8つのパレット色があります。テーマ作成時にエディターがコピーします。ベースを変えると継承色が更新され、下書きで既に編集した色は保持されます。スロットには `#RRGGBB` を入力するか、空欄にしてアクセントから導出します。新しいトラックは種類（instrument、drums、singer、audio、bus）でスロットを選びます。ライブラリは対応色を使い、エフェクトはバスのスロットを共有します。トラックの色メニューには8スロットすべてがあり、クリップは選択色を継承します。テーマを変えても保存済みプロジェクトは変わらず、表示だけが更新されます。

コードブロック、現在のコード表示、コード補完チップは I〜VII の7色を共有します。書かれた主数字が色を選び、クオリティ、臨時記号、転回、二次ターゲットは変えません（`V`、`V7`、`V7/V` はVを共有し、`VII` と `bVII` はVIIを共有します）。テーマエディターでは各度数を上書きでき、空欄は最初の7つのトラックパレットスロットに従います。テーマを変えると和音やキーを編集せず進行の色だけが変わります。ドラッグしたブロックは強い色味で度数色を保ち、ラベルは読めるコントラストを保ちます。

トランスポートとインジケーターにも編集可能なパレットがあります。再生と通常メーター、警告／ソロと高レベル、録音／クリップ／エラー、ミュートの色です。各プリセットは独自の配色を使います。空欄はアクセント（再生）、バス色（警告とミュート）、ドラム色（録音とクリップ）に従います。ホバー中を含め、インジケーターは読みやすさのため明度を調整します。全トラックとマスターメーターはこれらの色を共有します。

ピアノロールのノート色はテーマのベロシティグラデーションを使います。テーマエディターでは両端、位置（%）と色を編集できる中間点、ライブプレビューを指定します。点は追加・削除でき、位置は互いに異なり0〜100%の厳密な間でなければなりません。色は隣接点間の最短色相弧で補間します。GitHubプリセットは青、紫、赤を使い、トラックパレット、再生インジケーター、メーターに緑はありません。空の端点は楽器・ドラムのパレットスロットに従い、明示色はベーステーマを変えても残ります。継承した中間点は編集するまでベースに従います。これらの色変更は表示だけを変え、ノートのベロシティは変えません。表示グラデーションは両方のピアノロールレーン色に対して読めるよう明度を調整します。

設定はすべてのプラットフォーム（macOSとWindowsを含む）で `~/.config/auris-studio/` に保存します。`~/Library/Application Support` や `%APPDATA%` ではありません。

```
~/.config/auris-studio/
  settings.json       audio device, sample rate, buffer size, interface language
  progressions.json   the chord progressions you have kept
  keymap.json         key bindings you have changed from the defaults
  appearance.json     selected and custom colour themes, interface font
  layout.json         where each panel is docked, and how large each dock is
```

ドットファイルリポジトリをすでにチェックアウトしているディレクトリに、読みやすく手編集できる小さなJSONファイルを5つ置きます。`AURIS_CONFIG_DIR` でディレクトリを直接指定するか、`XDG_CONFIG_HOME` で親を移動できます。移動前のインストールも設定を保持し、初回起動時に旧ディレクトリのファイルを新しい場所へコピーします。ただし新しい場所に既にあるファイルは上書きしません。

<a id="export"></a>
## 書き出し

プロジェクト全体をWAVファイルへ、16ビット、24ビット、または32ビット浮動小数点で、リアルタイムより速くレンダリングします。レンダラーは最後のクリップを越えて、エフェクトが無音になるまで動作します。チェーン内のテールは重ならずに積み重なります。ディレイからリバーブへ送る場合、ディレイ自身の減衰全体を通じてリバーブへ送り続けるためです。そのため音が途中で切れることはありません。

書き出しは任意のサンプルレートで行えます。ソースは先にそのレートへ変換されるため、96 kHzで書き出したプロジェクトは、同じサンプルを速く再生したものではなく、同じ曲です。

サイクル領域は*File → Export Cycle…*から単独で書き出すか、コマンドラインで`auris render --loop`を使います。楽器とエフェクトを少なくとも1サイクル分、さらに報告されたテール長の分だけウォームアップした後、正確に1回分を出力します。リバーブとディレイは冒頭へ持ち越されますが、テールは追加しないため、マークした境界でファイルを繰り返せます。通常のプロジェクト全体の書き出しと、明示したフレーム範囲の書き出しには、引き続きリリーステールが含まれます。

<a id="stems"></a>
### ステム

*File → Export Stems…*はフォルダーを指定して、**トラックごとに1ファイル**を作成し、トラック名を付けます。コマンドラインの`auris render Song.auris --stems Stems/`でも同じことができます。

ステムは、**そのトラックだけをソロにしたときに聞こえる状態**のトラックです。トラック単体と同じではありません。経由するバスも含むため、リバーブへ送ったパートはドライではなくリバーブ付きになります。これが、他の人がミックスに使えるステムと、そのセッションを再構築しなければ使えないファイルの違いです。

* **音を出すトラックごとに1ファイル。**バスには専用ファイルを作りません。バスから出る音は、そこへ送るトラックのステムにすでに含まれており、両方を書き出すとステムを再び足したときにリバーブが二重になるためです。
* **ミュートしたトラックは除外します。**無音ファイルとして書き出すのではなく、ミックスを分解した結果だけを取得します。ソロは無視します。ソロはその瞬間の聞き方であり、曲の構成ではないためです。
* **同じ名前のトラックが2つあっても2ファイルになります。**2つ目には番号が付きます。
* **マスターチェーンはすべてのステムに含まれます。**ステムは1パートを含むミックスの聞こえ方だからです。チェーンが線形ならステムを足し戻すとミックスと完全に一致します。リミッターやコンプレッサーの場合は、各ステムが個別に処理されるため一致しません。ステムを合算する必要がある場合は、先にバイパスしてください。

トラックごとにグラフを1つ作るのではなく、1つのグラフからすべてをレンダリングするため、ホストされたプラグインは1回だけインスタンス化されます。ただしレンダリング自体はトラックごとに1回行われるので、20トラックのプロジェクトはミックスダウンの20倍の時間がかかります。進捗バーとCancelがあり、押す前に完了したものはディスクに残ります。

<a id="gpu-acceleration"></a>
## GPUアクセラレーション

`auris-gpu`は、[wgpu](https://wgpu.rs)を通じてGPU上で大規模かつ独立並列なオフライン縮約を実行します。クリップ描画用の波形のmin/max/RMS抽出と、ファイル全体のラウドネス解析が対象です。すべてのカーネルにCPUフォールバックがあり、GPUがなくてもアプリケーションは正しく動作します。

リアルタイムのブロック単位DSPは意図的にCPUに残します。GPUとの往復にかかるレイテンシーが、1つのオーディオブロックに許される処理時間全体より長くなるためです。

<a id="frontends"></a>
## フロントエンド

バックエンドはUIについて何も知らないクレート群で、各フロントエンドは同じ [`Session`](../crates/auris-session) の上にある薄い層です。1つのドキュメント、1つのエンジン、ユーザーコマンドごとに1つのメソッドを共有します。

```bash
cargo run --release                 # the desktop application
cargo run --release -p auris-cli -- help
```

コマンドラインツールは、役に立つためだけでなく、この分離を保つためにも存在します。ウィンドウもオーディオデバイスもない同一のセッションを動かすため、UIへの依存が漏れるとここでコンパイルに失敗します。

```bash
auris compose song.asong -o song.auris         # write a piece from a specification
auris progressions                             # every chord progression known by name
auris plugins                                  # every registered instrument and effect
auris presets                                  # the whole songs a piece can start from
auris compose --preset city-pop                # …and one written without a file
auris soundfonts                               # optional libraries and whether they are installed
auris new song.auris --bpm 128
auris info song.auris                          # tracks, clips, duration
auris render song.auris -o song.wav --bit-depth 24   # 既存の song.wav を置き換えるには --force
auris collect song.auris                       # gather every file it uses into its folder
```

音色・歌声の利用可能状況、モチーフを保つ再生成、エフェクトチェーン、サイドチェイン、パラメータ自動化、Ollama の設定については、[エージェントによる作曲とリビジョン](agent-workflows.ja.md) を参照してください。

`auris-mcp` は3番目のフロントエンドです。[Model Context Protocol](https://modelcontextprotocol.io) の背後で同じセッションを stdio 経由で動かすため、言語モデルのハーネスから操作できます。ツールは曲を書くところから聴くところまでのループをカバーします。`spec_reference` は例を使って `.asong` 形式を説明し、`check_spec` はドラフトを検証してすべての既定値を埋めた状態で回答し、`compose` は曲を書いてプロジェクトを保存し、`render` はプロジェクトを WAV ファイル（ミックス、またはトラックごとに1ファイル）へ変換し、`describe` はすべてのクリップに番号を付けてプロジェクトを読み戻し、`list_presets` / `list_progressions` は仕様から引用できる語彙を提供します。回答は、そのテキストに基づいて行動する読者向けに書かれます。拒否された仕様では行とフィールドが示され、レンダー結果では各ファイルの長さとピークが報告されます。

曲を改善するループは `analyze` です。サーバーがプロジェクトをレンダーし、モデルの代わりに聴き、ミックス全体、名前付きセクションごとの音量とピーク（曲のダイナミックアークを数値化したもの）、要求時にはトラック単体についても報告します。その回答を受けて、モデルは仕様を編集して再度作曲するか、`describe` が付けた番号でクリップを指定して `edit_recipe` を適用します。`take` は、現在の和声に従う `{kind:"same"}`、新しいテイクを作る `{kind:"next"}`、1つのシードを厳密に再現する `{kind:"seed",seed:42}` を選べます。`teach_progression` はこのマシンにコード進行を名前付きで保存し、`forget_progression` は削除します。

ミックスにも独自の小さなループがあります。机上の各操作に1つずつツールがあり、`mixer` はフェーダー、パン、センド、すべてのエフェクトパラメータとその範囲を含むミックス全体を読み取り、`set_level`、`routing`、`set_effect` はそれぞれ1項目を変更し、`section_gain` は1つの名前付きセクション全体でトラック（またはマスター）のゲインを一定レベルに保ちます。ゲイン自動化は短いランプ付きで書かれるため、セクションの外側ではフェーダーの値が効き、異なるセクションの指定も組み合わせられます。`analyze` がセクションの音量過多、埋もれたパート、マスターリミッターの張り付きなどを示したとき、再シードして小さな調整を重ねる代わりに、これらのツールで一度にデシベル単位の調整ができます。

アレンジはその場で編集できるため、パートを1つ追加する操作は再作曲ではなく編集になります。`add_track` は既存プロジェクトに新しいトラックを追加し、組み込み楽器ID（`list_instruments` が名前を返します）または音楽的な音色ヒントで音色を指定できます。音色ヒントは名前（"Electric Piano 1"）またはプログラム番号で指定します。対応するファミリーはネイティブモデルを選び、それ以外のヒントではインストール済みのGMライブラリを任意で使用できます。`add_part` は曲に既にあるキーとコードから生成パート（リード、コード、パッド、アルペジオ、ベース、またはキットとその各パーツ）をトラックへ書き込み、作曲したクリップと同じように `edit_recipe` を適用できるようレシピを保持します。`set_instrument`、`rename_track`、`remove_track` は名前どおりに動作します。

ノートは1つずつ配置できるため、作曲の進め方を逆転できます。`add_clip` は空のクリップを開き、`edit_notes` は名前と位置（「F#4」、2小節目、3.5拍目）でノートを追加・削除します。削除と追加は1回の呼び出しで行えます。`notes` は時間順に番号を付けてクリップを読み戻し、`accompany` はメロディークリップを読み、曲に設定されたキーとコードを使ってその下に伴奏バンドを書き込みます。メロディーのノートには一切触れません。これはウィンドウの伴奏機能と同じコマンドなので、モデルと人が同じメロディーから同じバンドを導けます。意図した使い分けは、モデルが制御したい箇所ではノート単位でメロディーを書き、それ以外は和声からすべてを導くことです。

MCPツールから曲を歌わせることもできます。`singer` を kind にして `add_track` を呼ぶと、ノートに歌詞を持つトラックが作られます。`write_lyrics` はクリップのノートに1音節ずつフレーズを配置し、かなは組み込み表を使い、その他の文字はインストール済みなら日本語辞書を使います（`notes` はピッチの横に歌詞を読み戻します）。`sing` は `voice` で一度選んだバックエンドの音声エントリへの絶対パスを使ってトラックをレンダーし、そのテイクを再生と `render` が使える形で保存します。各バックエンドのシード動作を含め、ウィンドウと同じレンダリングパイプラインを使い、結果を音声として保持します。MCPサーバーとAgent Panelでは同じツールセットを利用できます。

既存の曲は、置き換えを作曲せずに改訂できます。`inspect_composition` は元の仕様を、現在の和声、テンポ、セクション、クリップレシピとは分けて読み取ります。`edit_harmony` は指定された小節範囲を変更し、ノートとミックスをそのまま保ちます。`edit_recipe` はそれに従うべきパートを明示的に更新します。`edit_recipe` は1つのクリップの密度、強度、リズム、オクターブ、グルーヴを変更し、シードと指定されていない制御値を保持します。手編集したノートを置き換えるには明示的な置換フラグが必要です。`edit_clip` はノートクリップの移動、複製、分割、サイズ変更、削除、ミュート、固定を行います。`analyze_music` は保存されたノートの音域、密度、正確な小節パターンの反復を測定します。これらは説明的な測定であり、美的評価ではありません。

すべての `track` 引数は、`describe` と `mixer` が表示する `id:4` のような安定したセレクターも受け付けます。改名後も、同名のトラックを含む既存ドキュメントでも、IDは同じトラックを指し続けます。ツールからトラックを追加・改名する場合、名前は一意でなければなりません。`edit_recipe` は変更前に対象となるすべてのクリップを確認します。手編集を含む場合は、`edit_recipe` と同様に `replace_hand_edits: true` が必要です。

`section_gain` は絶対値の `gain_db` と相対値の `gain_delta_db` のどちらも受け付けます。相対変更は既存のエンベロープを移動し、その形を保ったままセクション内で調整をフェードイン・フェードアウトします。`mixer` はゲインエンベロープの各点と各セクションの中間値を一覧表示するため、モデルはベースフェーダーを再生時の値と取り違えずに自動化を読み取れます。

`render` は `start_bar` と `bars` による連続範囲、または `section` ラベルと1始まりの `instance` を指定して書き出せます。同じセクションラベルが繰り返される場合はインスタンスの指定が必要です。範囲の書き出しでは既定でエフェクトのテールを省き、`include_tail: true` で保持します。アレンジの範囲外を要求すると拒否されます。プロジェクト全体の書き出しは従来どおりです。

`preview` は同じ範囲セレクターを使い、最大120秒の試聴を行います。エフェクトのテールを含まない24 kHz、16ビットのWAVを `.auris-previews/` に書き込み、ドキュメントは変更しません。両方のフロントエンドはローカルWAVの絶対パスと測定値を返し、クライアントはローカルプレーヤーでファイルを開くかパネルに添付できます。どちらの書き出し経路も、レンダーされた信号が整数WAVでクリップする場合に警告します。

編集ツールは、編集前のドキュメントを `.auris-history/` に保持します。`checkpoints` ツールはこれらのスナップショットを一覧表示し、名前付きの代替を作成し、現在のバージョンを別のスナップショットとして残したまま1つを復元します。スナップショットはプロジェクトのアセットを共有するため、音声を複製しません。また、アーカイブ用のアセット収集の代わりにはなりません。

サーバーをクライアントに登録するには1行で済みます。

```bash
claude mcp add auris -- ./target/release/auris-mcp
```

デスクトップアプリケーションで開いているプロジェクトは、MCPサーバー（またはファイルを書き込む別のツール）を通じた編集に追従します。ウィンドウはファイルの更新時刻を監視し、未保存のものを何も保持していない間は変更を受け入れ、未保存のものがある場合はUndo可能な受け入れを提示します。手動のインプレース保存はディスク上の新しいバージョンを上書きしません。Autosave はプロジェクトファイルを上書きせず、非公開の復旧スナップショットを書き込みます。変更を受け入れると、以前のウィンドウドキュメントがUndoスタックに残り、Save As で別に保存することもできます。協調して書き込むプロセスは、プロジェクトファイルのロックで確認と保存を直列化します。

Agent Panel はローカルの Ollama サーバーまたは OpenAI互換APIに接続します。接続と生成の設定は Settings → Agent（Windowsでは Ctrl+,）にあります。モデルの選択とモデル一覧の更新はパネル内で行います。モデルランタイムはUI不要の `auris-agent` ライブラリにあり、`auris-studio` にリンクされています。専用のバックグラウンドスレッドが会話を処理するため、UIは応答可能なままです。`cargo run` はデスクトップとエージェントを一緒にビルドします。

Settings でプロバイダーを選び、パネルでモデルを選びます。モデルの検出もバックグラウンドで実行され、URLとAPIキーの環境変数名は共有設定に保存されます。秘密情報はプロセス環境に残ります。トランスクリプトにはツール呼び出し、結果、モデルの回答が表示されます。

モデルは、未保存の空プロジェクトを含む現在のセッションをライブコマンドで編集します。`inspect_project` は現在のアレンジを読み取ります。モデルは音楽パートを選び、フラットなトラック、クリップ、ノートの各ツールで書き込みます。`edit_notes` は `read_notes` の返す正確なティックとリビジョンを使って、範囲を限定した原子的なパッチ／置換を適用します。`edit_timeline` と `set_loop` はテンポ、拍子、ループを制御します。変更はモデルの最終回答前に表示されます。削除が明示的に要求されない限り、既存の音楽は保持されます。名前のないドキュメントに新しく書いた曲には `rename_project` で曲名が付けられ、「別名で保存」や書き出しのダイアログは「Untitled」ではなくその曲名を提案します。準備ができたら通常どおりプロジェクトを保存します。

パネルでは音声を添付し、進行中のやり取りを停止して新しい会話を開始できます。Enter または Send ボタンで送信します。回答は、選択可能なMarkdownブロックとして、簡潔な見出しと字下げしたリストで表示されます。Copy Markdown は回答全体をコピーします。別のドキュメントを開くと、エージェントがそのドキュメントに再バインドされます。保存済みプロジェクトでは、成功したユーザー／回答のペアが `.auris-conversation.json` にローカル保存され、次のメッセージで再開されます。コンテキスト圧縮は、それ以前のやり取りを要約しながら、直近2件を逐語的に保持します。自動でも Compact context でも実行できます。テキストストアには256回分のやり取り、100万文字という最終安全上限があり、ツールのペイロードとエンコード済み音声は保持されません。現在の選択はメッセージごとに新たに送信されます。新しい会話を始めると保存済みのテキストメモリが消去されます。

パネルには Read-only、Edit、Plan、Auto review、Bypass の各モード、操作の許可・拒否ルール、承認が必要な操作の前の確認があります。Codex と Claude Code はネイティブのファイル・シェルツールも提供します。Auto review は別のモデル会話を使ってユーザーに代わり保留中の操作をレビューし、不確かな判断は手動確認に戻します。モードの意味とキーボードコマンドについては、[エージェントの権限とコンテキスト圧縮](agent-workflows.ja.md#agent-permissions-and-context-compaction) を参照してください。
