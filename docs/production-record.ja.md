# 会話の制作記録

[English](production-record.md)

ライブの `production_record` ツールは、会話のモデルメモリと並べて、意図、音楽上の役割、モチーフ、判断、未解決の問題を保持します。各エントリには安定したキー、カテゴリ、本文、明示的なクリップ ID、引用したユーザーの依頼またはエージェントの仮定のいずれかが含まれます。帰属情報はトランスクリプトと照合するための主張であり、権限を与えるものではありません。更新すると1つのキーが置き換わり、他のエントリは保持されます。

`inspect_project` は毎ターン、統合済みの記録を返します。明示的に記録を読み取る場合も現在のドキュメントを調べるため、編集後にキャッシュされたリビジョンを誤って使うことはありません。存在しないクリップ ID と古くなった観察結果も表示されます。

ホストが保持するのは、最新のプロジェクト検査と数値リビジョンが一致する `inspect_audio` の測定値と `listen` のレポートだけです。編集後、測定前に検査を更新してください。ノートを書き込む操作でツールの証拠を設定することはできません。

証拠はコンテンツハッシュ、単調増加するリビジョン、ドキュメントの存続期間に結び付いています。再オープン、編集、Undo を行うと保守的に無効になります。対象範囲には短いセクション抜粋、セクション境界、終端、ループの継ぎ目が含まれます。トラックをソロにした測定はミックスを対象とせず、ループ端を別々に測定しても連続したループの接続は検証できません。台帳が人間による試聴を主張することはありません。ユーザーのフィードバックは帰属付きのメモとして保持し、現在の測定値やモデルが聴いた結果を、ユーザーの音楽的な好みとはみなしません。

記録は `memory.production.json` 内で64エントリ、32観察結果に制限されます。保存にはモデル履歴の生成ロックを使うため、遅れて到着した書き込みがリセット済みの履歴を再作成することはありません。Save As では記録も会話と一緒に保存されます。永続的な会話を持たないワーカーは `worker_lifetime` ストレージを報告します。スコアと Undo は影響を受けません。既存の会話ストレージを移行する必要はありません。大きな表示では、保存済みのコンテキスト全体を捨てずに `read_report` のページを使います。
