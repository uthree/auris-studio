# Physical Choir

[English](physical-choir.md)

インストゥルメントライブラリで **Physical Choir** を選び、通常のインストゥルメントトラックでノートまたはコードを演奏します。安定したプラグイン ID は `auris.physical.choir` です。4人の歌い手による持続する無歌詞の合唱母音をローカルで合成し、16音までポリフォニックに演奏できます。

<a id="controls"></a>
## コントロール

| コントロール | 効果 |
| --- | --- |
| Vowel (Oo / Ah / Ee) | 声道を連続的にモーフィングします。0は丸い「oo」、1は開いた「ah」、2は前寄りの「ee」です |
| Voice Size | 声道の長さを14〜20.5 cmで変えます。大きい声では同じ音高でも共鳴が低くなります |
| Ensemble Variation | 歌い手ごとの音律、ビブラートの速度／位相、ゆっくりした音高の揺れ、声道長の差を作ります |
| Breath | 各歌い手の声道入力に独立した息のノイズを加えます |
| Tone | 声門音源の高域ロールオフを調整します |
| Vibrato | 音高の揺れを半音単位で設定します。MIDI CC1 は最大0.3半音を加えます |
| Stereo Width | 歌い手をステレオ空間に広げます。0では合唱を中央に配置します |
| Attack / Release | 各ノートの立ち上がりとフェードを整えます |
| Level | 楽器の出力ゲインを設定します |

すべてのコントロールは通常のパラメーターエディター、プラグイン状態の保存、オートメーションレーンに対応します。Vowel と Voice Size の変更は、約20 msかけて鳴っている声道共鳴を移動させます。Width と出力ゲインの変更も同じ時間で平滑化されます。MIDI CC7 はチャンネルボリューム、CC11 はエクスプレッションを制御し、ピッチベンドは鳴っているノートに対して ±24半音で追従します。ノートオフは重なったユニゾンを含め、対応する保持中のノートを1つ解放します。all-notes-off は合唱全体を解放し、all-sound-off は共有のクリック除去エンベロープを使います。

既定パッチのアタックは283 ms、リリースは700 msです。C3〜C5付近の保持コードは伴奏パッドの出発点に適しています。母音値を下げてアタックを長くすると丸い背景テクスチャになり、Tone を上げてアタックを短くすると前面に出る合唱パートになります。リバーブをインサートすると周囲の部屋の響きを加えられます。

<a id="model-and-verification"></a>
## モデルと検証

各歌い手は、双方向の分数遅延線と面積変化部の受動的な圧力散乱を備えた8区間の円筒声道を持ちます。設計した断面形状は3つの母音設定の間を補間します。声門と唇の反射、分布損失、1次の唇放射近似が出力を形作ります。指定された体積流量音源は声門面積で圧力に変換され、唇面積で放射流量に戻るため、口の狭い母音でも演奏可能なレベルを保ちます。音源は Rosenberg 型の規定声門流パルスで、`prepare` 内で帯域制限された倍音テーブルに再構成され、シード付きの息ノイズも加わります。これはパラメトリック音源で駆動する縮約物理音響声道です。母音プロファイルと工場出荷時の音源コントロールは実際の持続母音に合わせて調整し、別の歌い手をホールドアウトにしています。歌い手の解剖を測定したものではなく、楽器の音色を表します。コホート、ログメル損失、パラメーター範囲、結果、再現用の開発コマンドは [実録音による較正の説明](choir-copy-synthesis.ja.md) にあります。

音源／フィルターと管の原理は Oxford phonetics の [tube-model practical](https://www.phon.ox.ac.uk/jcoleman/tubes_practical.html) に説明されています。[sndkit の声道の説明](https://pbat.ch/sndkit/tract/) では、関連する Kelly–Lochbaum 導波管の系統を説明しています。Auris は独自の圧力散乱実装、断面形状、分数区間遅延、合唱レンダラーを使います。

ユニットテストでは、物理的な4分の1波長共鳴、母音スペクトル、演奏音の基音、コードレベル、ステレオダウンミックス、コントローラー応答、ノート解放を測定します。ブロックサイズとリセットを変えた場合もサンプル単位で同じ出力になることを比較し、オートメーション、コントローラー変更、ボイススティール時のコールバック割り当てがゼロであることを数えます。セッションテストでは、母音オートメーション付きの通常のインストゥルメントトラックを保存して再オープンし、レンダリング音声を比較します。

編集可能なデモプロジェクトと、3種類のステレオ母音試聴を生成します。

```sh
cargo run -p auris-session --example choir_preview -- target/choir-preview
```

4コードのフレーズはすべての試聴で同じです。`choir-preview.auris` には既定の「ah」版が入り、`choir-oo.wav`、`choir-ah.wav`、`choir-ee.wav` はそれぞれ母音値0、1、2を使います。フレーズで使うのはこの楽器と通常のミックス出力だけです。

較正済みの4コード試聴のピークは、クリッピングなしで oo が -16.22 dBFS、ah が -8.59 dBFS、ee が -13.86 dBFSです。既存の9つの出荷プリセットは、この追加の前後で WAV ハッシュとシンボリックルーラー出力が同一です。これらの回帰チェックは追加した楽器が既存のアレンジメントを変更しないことを示し、母音スペクトルと物理共鳴のテストは新しい楽器そのものを説明します。
