# エージェント作曲トライアル — 2026-11-02

[English](agent-composition-trials-2026-11-02.md)

ありそうな依頼を2件、実際のアプリケーションホスト経由でエージェントに渡しました。バックエンドは
インストール済みの Codex、モデルは `gpt-6.1-sol`、隔離された未保存のフィクスチャと明示的な
バイパスです。どちらも完走しました。見つかったのは誤った編集ではなく、ツールが既に知っている答えを
モデルに探させている箇所が3つあったことです。

ハーネスはオプトインの `codex_composes_and_revises_the_open_document`（[作曲品質](composition-quality.ja.md)
に説明があります）です。これらの実行は凍結済みマニフェストではなく個別の設定を使ったため、測るのは
実行であって音楽的品質ではありません。

<a id="the-two-requests"></a>
## 2件の依頼

**料理動画のBGMループ**、空のプロジェクトから3ターン。110 BPM・ハ長調・16小節の明るいループを
ピアノ、ベース、軽いドラムで。次にドラムを控えめにし、既存の音符に触れずに9〜16小節へストリングスを
追加。最後に24bit WAVとMIDIを書き出し、長さ・無音・音割れを確認。

**ユーザーが書いたメロディーへの伴奏**、8小節6/8のフィクスチャから2ターン。手書きメロディーを
絶対に残したままギター、ベース、軽い打楽器を付ける。次に、その音符・強弱・コントローラーが元のままか
報告させ、同じWAVとMIDIを書き出し。

どちらも依頼どおりでした。ストリングスはちょうど9〜16小節（tick 30720から8小節）に入り、先に
作ったパートは不変、ドラムのフェーダーは最終的に −4 dB。手書きトラックはバイト単位で完全一致し、
tick 333 のCC1も残り、6/8と90 BPMも維持されました。ミックスは 34.909 秒と 16.002 秒 ——
それぞれのテンポで16小節ちょうど ——、48 kHz/24bit、フルスケールのサンプルはなく、true peak は
−9.50 と −18.51 dBTP。どちらもプロジェクトを保存せず、トラックIDとクリップIDの取り違えもありません。

<a id="what-the-trials-cost-and-why"></a>
## かかったコストとその理由

| | 呼び出し | 失敗 | 所要 |
| --- | --- | --- | --- |
| A：料理動画ループ、3ターン | 205 | 2（いずれも自己復帰） | 657 秒 |
| B：伴奏、2ターン | 357 | 0 | 552 秒 |
| B再実行（カーブ一覧の追加後） | 92 | 0 | 479 秒 |

**トライアルBの357回のうち258回は、存在しないコントローラーレーンの読み取りでした。** メロディーの
コントローラーが元のままか確認するよう頼まれたとき、クリップがどのレーンを持つかを問う手段がないため、
モデルは全部読みました —— 0から127までのコントローラー番号を2周、さらにベンドも —— 実際に存在する
モジュレーションレーン1本を見つけるためです。呼び出しはすべて成功しており、ツール側に確実を得る
近道がなかっただけです。

答えは `MidiClip::curves` が以前から持っていました。スケジューラとMIDIライタのためのものです。これを
両方の読み取りに載せました。`read_notes` のクリップページはレーンがあるとき `authored_curves` を返し、
`edit_clip_curve` の read も同じ一覧を、自身の `curve` 引数と同じ形で返します。トライアルBを再実行
すると、モデルは1本 —— コントローラー1 —— だけを読んでメロディーの保持を報告しました。357回では
なく92回で、成果物は同じです。

トライアルAの2件の復帰可能な失敗は、どちらも知っていることを言わないメッセージでした。`render` は
operation ではなく素のフィールドを取るツールですが、`tool_help` は
`Unknown operation for render; choose from ` と答えて以降が空でした。いまは operation を取らないと
言います。`完成：ひだまりキッチン16小節` というチェックポイント名は全角コロンのために拒否された一方、
メッセージは許可される文字しか挙げていませんでした。いまは空白と記号が使えないことを和英どちらでも
言います。規則そのものは変えていません —— その名前はファイル名になります。

<a id="left-as-an-observation"></a>
## 所見として残すもの

トライアルAは途中で測定するレンダの置き場所を必要としましたが、未保存のプロジェクトには自分の
フォルダがありません。モデルは `~/Music/Auris Exports/` を選び、会話が終わってもWAV4本とその
マニフェスト、約33 MBをそこに残しました。`preview` はまさにこのためにあり、ドキュメントの preview
フォルダ配下に書きますが、未保存のドキュメントにはそのフォルダがありません。ここに間違いはなく、
変更も提案しません。作業用レンダには durable なパスが必要で、ユーザーの書き出しフォルダは妥当な推測で、
未保存プロジェクトの中間音声をどこに置くかは欠陥ではなく設計上の判断です。

<a id="reproduction"></a>
## 再現

`cargo clippy --workspace --all-targets` と `cargo fmt --all --check` はクリーンです。
`auris-session` と `auris-toolbox` のスイートは通過し、テスト3本を追加しました。カーブ読み取りが
返すレーン一覧、レーンのある場合とない場合の `read_notes` ページ、operation を取らないツールの
ヘルプメッセージです。
