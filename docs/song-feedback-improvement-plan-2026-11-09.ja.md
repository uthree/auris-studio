# 歌メロを1つの型の貼り付けで書かせない ―「限界線を蹴り飛ばせ」の講評から立てた改良プラン

2026年11月9日。AIワークショップで作った「限界線を蹴り飛ばせ」（BPM 180、E minor、153小節）を友人数名に聴いてもらい、講評を受け取った。保存された楽譜と作曲ワーカーのログ（ワークショップのスレッド `song-18e4c4eb3c150254-1102c-1`）を読み、講評の一つひとつを楽譜の数値と照らし合わせた。

講評の大半は、楽譜から数値で確かめられた。歌は28行あるが、音高の並びは4種類、リズムは3種類しかない。28行すべてが小節の頭から入り、主音で終わる行は1つもない。原因は主に2つあると考える。1つめは作曲エージェントへの指示である。そこには「反復するモチーフの音符に歌詞を合わせ、リズムを変えた反復はもうモチーフではない」という趣旨の規則があり、エージェントはこれを4小節の行全体に当てはめた。2つめは、作曲中に使う診断ツールの死角である。行どうしの反復も、リズムも、終止も、セクションごとの和声とドラムも測っておらず、この曲に警告を1件も出さなかった。そこで、指示の書き換えと診断の追加から始め、意外性（情報量）の指標、演奏できるかの検査、評価の仕組みを順に加えることを提案する。

判断してほしい点として挙げた5つのうち4つには、11月9日に回答をもらった（7節）。診断の警告は極端な値のときだけ出し、撥音と連母音は1音にまとめて書けるようにする。参照のデータは東北きりたん歌唱データベースを中心に、ほかの公開データと比べて選ぶ。友人の言う「出せない音」はギターの弦が同時に鳴ることで、楽譜を見直すと、ストラムのずれは人が聞き分けられるずれより小さい値だった（3.6節）。そのあと第1段階から第4段階までを実装し、ログの依頼で2曲作り直して測った（8節）。残る判断は、RWC 研究用音楽データベースの利用を申請するかと、作り直した曲を友人に聴いてもらうかの2つである。

## 1. 講評のほとんどは楽譜の数値で裏付けられる

講評は要約して載せる。数値は保存されたプロジェクトファイル（形式バージョン34、Auris 0.19.0で保存）から数えた。伴奏の密度だけは、作曲ワーカーが作曲の終わりに実行した `arrangement_shape` の出力を使った。

| 講評（要約） | 楽譜とログで確かめたこと |
| --- | --- |
| メロディがどれも同じに聞こえ、型にはまりすぎている | 歌の28行のうち、音高の並びは4種類、リズムは3種類。Aメロは4行とも同じで、サビは4行（最終サビは6行）とも同じ。完全には一致しない2行も、違いは最後の音の長さだけ |
| モーラの割り振りが単調で、4分音符に1モーラ、行末だけ長い形が続く | 歌詞の20種類の行はすべて12モーラで、16行が7＋5、4行が5＋7に切れる。全336音が1音1モーラで、隣り合う発音の間隔の73%がちょうど1拍（333 ms） |
| 耳に残らず、授業で初めて作った曲のように聞こえる | 2節の情報量の測定で、同じ型の2回目以降の予測しやすさが極端に高い。七五調の影響も考えられる（3.5節） |
| リズムが一定で繰り返しがくどい。起承転結がほしい | どのセクションも同じ行の繰り返し（AメロはAAAA、BメロはBB、サビはCCCC）で、途中で役割を変える行がない |
| 上昇するメロディばかりで、どこに落ち着くのか分からない | 28行中22行が、始まりより高い音で終わる。行末の音は、サビ14行が5度（主和音の上）、Aメロ8行とブリッジ2行が短7度（VIIの上）、Bメロ4行が導音（Vの上）。主音で終わる行は0 |
| 打ち込みっぽく、楽器の仕組み上出せない音が出ている（あとで、ギターの弦が全部同時に鳴ることだと分かった） | 和音を弾くギターのストラムは、和音全体で7 ms と10 ms。3音のパワーコードなので、弦と弦のずれは3.5〜5 ms しかない（3.6節） |
| AメロとBメロのメリハリがない | どちらも4分音符中心の4小節フレーズで、1行12音、小節の頭から入る。違いは平均音高（4.4半音高い）とコードだけ。伴奏の密度も1小節あたり20.9音と20.6音でほぼ同じ |
| ドラムがずっと同じ | イントロ、Aメロ1、間奏、間奏2、アウトロの基本パターンが同一。サビではライドとキックが少し変わるだけ |
| コードがずっと同じ。カノン進行のほうがよいという声と、単純でノリやすいという声がある | イントロ、Aメロ、間奏、ブリッジ、アウトロは i–i–VI–VII（Em–Em–C–D）。サビは VI–VII–i–i で、同じ循環の始まりをずらしただけ。違うのは Bメロの iv–VI–VII–V と、あとから足した間奏2の最後の B7 だけ |
| 最後の終わり方はわりと良い | アウトロは冒頭のリフに戻り、主和音の E minor で終止して減衰させている。曲の中で主音に着地するのはここだけ |
| Cメロ（ブリッジ）はわりと良い | 下降から始まる行（E4–D4–B3）は、ブリッジの2行だけ。伴奏の密度は1小節10.4音で、ほかのセクション（20〜38音）の半分以下 |
| 入りがいつも小節の頭なので、シンコペーションを入れるべき | 28行すべてが1拍目から入る。発音336個のうち322個が拍の頭、14個が8分の裏（サビ冒頭の「この」の「の」）。拍の裏で始まって次の拍まで伸びる音は0 |

良いと言われた2か所は、ほかの部分に欠けているものを持っていた。終わり方には主音への着地があり、ブリッジには下降する旋律と薄い伴奏による対比がある。不満の指摘と、良いと言われた点は矛盾していない。

一方で、音から音への動きの統計はふつうだった。同じ音の反復は17.5%、2半音以内の順次進行は61.7%、3半音以上の跳躍は20.8%である。宮内・森勢（2026）が東北きりたん歌唱データベースの日本語ポピュラー曲50曲で数えた値（同音22.3%、順次55.9%、跳躍21.9%）と近い。音域、跳躍、音程の分布を見るいまの診断では、この曲の問題は見えない。問題は、行とセクションの水準での反復とリズムにある。

## 2. 同じ型の2回目以降は、曲自身からほぼ完全に予測できる

次の音がどれだけ予想外だったかを、確率から測る方法がある。それまでの文脈から次の音の確率を予測し、実際に来た音の確率を p として、−log₂ p（ビット）をその音の情報量とする。Pearce の IDyOM はこの考え方の代表的なモデルで、長さの違う文脈を組み合わせて予測する。情報量が低いほど、予想どおりの音である。

曲の頭から1音ずつ予測しては学習する簡易版を、この曲で試した。記号は、前の音からの音程（±12半音で打ち切り）と発音の間隔（16分音符単位）の組である。予測には PPM（エスケープ法C）を使う。4音前までの文脈で予測し、その文脈で見たことのない記号は、より短い文脈に退いて確率を割り当てる方式である。まだ見ていない記号には一様な確率を割り当てるので、初めて出る型の行は約7ビットになる。

| セクション | 行ごとの平均情報量（ビット/音） |
| --- | --- |
| Aメロ1 | 7.44、2.10、0.76、0.49 |
| Bメロ1 | 7.42、2.23 |
| サビ1 | 7.28、2.41、0.76、0.49 |
| Aメロ2 | 1.91、0.38、0.30、0.26 |
| Bメロ2 | 0.94、0.74 |
| サビ2 | 0.71、0.38、0.30、0.26 |
| ブリッジ | 7.07、1.98 |
| 最終サビ | 1.92、0.24、0.21、0.19、0.17、0.16 |

高い値が出るのは、新しい型が初めて出る4行だけだった。Aメロ2から後は、ブリッジの1行目を除いてすべての行が2ビットを下回り、最終サビは0.2ビット前後まで下がる。「繰り返しがくどい」「耳に残らない」という講評は、この平坦さと合っている。この測定は試作で、コーパスから学習した長期のモデルはまだない。試作のスクリプトもリポジトリには入れていない（5節の第1段階で `tools/eval` に入れる）。

## 3. 指示と手順が型の使い回しを促し、診断がそれを見逃した

### 3.1 作曲エージェントへの指示

作曲ワーカーのシステムプロンプトは [musical-design.md](../crates/auris-agent/src/prompts/musical-design.md) にあり、作曲フェーズの指示は [composition_workflows.rs](../crates/auris-toolbox/src/composition_workflows.rs) の `SCORE` にある。どちらにも次の規則がある。

- 反復するモチーフで歌う行は、そのモチーフの音符にぴったり合わせる（"a line sung to a repeated motif must fit that motif's notes exactly"）
- まず言葉を直す（"Adjust the words first"）。リズムを書き換えた反復は、もうモチーフではない（"a repeat whose rhythm is rewritten is no longer the motif"）
- 2つのモーラを1音に詰めない（"Never squeeze two sung moras onto one note"）
- サビは強拍に着地させ、フックで跳躍させる（"land the chorus on a strong beat", "let its hook leap"）
- 作曲フェーズでは、モチーフが繰り返される場所ではどの行も同じ音数で `analyze_lyrics` の fit を確かめ、モチーフより言葉を変える

どれも、過去の講評や試聴で見つかった問題（サビが持ち上がらない、字余り・字足らず）を1つずつ直すために入った規則である。ところが、モチーフをどの長さで捉えるかは書かれていない。この曲の作曲ワーカー（Codex、gpt-6.1-sol）は4小節の行全体をモチーフとして扱い、言葉の側を12モーラにそろえて、同じ音符を全行に置いた。サビの14行は、どれも1拍目の G4 から8分音符の後に D5 へ5度跳び上がって始まる。

ワークショップのディレクターが作曲ワーカーに渡した割り当て文も、同じ規則を書き写していた。書かれていたのは次の4つである。

- 「反復モチーフは歌詞を先に調整して同じ発音タイミングと輪郭を保つ」
- 「1音に複数の歌唱モーラを詰め込まない」
- 「サビ頭を強拍へ着地させる」
- 「5度または6度の印象的な跳躍を置く」

### 3.2 作曲の手順

ログを見ると、作曲ワーカーはまず全11セクションのコードを約1秒で書いた。次に、20種類の歌詞の行すべてを、音数12を指定した `analyze_lyrics` で2回確かめた。そのあと、歌の28行について、クリップを作り、音符を入れ、歌詞を書き込む操作を、開始から94〜101秒の約7秒間に続けて送っている。行ごとに聴き直したり、セクションごとに診断したりした形跡はない。最後に読んだ `melody_shape` と `arrangement_shape` には、どちらも警告がなかった。行の並び（起承転結）を計画する段階も、確かめる段階もなかった。

### 3.3 旋律の指針がワークショップに届いていない

10月26日の講評を受けて、作曲スキルの資料（[melody-design.md](../skills/auris-composition/references/melody-design.md)）には次の指針が入っている。新しいポップの旋律は8分音符を骨格にし、16分は弱起・ターン・応答に選んで入れる。語ごとに同じリズムを与えない。短い核となる音型から始める。

この資料は Codex や Claude Code がスキルとして読み込むもので、作曲ワーカーのプロンプトには含まれない。作曲ワーカーが受け取るのは、システムプロンプト（[core.md](../crates/auris-agent/src/prompts/core.md) と musical-design.md）とフェーズの指示だけである。`search_documentation` が検索する文書にも melody-design.md は入っていない。完成後に編集を頼んだ会話では、エージェントが自分でスキルのファイルを開いて読んでいたが、ワークショップの作曲ワーカーはスキルのファイルも開かず、`search_documentation` も一度も呼ばなかった。作曲ワーカーに届いたのは歌詞を合わせる規則とサビを持ち上げる規則で、リズムの指針は届かなかった。

### 3.4 診断ツールの死角

作曲中に使う診断が測るものは、次のとおりである。

| 診断 | 測るもの |
| --- | --- |
| `melody_shape` | セクションごとの音域、平均音高、跳躍の数、最大の音程、サビの持ち上がり、イントロとアウトロの長さ |
| `arrangement_shape` | セクションごとの鳴っているパート、1小節あたりの音数、パートごとの異なる小節の数、サビ前のフィルの有無、イントロとアウトロの長さ |
| `lint_project` | 調にも和音にもない保持音、低音域の濁り、重なり、歌詞のない歌の音など |

どの診断も測っていないのは、旋律では行どうしの反復、入りの位置、シンコペーション、行末の音であり、伴奏ではセクションごとのコード進行とドラムのパターンである。作曲ワーカーは警告をすべて解消してから作曲を終えたが、それは測っている項目だけを満たした状態だった。

### 3.5 歌詞の仕組みも同じ方向に働く

七五調は、明治以降の唱歌・寮歌・軍歌に多く、いまも校歌に多く使われる。同じ七五調の歌詞は、別の七五調の曲に合わせて歌っても、おおむね違和感がない（コトバンク「七五調」）。12モーラの七五調の行に、ほぼ同じ長さの音を1モーラずつ当てていく書き方は、唱歌や校歌の節付けに近いと考える。「授業で初めて作った曲」という印象の一因はここにあると推定するが、確かめてはいない。

旋律の反復と歌詞の反復の関係も逆になっている。ReLyMe（Zhang ほか、2022）は、歌詞の反復の構造を旋律の反復に映すことを、歌詞から旋律を作るときの原則の1つとして扱った。この曲では、Aメロの4行の歌詞はすべて違うのに、旋律は4行とも同じである。

歌詞の道具も、同じ旋律に別の言葉を合わせる使い方を前提にしている。`analyze_lyrics` の fit は指定した音数に合うかを返し、`repair_lyrics` は、参照の行とモーラの数や区切りの位置がそろう言葉の候補を選ぶ。歌声合成の VOICEVOX は1音に1モーラしか受け付けず、Auris で前のモーラと同じ音にまとめられるのは長音（ー）と促音（っ）だけである。宮内・森勢（2026）は50曲の歌詞と音符を対応づける際、1音符1モーラを原則としつつ、2モーラ目が促音・長音・撥音・母音のときに1音符へ2モーラを割り当てる例外を設けている。撥音（ん）と連母音（あい）を1音にまとめる書き方は、いまの Auris ではできない。

### 3.6 「出せない音」は、ストラムのずれが小さすぎて弦が同時に鳴ることだった

友人の指摘は、おそらくギターについてのものだった。手で弾けば弦は少しずつずれて鳴るのに、全部の弦が同時に鳴っている、という趣旨である。楽譜を見直すと、和音を弾くギターのクリップにはすべて、弦を順にずらして鳴らすストラムの段が入っていた。問題はその値である。

| トラック | ずらす時間（最初の弦から最後の弦まで） | 向き |
| --- | --- | --- |
| Open power L | 7 ms | いつも低音弦から |
| Open power R | 10 ms | 8分ごとにダウンとアップを交互 |

Auris のストラム（[strum.rs](../crates/auris-core/src/project/strum.rs)）は、指定した時間を和音の音に等間隔で割り振る。この曲のパワーコードは3音なので、弦と弦のずれは3.5〜5 ms になる。D'Amario ほか（2019）がまとめた先行研究によると、2つの音のどちらが先かを聞き分けられるずれは、よく訓練した聴き手でも15〜20 ms である。続けて鳴る2つの音は、音楽のような複雑な音なら、40 ms までのずれでも1つに溶け合って聞こえることがあるという。和音全体を7〜10 ms でずらしても、ストラムとしては聞こえないと考える。

小さな値の出どころは、ログから分かる。ロック用の演奏プリセット rock_rhythm_guitar のストラムは14 ms で、ストラムの既定値は20 ms である。作曲ワーカーはプリセットを使わずに8 ms を指定し、完成後の編集で「打ち込みっぽさをなくして」と頼まれたエージェントが、7 ms と10 ms に設定した。加えて、いまのストラムでは、どの和音も同じずれ方で鳴る。ずれが聞こえる値にしても、毎回まったく同じ鳴り方になる。

Fluid R3 GM の音色を使ったことは原因から外す。利用者は、内蔵の音源よりサウンドフォントのほうが良い音だと判断している。楽譜のほかの点も確かめたが、ドラムには3本以上の手が同時に要る打点も、オープンとクローズのハイハットが同時に鳴る打点もない。音域はギターが E2〜D5、ベースが E1〜G2 で、どちらも標準調弦の範囲に収まる。

今回の指摘とは別に、次の点も不自然に聞こえる可能性がある。

- 合成した効果音。演奏前の機材の起動音（ノイズのクリック）と、ピッチベンドで −5 から +12 半音まで上げるノイズのライザー
- 18〜28 ms しかないベースとギターのゴーストノート
- 主旋律と上下のハモリの3トラックが、いまのファイルではすべて同じ話者（春日部つむぎ）であること

## 4. 改良プラン

7つの作業に分けた。中心は4.1の指示の書き換えと4.2の診断の追加で、残りはその効果を測るか、範囲を広げる作業である。

### 4.1 作曲エージェントへの指示と手順を書き換える

対象は musical-design.md、composition_workflows.rs の `SCORE` と `ARRANGEMENT`、ワークショップのディレクターへの指示である。次の変更を提案する。

- モチーフを「2〜6音、1拍から2小節ほどの短い単位」と定義し、行全体ではないと書く。完全な反復はフック（タイトルの句など）とサビの繰り返しに限る。ほかの行では、頭の音型を残して後半のリズム、音高、音域を変える。「リズムを書き換えた反復はもうモチーフではない」という一文は削るか、フックだけに限る。
- 音符を書く前に、セクションごとに行の役割を決めて `production_record` に残させる。4行のセクションなら、提示、反復と変化、転換、着地という起承転結の形を基本形の1つとして示す。Aメロなら a a' b c、Bメロは行の長さかリズムを変える、サビはフック、応答、頂点、着地、のように例を添える。
- セクションごとに入り方とリズムの密度を選ばせる。入り方には、前の小節から入る弱起、拍の頭、遅れて入る、の3つがある。サビの頭やキーワードでは、強拍の8分か16分前から入って拍をまたぐ食いを候補として示す。Tan ほか（2019）は、ロックの旋律で強勢のある音が強拍の直前に来る先取りのシンコペーションを、聴き手が拍にそろった形をずらしたものとして捉えると論じている。この見方に立てば、食いは拍との対応を崩さずにリズムを変える手段になる。BPM 180 なら、Aメロは8分中心で語るように、Bメロは長い音で溜める、のように差をつける。
- 行ごとに終わりの音を計画させる。2・5・7度で終わる開いた行と、1・3度で終わる閉じた行を対にする。最終サビの最後の行は、理由がない限り主音に着地させる。下降する行や山型の行も書かせる。
- 歌詞の行の長さをそろえさせない。全行を七五調にするのは、唱歌風を狙うときだけにする。
- 旋律を1セクション書くたびに、4.2の診断を読んで直させる。全セクションの旋律をまとめて書いてから確かめる手順をやめる。
- melody-design.md にある、8分を骨格にして16分を選んで入れる指針と、語ごとに同じリズムを与えない指針を、作曲ワーカーが必ず読む musical-design.md か `SCORE` の指示に移す。この曲では `search_documentation` が呼ばれなかったので、検索できる場所に置くだけでは届かない。
- ディレクターには、作曲の規則を割り当て文に書き写させず、セクションごとの意図を書かせる。たとえば、Aメロは語るように、Bメロは長い音で溜め、サビで一気に解き放つ、のような書き方である。

指示は長くなる。作曲の質をフロンティアモデルで上げることを優先する方針なので、プロンプトの長さに `auris-agent` のテストが設けている上限は引き上げてよい。同じ内容を2か所に書くことだけは避ける。

確かめ方として、この曲の依頼文（「BPM 180くらいの激しいロックっぽい感じの歌を一気に作って。」）をワークショップのログから再実行し、変更前と変更後で3曲ずつ作る。バックエンドとモデルは同じ Codex と gpt-6.1-sol にそろえ、4.2の指標と、歌もの全体を採点する学習済みモデル SAE（`tools/eval/song_aesthetics.py`）の Arrange 軸を比べる。PC への負荷を考えて、1曲ずつ順に実行する。

### 4.2 診断ツールに、行・リズム・終止・和声・ドラムの観点を加える

`melody_shape` に次の出力を加える。警告は、この曲のような極端な値のときだけ出す。

| 足す出力 | この曲の値 | 警告を出す例 |
| --- | --- | --- |
| セクションごとの行の並び（A A' B C の形） | AメロはAAAA、サビはCCCC | セクションの全行が、音高もリズムも同じ |
| 異なる行の数 | 28行中6行（最後の音の長さの違いを除くと4行） | — |
| 行の入りの位置（拍の頭、弱起、遅れ） | 28行すべてが1拍目 | 全行が同じ位置から入る |
| 裏拍の発音の割合、シンコペーションの量、食いの数 | 裏拍4.2%、拍をまたぐ音0、食い0 | 歌全体でシンコペーションが0 |
| 発音の間隔（モーラの間隔）の分布 | 1拍が73% | 1つの音価が大半を占める |
| 行末の音度とその下の和音 | 主音で終わる行が28行中0 | 一度も主音に着地しない |
| 行の輪郭の型 | Aメロが上行、サビとBメロが山型、ブリッジが谷型 | 全行が同じ型 |

シンコペーションの量には、`auris_compose::metrics::syncopation` が実装している Longuet-Higgins と Lee の指標をそのまま使える。行の輪郭の型は、Huron（1996）の分類のように、行の最初の音、途中の音の平均、最後の音の高低で決める。この分類は、旋律の輪郭が本当にこの型に分かれるのかを疑う研究もある（Cornelissen ほか、2026、査読前）。そのため、輪郭の型は警告には使わず、参考の出力にとどめる。

`arrangement_shape` か新しい和声の診断には、次の出力を加える。

- セクションごとのコード進行と、コードが変わる間隔。始まりをずらしただけの同じ循環も同一とみなす（この曲ではサビが Aメロと同じ循環になる）
- セクションの終わりの終止の種類（V–i、VII–i、偽終止など）
- ドラムの基本パターンがどのセクションと同じか（この曲ではイントロ、Aメロ1、間奏、間奏2、アウトロが同一）
- フィルが4・8・16小節の切れ目のどこに入っているか
- 隣り合うセクションの比較表。モーラの密度、行の長さ、入りの位置、音域、コードの変わる間隔、伴奏の密度、ドラムのパターンを並べる（この曲の Aメロ→Bメロは、音域とコードだけが違う）。サビをほかのセクションと区別する計算可能な特徴を、Billboard のデータで調べた研究（Van Balen ほか、2013）も、比べる項目を選ぶ参考になる

警告は極端な値のときだけ出す。11月9日に、この方針で進めることが決まった。どの警告も、理由を `production_record` に書けば残せるようにする。`lint_project` の警告と同じ扱いである。休符の最低割合や変形の回数のような合格条件にはしない。この方針は [melody-domain-evaluation.md](melody-domain-evaluation.md) の考え方と同じだ。警告を出す境目は、4.7の参照の統計で決める。テストは、この曲の極端さを再現した小さな合成の曲を作り、数値で確かめる。

### 4.3 意外性（情報量）の指標を作る

2節の試作を、2種類のモデルに分けて作る。曲の中だけで学習する短期のモデルは、繰り返しのくどさを測る。情報量の低い行が何行続くかを出す。コーパスが要らないので、Auris 本体の診断に入れられる。コーパスで学習する長期のモデルは、ジャンルの中でのありきたりさを測る。こちらはまず `tools/eval` の開発用ツールにし、Python の既存実装（IDyOMpy など）も候補にする。予測に使う観点は、IDyOM と同じように、音程、音度、発音の間隔、拍の中の位置を別々に、または組み合わせて使う。

この指標は最大化しない。Cheung ほか（2019）は、ビルボードの曲のコード進行を使って、聴き手の快を調べた。快が高かったのは、予測の不確かさが低い文脈で予想外の和音が来るときと、不確かさが高い文脈で予想どおりの和音が来るときだった。旋律でも、予測しやすい文脈を作ったうえで、サビの頭、タイトルの語、転の行のような要所に驚きがあるかを見る。Jakubowski ほか（2017）は、頭に残りやすい曲は、全体の輪郭がありふれている一方で、旋律の上下が折り返す点どうしを結んだ平均の傾きは珍しい傾向があると報告している。そこで、行の輪郭がどれだけありふれているかと、局所の音程の情報量を分けて出す。和声の情報量（Cheung ほかの方法）は後回しにする。

長期のモデルの学習と、4.2の警告の境目を決める統計には、参照のデータが要る。東北きりたん歌唱データベースを中心にする方針が決まったので、ほかの公開データと並べて比べた。利用の条件は、ACE-Opencpop と ACE-KiSing の論文の比較表と、各データの公開ページの記述による。

### 4.4 歌詞と旋律の対応を広げる

- `analyze_lyrics` の fit が、音数が合うかどうかだけでなく、旋律の側を変える案も返すようにする。弱起の音を足す、長い音を2つに割る、2音を1つにまとめる、の3種類である。`repair_lyrics` は、フックの反復を守るために残す。
- 撥音と連母音を、楽譜上で1音にまとめて書けるようにする（11月9日に決定）。VOICEVOX に送るときに2つの短い音へ分ける。分ける長さの比と、発音が自然に聞こえるかは、試して決める。
- 1つのモーラを音高を変えながら伸ばすメリスマを、長音（ー）の音で書けることを指示に書く。いまの仕組みでも書けるが指示にはなく、この曲では「こどー」「むこー」のように、歌詞にもともと長音がある箇所にしか現れない。
- 単語のアクセントと旋律の向きの食い違いを、情報として報告する。auris-vocal にはすでに、Orpheus（深山ほか、2013）と同じ考え方でアクセント句を分析する [accent.rs](../crates/auris-vocal/src/accent.rs) がある。規則にはしない。

### 4.5 セクションごとに和声とドラムを設計させる

和声は、Aメロの単純な循環を残す。単純でノリやすいという声もあったからだ。Bメロでは、機能か、コードの変わる間隔を変える。iv–v–VI–VII や、ベースが半音ずつ下がる進行（クリシェ）が候補になる。サビでは別の進行を試す。G major から見た王道進行（IV–V–iii–vi）にあたる C–D–Bm–Em や、友人が挙げたカノン進行（G–D–Em–Bm–C–G–C–D）がその例である。どれも聴き比べる候補で、規則ではない。

ドラムは、セクションごとに基本パターンを決めさせる。Aメロ1は薄くし、Aメロ2で16分のハイハットやスネアのゴーストを足す。Bメロはハーフタイムかタム中心、サビはライドかクラッシュの8分とキックの変化で開く。BPM 180 ならツービートも候補になる。ブリッジはハーフタイムにし、最終サビをいちばん厚くする。フィルは4小節ごとに小さく、8小節で中くらいにし、サビの前で最大にする。キメはリフや歌のアクセントに合わせる。これらを `ARRANGEMENT` の指示と [composition-techniques.md](composition-techniques.md) に書き、4.2の診断で確かめる。

### 4.6 演奏の自然さと、演奏できるかを確かめる

友人の指摘したギターの弦の鳴り方は、いまの「演奏」の機能で直せる。次の4つを提案する。

- 作曲の指示で、和音を弾くギターには演奏プリセット（ロックなら rock_rhythm_guitar）を適用してから調整させる。ストラムの合計は、聞き分けられるずれ（15〜20 ms）より小さくしないよう書き、プリセットの14 ms と既定の20 ms を下限の目安にする。
- ストラムの段に、和音ごとのばらつきを加える。いまは毎回同じ等間隔のずれなので、ずれの合計と弦ごとの間隔を、シードつきで和音ごとに少しずつ変える。Câmara ほか（2024）は、ギタリストが拍より遅らせて弾くと打弦が遅く、動きの時間が長くなり、音の立ち上がりも長くなると報告している。そこで、ベロシティの弱い和音や後ろにずらした和音ほど、ずれを長くする案を試す。
- ずれを、和音全体の時間だけでなく弦1本あたりの時間でも指定できるようにする。いまの spread_ms は最初から最後の弦までの合計なので、3音の和音も6音の和音も同じ時間で鳴る。
- 和音を弾くギターにストラムがないときや、合計のずれが聞き分けられないほど小さいときに、`lint_project` で警告する。警告は極端な値のときだけ出す。`inspect_performance` も、実際にずれた時間を ms で返すようにする。

演奏できるかの検査は、`lint_project` の規則として追加する。ギターでは、弦とフレットの割り当てを動的計画法で探す。MIDI からタブ譜を作る研究で標準になっている方法である。楽器ごとに確かめる点は次のとおり。

- ギターは、6本を超える同時発音、同じ弦の同時発音、指が届かないフレットの幅、テンポに間に合わないポジションの移動を報告する。チョーキングの幅と、ナチュラル・ハーモニクスの出る音高も確かめる
- ベースは、弦の数と最低音を見る
- ドラムは、同時に要る手足の数（手2本、足2本まで）、オープンとクローズのハイハットの同時発音、片手で連打する速さを見る
- 歌は、息継ぎなしで歌い続ける長さと、高い音に留まる長さを見る

この曲のドラムでは、同時に要る手の数とハイハットの同時発音の検査で問題は見つからなかった。

打ち込みっぽさは、音源を替えずに演奏の書き方で減らす。歌の336音はすべてベロシティ0.82で、VOICEVOX の経路ではベロシティが音量に反映される。フレーズごとに強弱をつけ、セクションごとにも、Aメロは弱く、サビは強くする。ハイハットは拍の頭で強め、ギターはダウンとアップで強さを変える。Auris の揺らぎは、4拍と1拍の滑らかな成分に小さな独立の成分を重ねて作っている。Hennig ほか（2011）は、人が演奏するときのタイミングの揺らぎには長い時間にわたる相関があり、聴き手もそういう揺らぎを好むと報告した。フレーズやセクションの長さの成分を加えると良くなるかを試す。

サウンドフォントでは、音の長さは主に音符の長さで決まる。`ARRANGEMENT` の指示には、音の長さを奏法に合わせる書き方を加える。撥弦楽器では和音の切れ目で消音し、パームミュートは短いゲートと弱いベロシティで書き、シンバルはチョークで止める。

### 4.7 評価の仕組みを整える

講評を項目の一覧にして、作曲の指示や診断を変えるたびに同じ項目で測る。1節の表がそのまま使える。

学習済みの評価器 SAE は、10秒の区間を5秒ずつずらしながら採点する。BPM 180 の10秒は約7.5小節で、1つの区間には歌の行が2行ほどしか入らない。区間どうしを比べないので、同じ旋律の行を曲全体で何度も繰り返していることは、点数に直接は表れない。行とセクションの水準の評価は、4.2と4.3の指標に任せる。SAE の Arrange 軸は、伴奏が悪くなっていないかを確かめるために使う。

4.2の指標を4.3のコーパスで計算し、極端な値の境目を決める。市販曲それぞれの結果はリポジトリに入れず、平均と散らばりだけを書く。

改良したあと、同じ依頼で作った曲を同じ友人に聴いてもらう。今回の講評と同じく、旋律の変化、譜割り、リズム、AメロとBメロの対比、コード、ドラム、自然さ、終わり方について、時刻つきで書いてもらう。

## 5. 進める順序

順序は、作業どうしの依存関係から決めた。

第1段階では、4.1の指示の書き換えと、2節の試作を `tools/eval` の測定スクリプトにする作業を同時に進める。測定スクリプトがないと、指示を変えた前後を比べられないからだ。4.6のストラムの見直しもここで行う。変更が小さく、友人の指摘に直接対応するからである。

第2段階では、4.2の診断を Rust で実装し、作曲ワーカーに読ませる。4.1の指示から4.2の警告を参照させ、ログの依頼を再実行して比べる。

第3段階では、4.3の短期のモデルを本体に、長期のモデルを開発用ツールに入れる。4.4の「1音に2モーラ」と fit の拡張、4.5の指示と診断もここで行う。

第4段階で、4.6のうちストラム以外の、演奏できるかの検査と演奏表現を進め、4.7の2回目の講評を行う。

## 6. 指標を目標にしないよう気をつける

「限界線を蹴り飛ばせ」は、以前の講評から入った規則（サビの持ち上げ、跳躍、8小節以上のイントロとアウトロ）をすべて満たしたうえで、単調になった。新しい指標も、最大化させれば別の型を生む。警告は極端な値に限り、理由があれば残せるようにする。ファンクのドラムブレイクを使った実験では、シンコペーションの量と、体を動かしたくなる度合いや快との関係は逆U字型で、中くらいがいちばん好まれた（Witek ほか、2014）。シンコペーションも多いほど良いわけではない。

変化を増やしすぎると、何がフックか分からなくなる。完全な反復は、フックとサビに残す。

コーパスの権利にも注意する。市販の曲の採譜と統計は手元でだけ扱う。VOICEVOX は1音1モーラの合成器なので、2モーラをまとめた音や速い16分の連続を送ったときの発音は、実際に合成して確かめる。

## 7. 決まったことと、残る判断

11月9日に、次の4点が決まった。

- 診断の警告は、極端な値のときだけ出す（4.2節）
- 撥音と連母音を、楽譜上で1音にまとめて書けるようにする（4.4節）
- 参照のデータは東北きりたん歌唱データベースを中心にし、ほかの公開データと比べて選ぶ（4.3節）
- 友人の言う「出せない音」はおそらくギターで、弦が全部同時に鳴ることを指していた。「演奏」の機能で直す（3.6節、4.6節）

あとで出た判断は次の2つである。

1. 第1段階から始めてよいか。11月9日に承認され、第4段階まで進めた（8節）。
2. RWC 研究用音楽データベースの利用を申請するか。申請しないことになった。長期のモデルを作るなら、自由に入手できるデータを使う。

友人に聴いてもらえるのは不定期なので、2回目の講評は計画の手順に入れない。調整は、SAE と SongEval などの自動評価と楽譜の指標で続ける（9節）。

## 9. 自動評価で調整を続けた結果（11月9日）

7節の方針を受けて、自動評価を頼りに調整を続けた。分かったのは、SAE が反応するのは曲の違いと、音量とサンプリング周波数だけで、ミックスや歌い方の細かな調整には反応しないことである。

### 48 kHz で測り直すと、作り直しの差は1点以内だった

8節の評価器の値は、ワークショップの試聴音源から測っていた。試聴音源は 22.05 kHz で書き出されていて、同じプロジェクトを 48 kHz で書き出した音源より、SAE が Overall で約3点、Singing と AudioQ で5〜6点低く出る。3曲を `auris render` で 48 kHz に書き出し直し、-14 LUFS のまま測った。

| 曲 | Overall | Singing | Melody | Arrange | AudioQ |
| --- | --- | --- | --- | --- | --- |
| 変更前（ワークショップの候補1） | 72.8 | 73.4 | 79.5 | 80.3 | 77.0 |
| 作り直し1 | 72.0 | 72.7 | 78.6 | 80.8 | 75.8 |
| 作り直し2 | 71.8 | 73.2 | 79.3 | 81.3 | 77.0 |
| 市販の36曲を -14 LUFS にそろえた平均 | 81.4 | 80.2 | 82.6 | 84.5 | 83.2 |

変更前と作り直しの差は、どの軸も1点以内である。8節で見えた Arrange の上がり（74.4から77.8）は、試聴音源で測ったために大きく見えていた。楽譜の指標では型の使い回しが大きく減ったが、SAE にはその差が表れない。

市販の曲は、マスターの音量（約 -8 LUFS）のまま採点すると Overall の平均が83.6で、-14 LUFS にそろえると81.4に下がった。音量をそろえても、Auris の曲との差は Overall で約9点残る。差が大きいのは Singing（約7点）と AudioQ（約6点）で、Melody と Arrange の差は3〜4点である。

### ミックスと歌い方を変えても、SAE はほとんど動かない

作曲のばらつきを除くため、同じ曲のミックスと演奏だけを変えた版を書き出して比べた。断りのない版は、-14 LUFS にそろえている。

- 音量を上げると点が上がった。リミッターへの入力を4 dB 上げて -10.7 LUFS にすると、2曲とも Overall が2.0〜2.6点、AudioQ が約2点上がった。ただし、同じ処理のあとで -14 LUFS に戻すと、上がりは消えた。点を上げたのは密度ではなく、音量そのものである。
- 歌の音量を±3 dB 変える、リバーブの送りを増やすといった変更では、点はほとんど動かなかった。この2つは音量をそろえずに測ったが、曲全体の音量の変化は1 LU 未満だった。
- 3曲で次の5つの変更を試した。どれも Melody、Arrange、Singing の動きは0.5点未満だった。
  - マスターにまとめのコンプレッサーをかける
  - ギターの高域を出す
  - 歌にディレイをかける
  - ドラムとベースを2 dB 上げる
  - リミッターに深くかけてから音量を戻す
- Overall は最大2点動いたが、同じ変更でも曲によって向きが違った。ドラムとベースを上げると、AudioQ は3曲とも0.5〜0.7点上がった。ただ、この幅は歌わせ直しによるばらつき（AudioQ で0.4点）と変わらないので、既定の値は変えていない。
- 3曲とも、歌の音符にビブラートが1つもなかった。そこで、2曲の0.5秒以上の音符（30音と49音）に深さ0.2と0.35半音のビブラートを付け、VOICEVOX で歌わせ直した。SAE の Singing の差は0.1点以内で、同じシードで歌わせ直しただけの版と変わらなかった。

ミックスや歌い方の細かな調整を、SAE の点で選ぶことはできない。

### 評価器は日本語の歌で学習していない

調べた範囲では、SongEval（英語と中国語）、SAE（SongEval のデータと中国語の曲）、Audiobox、TuneJury、MuQ のどれも、日本語の歌を学習データに含んでいない。詳しくは `docs/evaluation.ja.md` に書いた。SAE の Singing と Melody には中国語のポップスでの好みが入っているので、日本語の歌詞の自然さやモーラの割り振りは、楽譜側の指標で判断する。インストの曲では SAE が使えないので、SongEval を主な参考にする。

### 作曲の指示を外すと、依頼に長さと構成がなければ曲が完成しない

作曲の指示が役に立っているかを確かめるため、指示を外した条件を作った。`workshop_trial` に `AURIS_TRIAL_GUIDANCE=bare` を付けると、作曲エージェントが受け取るのは、ユーザーの発言とツールの使い方だけになる。ディレクターの指示、フェーズとその指示、技法のドキュメント、lint と構成のチェックによる差し戻しは渡さない。「BPM 180くらいの激しいロックっぽい感じの歌を一気に作って。」という依頼で、指示なしの条件で4曲、通常の条件で2曲を作った。作曲エージェントは、どちらも claude sonnet である。

| 条件 | 長さ | 作曲時間 | SAE Overall | Arrange | AudioQ | Audiobox PQ | Audiobox CE |
|---|---|---|---|---|---|---|---|
| 指示なし（4曲の平均） | 21〜43秒 | 1.5〜3分 | 73.4 | 81.1 | 76.2 | 6.75 | 5.91 |
| 指示なし、依頼に長さと構成あり（4曲の平均） | 2分47秒〜2分57秒 | 3〜6分 | 71.7 | 79.7 | 75.5 | 7.19 | 6.14 |
| 通常（2曲の平均） | 3分3秒 | 15〜16分 | 70.4 | 81.0 | 74.8 | 7.18 | 6.67 |

指示なしの4曲は、ドラム・ベース・ギター・歌の4トラックで、エフェクトもリミッターもなく、書き出しは約 -6 LUFS だった。どれも1分に満たず、曲としては完成していない。それでも、-14 LUFS にそろえると、SAE はこれらを完成曲と同じか、それより高く採点した。SAE は区間ごとの点を平均するので、曲の長さや構成の展開を見ていない。Audiobox は完成曲を高く採点し、SongEval は2曲の完成曲のうち1曲だけを高く採点した。

依頼に長さと構成を書き足して、指示なしの条件でもう4曲を作った。書き足したのは「長さは3分くらいで、イントロ、Aメロ、Bメロ、サビを2回まわして、ブリッジ、最後のサビ、アウトロで締める構成。ミックスまで仕上げて。」である。今度は4曲とも3分近い完成曲になり、マスターにエフェクトが入って、書き出しも約 -14 LUFS だった。表の3行目がその結果である。

この条件と通常の条件の差は小さい。SAE の Arrange は通常の条件より1.3点低く、Audiobox の CE は0.5低い。Audiobox の PQ は同じだった。SongEval は5軸のうち4軸で指示なしのほうが高いが、日本語の歌では当てにならない（前の節）。通常の条件は2曲しかないので、この程度の差は曲ごとのばらつきと区別できない。

はっきり違ったのは lint の警告と作曲時間である。lint の警告は、指示なしの曲では1曲あたり2〜11件残った（平均5件）。通常の条件では2曲とも0件だった。ただし、指示なしの条件は差し戻しをしないので、この差には指示の効果と差し戻しの効果が混ざっている。作曲時間は、指示なしが3〜6分、通常が15〜16分だった。

このベースラインから言えるのは、学習済みの評価器で測れる範囲では、通常の条件がはっきり上回ったのは lint の警告の少なさだけだということだ。依頼に長さと構成が書いてあれば、指示がなくても曲は完成する。書いていない依頼で曲を完成させているのは、指示である。音の良し悪しを比べるときは、まず曲の長さ・構成・ミックスがあるかを確かめる。そのうえで、楽譜側の指標（melody_shape、arrangement_shape）でも比べる必要がある。

楽譜側の指標で比べると、指示の効果ははっきり表れた。`song_shapes` の例で10曲を測った結果が次の表である。伴奏のパート数は歌を除いた数、シンコペーションは拍の裏から入って次の拍にかかる音の割合である。

| 条件 | 長さ（小節） | 伴奏のパート | arrangement_shape の警告 | melody_shape の警告 | シンコペーション |
|---|---|---|---|---|---|
| 指示なし（依頼文そのまま） | 16〜32 | 3 | 2（4曲とも同じ） | 測れない | 測れない |
| 指示なし（長さと構成を書き足した依頼） | 124〜132 | 3〜4 | 2〜7（平均5） | 3〜7（平均4.5） | 4曲とも0% |
| 通常 | 135 | 5 | 0と1 | 6と2 | 7%と5% |

依頼文そのままの4曲は、セクションに名前がないので melody_shape が測れなかった。arrangement_shape の警告は、4曲ともイントロとアウトロが短いという2件である。

長さと構成を書き足した依頼の4曲には、指示が防ごうとしている書き方がそのまま出た。
- 3曲で、どのセクションも同じパートが鳴っていて、サビで厚くならない。残る1曲も、サビが前のセクションより厚くなっていない
- 2曲で、サビとBメロが Aメロのコード進行をそのまま繰り返している
- 4曲とも、拍の裏から入って拍をまたぐ音が1つもない
- 3曲で、歌の音の72〜100%が四分音符の間隔で並んでいる
- 2曲で、サビやBメロが順次進行だけで、4度以上の跳躍がない

通常の2曲では、これらの警告は出なかった。ただし通常の2曲にも、すべての行が小節の頭から入る、歌の音の74%が八分音符の間隔で並ぶ、という警告は残っている。この2つは、指示があっても直っていない弱点である。

学習済みの評価器は、この差をほとんど見ていない。SAE の Arrange の差は1.3点で、曲ごとのばらつきと区別できなかった。作曲の指示を変えたときの良し悪しは、楽譜側の指標で判断する。学習済みの評価器は、音の仕上がりが大きく崩れていないかを見るために使う。

### 残った2つの弱点を、差し戻しで直させた

指示はもともと、行の入りと音価を変えるように書いていたが、通常の2曲はそれを守らなかった。そこで、`melody_shape` のリズムの警告を作曲フェーズのチェック `melody_rhythm_varied` にした。対象は、すべての行が小節の同じ位置から入る、シンコペーションがない、すべての行の音数が同じ、大半の音が同じ間隔で並ぶ、の4つである。完成と報告した曲にこれが残っていれば、ほかの構成のチェックと同じく差し戻す。

同じ依頼で通常の条件の曲を2曲作ると、2曲とも1回差し戻され、リズムの警告は消えた。行の入りは、2曲とも小節の頭と1拍目の裏の2種類になった。シンコペーションの割合は22%と5%だった。前の2曲は7%と5%である。作曲時間は15〜16分から20〜22分に延びた。

| 条件 | SAE Overall | Singing | Melody | Arrange | AudioQ | Audiobox PQ | CE |
|---|---|---|---|---|---|---|---|
| 変更前（2曲の平均） | 70.4 | 72.1 | 78.7 | 81.0 | 74.8 | 7.18 | 6.67 |
| 変更後（2曲の平均） | 71.3 | 70.6 | 77.7 | 81.2 | 74.7 | 7.48 | 6.60 |

学習済みの評価器の差は、どれも曲ごとのばらつきの範囲で、大きく崩れたところはない。SAE の Singing は1.5点下がったが、そのうち1曲が69.3と低いためで、2曲では判断できない。

代わりに、別の警告が2曲とも出た。予測しやすい行が8行と15行続く、つまり前に出た旋律が変わらずに戻ってくる、という melody_shape の警告である。1曲は、2番の旋律が1番と同じだと自分で記録していた。2番を1番の繰り返しにしない指示はすでにあるので、これも次の候補になる。

### 2番の写しも差し戻しで直させた

リズムを直した2曲には、前に出た旋律がそのまま戻ってくるという警告が出ていた。この警告は、予測しやすい行が4行続くと出していた。中身を見ると、その大半はサビの繰り返しで、フックとしては正しい書き方だった。問題だったのは、2番のAメロが1番を音符ごと写していることのほうである。8曲を測ると、6曲がそうなっていた。

そこで警告を作り直した。サビ以外のセクションが、前のセクションの行を音の高さとリズムまで同じに歌い直したときだけ出す。この警告をリズムの警告と同じ作曲フェーズのチェックに入れ、チェックの名前を `melody_develops` に改めた。作曲フェーズの指示には、2番は1番のモチーフを使い、音符は写さず、新しい歌詞のモーラ数に合わせて行の後半を変えるように書いた。

同じ依頼で2曲作り直すと、2曲とも2番のAメロは1番と違う行になった。1曲目の行の形は、1番が A B C D E F、2番が A' B' J B'' F' である。差し戻しは1回と2回だった。

| 条件 | SAE Overall | Singing | Melody | Arrange | AudioQ | Audiobox PQ | CE |
|---|---|---|---|---|---|---|---|
| リズムを直した後（2曲の平均） | 71.3 | 70.6 | 77.7 | 81.2 | 74.7 | 7.48 | 6.60 |
| 2番を直した後（2曲の平均） | 71.0 | 71.9 | 78.5 | 81.0 | 75.1 | 7.35 | 6.77 |

学習済みの評価器の差は、ここでも曲ごとのばらつきの範囲に収まった。

### 見送っていた項目のうち、5つを入れた

8節で見送った項目のうち、次の5つを入れた。ストラム以外は、8曲以上の試作曲で測ってから入れている。

- **アクセントの食い違い**（4.4）：`melody_shape` に、歌詞の東京式アクセントと旋律の上下が食い違う箇所の報告を加えた。クリップの歌詞を辞書で読み直し、音素で音符と対応させて数える。警告ではなく情報として出す。8曲では、確かめた上下のうち36〜59%がアクセントと逆向きだった。偶然に上下させた場合と変わらない水準で、作曲エージェントはアクセントを見ていない。作曲フェーズの指示に、フック以外ではアクセントに従うように書いた。
- **ドラムの強弱**（4.6）：`arrangement_shape` に、ドラムの平均ベロシティがセクションどうしで0.04未満しか違わないときの警告を加えた。8曲のうち6曲で、ドラムはイントロから最後のサビまで0.55前後のままだった。編曲の指示に、Aメロとブリッジを弱く、サビを強く、最後のサビをいちばん強くするように書いた。歌の強弱は、すでにセクションごとに付いていた（Aメロ0.8前後、サビ0.97前後）。
- **押さえられない和音**（4.6）：ギターの和音を、標準調弦の6本の弦に1音ずつ、開放弦を除いて4フレットの幅に収められるかを調べる lint の規則 `unfrettable_chord` を加えた。11曲を調べると、該当する和音はなかった。作曲エージェントは、パワーコードのように押さえられる形で書いている。
- **セクション末の終止**（4.2）：`arrangement_shape` の各セクションに、最後の2つのコードから終止の種類を付けた。V→I の完全終止、IV→I の変格終止、VII→I、V→vi の偽終止、V で止まる半終止などである。報告だけで、警告は出さない。
- **強さによるストラムの長さ**（4.6）：弱く弾いた和音ほど、弦を掃く時間を長くした。ばらつきが0.3のとき、ベロシティ0.5の和音は0.8の和音より9%長く、1.0の和音は6%短く掃く。新しい設定は足さず、既存のばらつきに連動させたので、ばらつきが0なら今までどおりすべての和音が同じに鳴る。

### 長期のモデルを開発用ツールに入れた

4.3の長期のモデルを `tools/eval/melody_corpus.py` に入れた。短期のモデルと同じ記号で PPM のモデルをコーパスから数え、曲の各行の情報量と、コーパス自身の曲を交差検証した値に対する z 値を出す。RWC は申請しないことにしたので（7節）、自由に入手できるデータから2つを試した。

| コーパス | 曲数 | 音数 | 交差検証（ビット／音） | 試作14曲の z 値 |
|---|---|---|---|---|
| PJS 1.1（CC BY-SA 4.0） | 100 | 3,801 | 5.22 ± 0.73 | すべて正、最大 +3.6 |
| PDMX のポップスとロック、歌詞あり（CC0 とパブリックドメイン） | 620 | 189,217 | 5.57 ± 1.65 | -0.6〜+1.3 |

PJS は日本語の歌だが、音素の偏りをなくすために作った短い歌で、速いロックとは書き方が違う。試作曲がすべて PJS より高く出たのは、ありふれ方の差ではなく、ジャンルの差と考える。PDMX のポップスとロックと比べると、試作曲の旋律は、コーパスの曲とほぼ同じ程度にありふれていた。指示なしで長さと構成だけを頼んだ4曲の平均は -0.1、通常の条件の6曲の平均は +0.5 で、曲ごとの散らばりのほうが大きい。PDMX の旋律は、ドラム以外で最初に音のあるトラックの最高音を取っているので、歌のパートのない楽譜ではピアノの右手になる。どちらのモデルも手元にだけ置いた。

### 残っていた3つも入れた

8節で見送った項目は、これで全部入った。

- **fit の拡張**（4.4）：`analyze_lyrics` の fit が合わないとき、旋律の側の直し方を `melody_options` として返すようにした。モーラが多ければ、弱起の音を足すか長い音を割る数を、少なければ2音をまとめる数を示す。どれも、それだけで差がなくなる数である。
- **フィルの階層**（4.2）：`arrangement_shape` が、16小節以上のセクションの中で8小節ごとのフレーズの終わりを数え、そのうちセクションの基本パターンと違う小節を弾いている数と、その小節の音数を、サビに入る小節の音数と並べて出すようにした。どのフレーズの終わりにもフィルがないときだけ警告する。10曲では、6か7あるフレーズの終わりのうち3〜6にフィルがあり、警告は出なかった。サビに入る小節のほうが音数が多い曲が8曲だった。
- **時間をまたぐ運指**（4.6）：ギターのパートで、各発音の押さえ方を全部挙げ、手の移動が最も少ない道筋を動的計画法で選ぶ。そのうえで、80 ms 未満のあいだに9フレット以上の移動が残れば、lint の規則 `guitar_position_jump` で報告する。11曲では該当がなかった。

セクション末の終止の報告を10曲で見ると、指示なしで長さと構成を頼んだ曲には、すべてのセクションが同じ終わり方の曲があった（1曲はすべて open、1曲はすべて半終止）。通常の条件の曲は、半終止と VII→i を使い分けていた。報告だけで、警告にはしていない。

### 最終的な指示で作った4曲

ここまでの変更をすべて入れた指示（af0f9241）で、ほかの条件と同じ依頼から4曲を作った。1曲に15〜18分かかり、どの曲も差し戻しは1回だった。3曲は `melody_develops`（行の入りが一か所にそろう、音の間隔が一様）、1曲は lint の `no_breath` で差し戻された。仕上がった4曲に lint の警告はなく、残ったのは情報の `avoid_note` だけだった。

学習済みの評価器の点は、これまでの条件と変わらない。

| 条件 | 曲数 | SAE Overall | SAE Melody | SAE Arrange | SAE AudioQ | Audiobox PQ | Audiobox CE |
|---|---|---|---|---|---|---|---|
| 通常（指示の変更前） | 2 | 70.3 | 78.7 | 81.0 | 74.7 | 7.18 | 6.67 |
| 行の入りと音の間隔を差し戻す | 2 | 71.2 | 77.7 | 81.2 | 74.7 | 7.48 | 6.60 |
| 2番の写しも差し戻す | 2 | 71.0 | 78.5 | 81.0 | 75.1 | 7.35 | 6.77 |
| 最終 | 4 | 70.8 | 78.6 | 79.5 | 74.2 | 6.90 | 6.65 |

最終の PQ が低いのは、final-2 と final-4 の2曲（6.71、6.61）が下げているためだ。4曲とも、比べる前に -14 LUFS にそろえてある。SAE は、ほかの条件との差が1.5点以内だった。曲数が少ないので、この差から指示の良し悪しは言えない。

楽譜側の指標では、指示で直そうとしたところが直っていた。

- **行の入り**：いちばん多い入りの位置に行が集まる割合は、指示の変更前の2曲が100%、最終の4曲が45〜75%だった。最終の曲では、1拍目、1拍目の裏、2拍目、16分ずれた位置と、入りの位置が1曲に3〜5種類あった。
- **2番**：4曲とも、Aメロの2番は1番と別の旋律か、同じリズムで音の高さを変えた旋律だった。1番をそのまま写した曲はなかった。
- **コーパスと比べたありふれ方**：PDMX のポップスとロックに対して z 値が 0.03〜1.0 で、これまでの14曲と同じ範囲に収まった。

弱いままのところも3つある。

- **アクセント**：旋律の動きが話すときの高低と逆になる割合は48〜60%で、これまでの曲（36〜59%）と変わらない。アクセントは情報として返すだけで、差し戻しには使っていない。
- **ドラムの強さ**：2曲（final-2、final-4）が、全セクションを同じ強さ（平均ベロシティ 0.54〜0.55）で叩いていた。いまの判定で前の条件の6曲を測り直すと、3曲が同じ状態だった。ドラムの強さは指示の文に書いただけで、差し戻しの判定には入っていない。
- **Bメロ**：2曲で、Bメロが順次進行だけで動いていた（いちばん広い音程が3〜4半音）。

セクション末の終止は、4曲とも open（主和音に戻らない）と VII→i がほとんどだった。フィルは、6〜8あるフレーズの終わりのうち3〜6にあった。

### ドラムの強さを差し戻しの判定に入れた

アレンジのフェーズの完成条件に `drums_follow_sections` を足した（57aa09a8）。`arrangement_shape` の「ドラムが全セクションを同じ強さで叩いている」という警告が残っていると、未達になる。同じ強さとは、セクションごとの平均ベロシティの、最大と最小の差が0.04未満のことである。この版で同じ依頼から4曲を作った。

4曲とも、この判定で差し戻されることはなく、仕上がりにも警告は残らなかった。差し戻しは1曲に1〜2回あったが、理由は `melody_develops`、lint、ミックスまで進んでいないことのどれかだった。作曲エージェントは、指示の文で判定のことを読んで、最初からベロシティを変えていた。

ただし、ベロシティの変え方は2通りに分かれた。

| 曲 | Aメロ | サビ | 最後のサビ | 差がいちばん大きいセクション |
|---|---|---|---|---|
| drums-1 | 0.55 | 0.54 | 0.54 | イントロ 0.65、ブリッジ 0.50 |
| drums-2 | 0.56 | 0.82 | 0.86 | — |
| drums-3 | 0.52 | 0.84 | 0.84 | — |
| drums-4 | 0.56 | 0.57 | 0.57 | ブリッジ 0.61 |

drums-2 と drums-3 は、指示のとおり Aメロを弱く、サビを強く叩いている。drums-1 と drums-4 は、Aメロとサビが同じ強さのままで、イントロかブリッジの1セクションだけが違うために、差が0.04を超えて判定を通っている。最大と最小の差だけを見る判定は、この書き方を見分けられない。そこで判定を直し、Aメロとサビのある曲では、サビの平均ベロシティが Aメロより0.04以上高いことを求めるようにした。どちらかがない曲は、これまでどおりセクションどうしの差で見る。直した判定で8曲を測り直すと、drums-1 と drums-4 に加えて、final-1、final-2、final-4 が未達になり、通ったのは drums-2、drums-3、final-3 の3曲だった。

学習済みの評価器の点は、前の4曲と同じ範囲だった。

| 条件 | 曲数 | SAE Overall | SAE Melody | SAE Arrange | SAE AudioQ | Audiobox PQ | Audiobox CE |
|---|---|---|---|---|---|---|---|
| 最終 | 4 | 70.8 | 78.6 | 79.5 | 74.2 | 6.90 | 6.65 |
| ドラムの強さも差し戻す | 4 | 69.9 | 78.1 | 80.3 | 73.9 | 7.28 | 6.90 |

ドラムの強さがはっきり変わった drums-2 と drums-3 も、SAE の Arrange は 79.0 と 80.7 で、変わらなかった drums-1 と drums-4（80.9、80.7）と差がない。評価器は、この差を聞き分けていない。

楽譜側のほかの指標は、前の4曲とほぼ同じだった。lint の警告はなく、コーパスに対する z 値は 0.27〜0.76、アクセントの逆向きは52〜57%だった。行の入りは、drums-1（98%）と drums-3（88%）で一か所に集まっていた。`melody_develops` は、すべての行が同じ位置から入るときにしか警告を出さないので、この2曲は判定を通っている。

### 次にできること

自動評価で作曲を調整し続けるには、曲どうしの違いを見分けられるだけの曲数が要る。SAE は同じ曲ならほとんど動かないので、条件ごとに4曲程度を作り、平均を比べる必要がある。1曲の作曲には15〜20分ほどかかり、作曲エージェントの利用量も増える。どの変更を比べるかを決めてから進める。楽譜側の指標は1曲ずつでも差が読めるので、指示の変更はまず楽譜側の指標で確かめる。
