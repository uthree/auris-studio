# エージェントオーディオ配信

[English](agent-audio-delivery.md)

保存されたプロジェクトのMCPツールとライブリグエージェントは、全体ミックスの正規化に同じセッションコマンドを使用します。サウンド検索結果はサウンドを特定しますが、そのフェーダー値はサウンドの出力レベルを予測しません。`set_instrument`または`setup_tracks`を実行した後、調整またはエクスポートする前にミックスを再度測定してください。`setup_tracks`はリクエストされたサウンドIDを繰り返すため、エージェントが選択を確認できます。

<a id="set-a-measurable-goal"></a>
## 測定可能な目標を設定する

各デリバリーに対して、統合された音量ターゲットと真ピーク天井を選択してください。たとえば、使用されたエージェント比較実験では -23 LUFS と -1 dBTP が使用されました。これらは実験設定であり、すべての曲のデフォルトではありません。`analyze` を使用して現在の保存済みプロジェクトを測定してください。ライブリグパスでは、`inspect_audio` は短い抜粋を測定し、`normalize_mix` は全体のアレンジメントを測定します。すべてのライブバックエンドは、その保存されていないスナップショットをエクスポートできます。

`normalize_mix`はソースフェーダーに共通のオフセットを適用し、それらの差を保持したまま、フルミックスを再度レンダリングします。マスターフェーダーや作成されたノートは変更されません。使用する前にソースゲインオートメーションレーンをクリアする必要があります。True-peakやフェーダーリミットにより、リクエストされたLUFSが達成されない場合があります。ツールは目標が達成されたと主張するのではなく、測定結果を報告します。

<a id="check-the-encoded-file"></a>
## エンコードされたファイルを確認してください

`render`は書き込んだ各WAVをデコードし、測定された音量、サンプルピーク、推定真ピーク、フルスケールサンプル数、最終的なハーフ秒RMS、およびSHA-256を報告します。以前のレンダリングピークはエンコーディング前に測定されます。エンコード後の検査結果が配信に使用される結果となります。絶対出力パスと選択したターゲットを指定して`verify_render`を実行すると、配信はPASSまたはFAILとなります。フェードアウトの場合は、-60 dBFSなどの`ending_rms_max_db`を指定してください。意図的なループまたはハードカットの場合は、この制限は省略してください。ゼロを超えるフルスケールサンプル数は、整数飽和の可能性を示します。ファイルを配信する前に検査し、調整してください。`verify_render`はWAVを一切変更しません。

<a id="export-the-unsaved-document"></a>
## 保存されていないドキュメントをエクスポートする

組み込みのClaude、Codex、ネイティブAPIエージェントは、保存されたプロジェクトMCPと`render`、`preview`、`export_midi`、`verify_render`を共有します。保存された呼び出しは`project`のみを追加し、ライブ呼び出しは保存やプロジェクトパスは必要ありません。WAVミックスの場合：

```json
{"destination":{"kind":"mix","path":"/absolute/new-mix.wav"},"bit_depth":24}
```

ステムには出力先 `{"kind":"stems","folder":"/absolute/new-stems"}` を使用してください。オプションの `range` は `{"start_bar":1,"bars":4}` です。全体の構成では省略してください。`include_tail` はデフォルトで false です。`preview` は最大 120 秒の範囲が必要です。これにより、ドキュメントのプレビューフォルダに保護された 24 kHz の WAV ファイルが作成されます。`export_midi` は現在の楽器譜の絶対的な `output` パスを受け取ります。

エンコーディング、レンダリング、エンコード済みファイルの測定はUIスレッド上で実行されます。プライベートステージは、ドキュメントの所有権、バージョン変更、キャンセル、アセットガードが確認された後にのみ公開されます。既存の出力ファイルは拒否されます。古いまたは停止した操作はステージを削除し、既存のファイルは変更しません。エクスポートはスコアを保存または変更しません。結果は公開されたファイルと正確なバイトハッシュを識別し、マルチステム公開の失敗はすでに公開されたファイルを報告します。

`verify_render` は `path`、オプションの `target_lufs`、`ceiling_db`（デフォルト -1）、`tolerance_lu`（デフォルト 1）、および `ending_rms_max_db` を受け取ります。プロジェクトを再度レンダリングすることなく、エンコードされた WAV を測定します。PASS/FAIL の判定は再生とは別です。

<a id="inspection-and-audition"></a>
## 検査とオーディション

`inspect_audio`は、保存されたMCPとライブホストを通じて、同じ測定値とPNGを返します。`preview`は24 kHz保護PCM16 WAVを使用し、報告される減衰はオーディションのみ適用されます。ミックスおよびエクスポート時の配信設定は変更されません。`listen`は、レンダリングした小節を音声入力として、音声を受け付けるモデルに届けます。返された`audition_id`を`compare_to`に渡すと、編集前と編集後を共通の保護ゲインで届けます。[エージェントに曲を聴かせる](agent-listening.md)を参照してください。
